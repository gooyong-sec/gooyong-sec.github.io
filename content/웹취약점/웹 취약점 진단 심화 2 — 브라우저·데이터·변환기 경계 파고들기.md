## 공통 localhost Docker 실습 앱

아래 앱은 1·4·5·6절에서 사용합니다. 포트 공개 범위를 `127.0.0.1`로 고정했고 ReDoS 입력은 26자로 제한했습니다. 빈 폴더에 두 파일을 그대로 저장합니다.

`Dockerfile`:

```dockerfile
FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim
WORKDIR /app
RUN apt-get update \
    && apt-get install -y --no-install-recommends libpango-1.0-0 libpangoft2-1.0-0 \
       libharfbuzz-subset0 libjpeg62-turbo libopenjp2-7 \
    && rm -rf /var/lib/apt/lists/*
RUN uv pip install --system "flask==3.1.2" "weasyprint==70.0"
COPY app.py .
CMD ["python", "app.py"]
```

`app.py`:

```python
import re
import time
import unicodedata

from flask import Flask, Response, jsonify, request
from weasyprint import HTML

app = Flask(__name__)
state = {"admin_actions": 0, "internal_fetches": 0}
dangerous_pattern = re.compile(r"^(a+)+$")


@app.get("/")
def index():
    return """<!doctype html><meta charset=utf-8><title>CSPT lab</title>
<p id=result>waiting</p><script>
const id = new URLSearchParams(location.search).get('id') || 'alice';
const target = new URL('/api/users/' + id, location.origin);
document.querySelector('#result').textContent = target.pathname;
fetch(target, {method: 'POST', credentials: 'same-origin'});
</script>"""


@app.post("/api/users/<user_id>")
def user_update(user_id: str):
    return jsonify(updated=user_id)


@app.post("/api/admin/toggle")
def admin_toggle():
    state["admin_actions"] += 1
    return jsonify(admin_actions=state["admin_actions"])


@app.get("/state")
def show_state():
    return jsonify(state)


@app.get("/unicode")
def unicode_check():
    raw = request.args.get("name", "")
    if raw == "admin":
        return jsonify(raw=raw, result="blocked"), 403
    normalized = unicodedata.normalize("NFKC", raw)
    return jsonify(raw=raw, normalized=normalized, is_admin=normalized == "admin")


@app.get("/redos")
def redos():
    value = request.args.get("value", "")
    if len(value) > 26:
        return jsonify(error="lab input capped at 26 characters"), 400
    started = time.perf_counter()
    matched = dangerous_pattern.fullmatch(value) is not None
    elapsed = time.perf_counter() - started
    return jsonify(matched=matched, elapsed_seconds=round(elapsed, 4), length=len(value))


@app.post("/pdf")
def pdf():
    html = request.form["html"]
    output = HTML(string=html, base_url="http://127.0.0.1:5000/").write_pdf()
    return Response(output, mimetype="application/pdf")


@app.get("/internal.svg")
def internal_svg():
    state["internal_fetches"] += 1
    svg = """<svg xmlns="http://www.w3.org/2000/svg" width="240" height="40">
    <text x="5" y="25">LOCAL INTERNAL ONLY</text></svg>"""
    return Response(svg, mimetype="image/svg+xml")


if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000, threaded=True)
```

```bash
docker build -t web-deep2-lab .
docker run --rm --name web-deep2-lab -p 127.0.0.1:5000:5000 web-deep2-lab
```

## 1. CSPT(Client-Side Path Traversal) — 브라우저가 API 경로를 바꿀 때

### 단서 기능·성립 조건·원리

- **단서 기능**: SPA가 `location.search`, URL 해시, DOM 속성, `postMessage`의 값을 `fetch('/api/users/' + id)`처럼 경로에 붙이는 코드입니다.
- **성립 조건**: 비신뢰 값에 `/`·`.` 세그먼트를 허용하고, 브라우저가 URL을 정규화한 뒤 요청하며, 바뀐 목적지에 상태 변경 API가 있고 쿠키·인증 헤더가 자동으로 따라갈 때입니다.
- **원리**: 서버 파일을 읽는 전통적 Path Traversal과 달리, **피해자의 브라우저가 의도하지 않은 same-origin API로 인증된 요청을 보내게** 합니다. HTTP 메서드·본문·헤더가 목표 API와 맞아야 실제 CSRF 영향으로 이어집니다.

### 따라하기

1. 공통 앱 실행 후 기준 상태를 확인합니다.

```bash
curl -s http://127.0.0.1:5000/state
# 기대: {"admin_actions":0,"internal_fetches":0}
```

2. 브라우저에서 다음 URL을 엽니다. `curl`은 JavaScript를 실행하지 않으므로 반드시 브라우저를 씁니다.

```text
http://127.0.0.1:5000/?id=../admin/toggle
```

3. 화면에 정규화된 `/api/admin/toggle`이 표시됩니다. 다시 상태를 조회합니다.

```bash
curl -s http://127.0.0.1:5000/state
# 기대: admin_actions가 1 증가
```

**성공 판별 기준**은 개발자가 의도한 `/api/users/{id}`가 아니라 `/api/admin/toggle`로 POST가 전송되고 카운터가 증가하는 것입니다.

### 진단 체크리스트·오탐 구분·조치

- [ ] Source(URL·hash·DOM·message)에서 sink(`fetch`, Axios, XHR, 동적 `src`/`href`)까지 데이터 흐름을 추적했다.
- [ ] DevTools Network에서 **최종 요청 URL, 메서드, 본문, 인증정보**를 기록했다.
- [ ] 단순 404 경로 변경이 아니라 상태 변화 또는 권한 있는 응답을 확인했다.
- [ ] 서버 API의 CSRF 토큰·Origin 검증·재인증이 실제로 막는지도 확인했다.

```javascript
const id = new URLSearchParams(location.search).get("id") ?? "";
if (!/^[A-Za-z0-9_-]{1,64}$/.test(id)) throw new Error("invalid id");
const target = new URL(`/api/users/${encodeURIComponent(id)}`, location.origin);
```

경로 세그먼트는 허용 목록으로 검증하고 상태 변경 API에도 CSRF 방어와 서버 측 인가를 둡니다. 탐지는 프런트 소스맵에서 동적 경로 조립을 찾고, 서버에서는 정상 UI 흐름과 맞지 않는 Referer/경로 조합 및 `..` 정규화 전후를 기록합니다.

- 참고: [Doyensec — CSPT2CSRF 연구](https://blog.doyensec.com/2024/07/02/cspt2csrf.html), [Doyensec CSPT2CSRF Whitepaper](https://www.doyensec.com/resources/Doyensec_CSPT2CSRF_Whitepaper.pdf), [OWASP CSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)

## 2. DOM Clobbering — HTML 이름이 JavaScript 객체를 덮을 때

### 단서 기능·성립 조건·원리

- **단서 기능**: 댓글·프로필·CMS에서 일부 HTML을 허용하고, 코드에 `window.config || {...}`, `document.x`, 전역 이름을 통한 설정 조회가 있습니다.
- **성립 조건**: 공격자가 `id`/`name`을 가진 요소를 삽입할 수 있고, 브라우저의 named property access가 같은 이름의 전역 값이나 속성을 가리키며, 그 값이 URL·스크립트·HTML sink로 전달됩니다.
- **원리**: 브라우저는 일부 이름 있는 요소를 `window`/`document` 속성처럼 노출합니다. 스크립트를 직접 넣지 못해도 애플리케이션이 이미 가진 코드 조각(gadget)의 입력을 HTML만으로 바꿀 수 있습니다.

### 따라하기 — PortSwigger 랩

실습: [Lab: Exploiting DOM clobbering to enable XSS](https://portswigger.net/web-security/dom-based/dom-clobbering/lab-dom-xss-exploiting-dom-clobbering). 공식 안내대로 Chrome을 사용합니다.

1. 블로그 글의 댓글에 다음 HTML을 등록합니다.

```html
<a id=defaultAvatar><a id=defaultAvatar name=avatar href="cid:&quot;onerror=alert(1)//">
```

2. 같은 글에 임의의 두 번째 댓글을 등록해 페이지를 다시 렌더링시킵니다.
3. `alert(1)`이 실행되는지 확인합니다. 두 개의 같은 `id`가 컬렉션을 만들고 두 번째 요소의 `name=avatar`가 `defaultAvatar.avatar`를 덮습니다.

**성공 판별 기준**은 HTML 삽입만으로 기존 JavaScript gadget의 값이 바뀌어 alert가 실행되는 것입니다. HTML이 저장되었다는 사실만으로는 DOM Clobbering이 아닙니다.

### 진단 체크리스트·오탐 구분·조치

- [ ] HTML 삽입 가능 여부와 허용되는 `id`/`name`/`href`를 확인했다.
- [ ] 충돌 대상 전역 이름과 최종 sink를 코드로 연결했다.
- [ ] 브라우저별 named property 차이를 확인했다.
- [ ] 단순 DOM 요소 생성과 보안 영향(XSS·리다이렉트·데이터 유출)을 분리했다.

전역 객체를 설정 저장소로 쓰지 말고 모듈 로컬의 명시적 객체를 사용해 `Object.freeze()`합니다. DOMPurify를 쓴다면 사용자 정의 이름까지 격리하도록 `SANITIZE_NAMED_PROPS: true`를 검토하고 CSP를 방어 계층으로 둡니다. 탐지는 사용자 HTML의 기존 전역 변수와 충돌하는 `id`/`name`, 두 개 이상의 같은 ID, `cid:` 등 비정상 URL 스킴을 봅니다.

- 참고: [OWASP DOM Clobbering Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/DOM_Clobbering_Prevention_Cheat_Sheet.html), [OWASP WSTG DOM Clobbering](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/11-Client-side/16-DOM_Clobbering/), [PortSwigger — DOM clobbering](https://portswigger.net/web-security/dom-based/dom-clobbering)

## 3. NoSQL 인젝션 — MongoDB 연산자 주입

### 단서 기능·성립 조건·원리

- **단서 기능**: JSON 본문의 로그인·검색·비밀번호 재설정, MongoDB `ObjectId` 오류, `$regex`·`$where` 관련 에러, Node/Mongoose 계열 응답입니다.
- **성립 조건**: 서버가 `username`을 문자열로 강제하지 않고 객체도 받아 `findOne({username: req.body.username, ...})`에 그대로 전달할 때입니다.
- **원리**: `"admin"`이라는 데이터 대신 `{"$ne":""}`라는 **쿼리 연산자 객체**가 들어가면 일치 조건 자체가 바뀝니다. 문자열 기반 SQLi와 달리 JSON의 타입 혼동이 핵심인 경우가 많습니다.

### 따라하기 — PortSwigger 랩

실습: [Lab: Exploiting NoSQL operator injection to bypass authentication](https://portswigger.net/web-security/nosql-injection/lab-nosql-injection-bypass-authentication).

1. `wiener:peter`로 로그인한 `POST /login`을 Repeater로 보냅니다.
2. JSON 본문으로 바꾸거나 원래 JSON 요청에서 다음처럼 정상 계정에 연산자를 넣어 반응을 비교합니다.

```http
POST /login HTTP/1.1
Host: YOUR-LAB-ID.web-security-academy.net
Content-Type: application/json

{"username":{"$regex":"admin.*"},"password":{"$ne":""}}
```

3. 응답에서 관리자 세션이 발급되고 My account의 사용자가 `administrator`인지 확인합니다.

**성공 판별 기준**은 `$regex`와 `$ne` 객체가 쿼리 연산자로 해석되어 비밀번호를 모르는 관리자 계정으로 인증되는 것입니다. 단순 500 오류는 타입 검증 부재의 단서일 뿐 인증 우회 증거는 아닙니다.

### 진단 체크리스트·오탐 구분·조치

- [ ] 문자열 필드에 객체·배열·null을 각각 보냈을 때 스키마 검증 여부를 확인했다.
- [ ] `$ne`, `$regex`가 데이터 문자열인지 연산자인지 응답 차이로 확인했다.
- [ ] 인증 우회, 데이터 추출, DoS 영향을 별도 증거로 구분했다.
- [ ] ODM의 `sanitizeFilter` 같은 옵션이 켜져도 애플리케이션 스키마 검증이 있는지 확인했다.

```javascript
const schema = z.object({
  username: z.string().min(1).max(64),
  password: z.string().min(1).max(128),
}).strict();
const { username, password } = schema.parse(req.body);
const user = await users.findOne({ username });
```

입력 타입과 길이를 엄격히 검증하고 예상하지 않은 `$` 키·점 표기·추가 필드를 거부합니다. 비밀번호는 DB 쿼리 조건에 사용자 입력 그대로 넣지 말고, 사용자 한 명을 조회한 뒤 안전한 해시 비교를 합니다. 탐지 시 JSON 객체가 들어온 문자열 필드, `$`로 시작하는 키, 과도한 정규식과 인증 실패/성공 전환을 연결합니다.

- 참고: [PortSwigger NoSQL injection](https://portswigger.net/web-security/nosql-injection), [MongoDB Query Selectors](https://www.mongodb.com/docs/manual/reference/mql/query-predicates/), [MongoDB `$where` 보안 참고](https://www.mongodb.com/docs/manual/reference/operator/query/where/)

## 4. 유니코드 정규화 우회 — 같은 글자처럼 보이는 다른 코드 포인트

### 단서 기능·성립 조건·원리

- **단서 기능**: 사용자명·테넌트명·파일명·경로, 차단 단어, 대소문자 무시 검색, IDN 도메인, 서로 다른 언어/DB가 문자열을 처리하는 흐름입니다.
- **성립 조건**: 앞 단계는 원문을 검사하지만 뒤 단계가 NFC/NFKC·case folding을 적용하거나, 반대로 저장과 비교가 다른 정규형을 사용할 때입니다.
- **원리**: 전각 `ａｄｍｉｎ`은 원문 비교에서 `admin`과 다르지만 NFKC 후 `admin`이 됩니다. 검증 후 정규화하면 차단한 값이 검증을 통과한 뒤 다시 만들어집니다.

### 따라하기

```bash
# 기준: ASCII admin은 앞 필터에서 차단
curl -i -G 'http://127.0.0.1:5000/unicode' --data-urlencode 'name=admin'
# 기대: HTTP 403

# 우회: 전각 문자는 원문 검사를 통과한 뒤 NFKC에서 admin이 됨
curl -s -G 'http://127.0.0.1:5000/unicode' --data-urlencode 'name=ａｄｍｉｎ'
# 기대: normalized="admin", is_admin=true
```

**성공 판별 기준**은 첫 요청은 차단되지만 두 번째 요청은 `normalized=admin`과 `is_admin=true`를 동시에 반환하는 것입니다.

### 진단 체크리스트·오탐 구분·조치

- [ ] 각 계층의 문자 인코딩, 정규형, locale, case folding 순서를 기록했다.
- [ ] 원문과 정규화 결과를 코드 포인트 단위로 비교했다.
- [ ] 시각적 유사성만이 아니라 실제 권한·고유성·차단 결정이 바뀌는지 확인했다.
- [ ] 등록·로그인·비밀번호 재설정이 같은 canonicalization 함수를 쓰는지 확인했다.

```python
canonical = unicodedata.normalize("NFKC", raw_name).casefold()
if canonical == "admin":
    reject()
# canonical 값을 고유 키로 저장하고 이후 비교에도 같은 함수를 사용한다.
```

정규화는 **검증 전에 한 번**, 등록·조회·인가 전체에서 동일한 정책으로 수행합니다. 원문도 감사용으로 보관하되 권한 결정은 canonical 값으로만 합니다. 탐지는 원문과 canonical 값이 크게 다른 계정 생성, 기존 보호 이름과 정규화 충돌, mixed-script 식별자를 기록합니다.

- 참고: [Unicode UTR #36 Security Considerations](https://www.unicode.org/reports/tr36/), [Unicode UAX #15 Normalization Forms](https://unicode.org/reports/tr15/), [Python `unicodedata.normalize`](https://docs.python.org/3/library/unicodedata.html#unicodedata.normalize)

## 5. ReDoS — 정규식의 재앙적 백트래킹

### 단서 기능·성립 조건·원리

- **단서 기능**: 이메일·URL·사용자명 검증, 로그 마스킹, WAF 룰처럼 사용자가 긴 문자열을 정규식에 넣을 수 있는 기능입니다.
- **성립 조건**: `^(a+)+$`처럼 중첩 수량자 또는 겹치는 대안이 있고, 거의 일치하지만 끝에서 실패하는 입력을 백트래킹 엔진이 처리하며 길이·시간 제한이 없을 때입니다.
- **원리**: 엔진은 앞의 `a`들을 안쪽/바깥쪽 그룹에 나누는 조합을 되짚습니다. 마지막 `!`에서 실패하면 가능한 분할을 폭발적으로 탐색해 CPU를 점유합니다.

### 따라하기

```bash
curl -sG 'http://127.0.0.1:5000/redos' --data-urlencode 'value=aaaa!'
curl -sG 'http://127.0.0.1:5000/redos' --data-urlencode 'value=aaaaaaaaaaaaaaaaaaaa!'
curl -sG 'http://127.0.0.1:5000/redos' --data-urlencode 'value=aaaaaaaaaaaaaaaaaaaaaaaaa!'
```

응답의 `elapsed_seconds`를 비교합니다. PC마다 절대 시간은 다르지만 입력이 조금 늘 때 실패 시간이 급격히 증가합니다. 앱은 26자 초과를 400으로 거부합니다.

**성공 판별 기준**은 동일 엔드포인트에서 길이에 비해 비선형적으로 시간이 증가하는 재현 가능한 추세입니다. 네트워크 지연 한 번만으로 ReDoS라 단정하지 말고 각 길이를 여러 번 반복해 중앙값을 비교합니다.

### 진단 체크리스트·오탐 구분·조치

- [ ] 정규식과 공격자 제어 입력 길이 상한을 확인했다.
- [ ] 일치 입력과 끝에서 실패하는 입력의 시간을 분리 측정했다.
- [ ] 애플리케이션 CPU/이벤트 루프 지연과 응답 시간을 함께 관찰했다.
- [ ] 동시 요청 없이도 단일 입력의 계산 복잡도가 증가하는지 확인했다.

이 예제는 `^a+$`로 단순화할 수 있습니다. 일반적으로 중첩 수량자·겹치는 대안을 제거하고 입력 길이 제한, 실행 타임아웃, RE2 계열의 선형 시간 엔진을 검토합니다. 탐지는 특정 필드의 길이·문자 패턴과 정규식 실행 시간, CPU 스파이크, 이벤트 루프 지연을 묶습니다.

- 참고: [OWASP ReDoS](https://owasp.org/www-community/attacks/Regular_expression_Denial_of_Service_-_ReDoS), [CWE-1333 — Inefficient Regular Expression Complexity](https://cwe.mitre.org/data/definitions/1333.html), [Python `re` 문서](https://docs.python.org/3/library/re.html)

## 6. HTML→PDF 변환기 SSRF — 렌더러가 서버 안에서 URL을 가져올 때

### 단서 기능·성립 조건·원리

- **단서 기능**: 영수증·보고서·이력서·웹페이지를 PDF로 변환하거나 HTML/CSS를 입력받아 미리보기를 만드는 기능입니다.
- **성립 조건**: 비신뢰 HTML/CSS에서 `<img src>`, `@import`, `url()`, 폰트·첨부 URL을 허용하고 렌더러가 서버 네트워크 권한으로 원격·로컬 리소스를 가져올 때입니다.
- **원리**: 브라우저가 아니라 서버의 headless browser/wkhtmltopdf/WeasyPrint가 URL을 요청하므로, 외부에서 접근할 수 없는 localhost·내부 API·클라우드 메타데이터까지 닿을 수 있습니다. 렌더링 시간 기반 Blind SSRF도 가능합니다.

### 따라하기

1. 변환 전 카운터를 기록합니다.

```bash
curl -s http://127.0.0.1:5000/state
```

2. 로컬 내부 SVG를 포함한 HTML을 PDF 변환기에 전달합니다.

```bash
curl -s -X POST 'http://127.0.0.1:5000/pdf' \
  --data-urlencode 'html=<h1>PDF</h1><img src="http://127.0.0.1:5000/internal.svg">' \
  -o out.pdf
```

3. PDF가 생성됐는지와 내부 요청 카운터를 확인합니다.

```bash
ls -l out.pdf
curl -s http://127.0.0.1:5000/state
# 기대: internal_fetches가 1 증가
```

**성공 판별 기준**은 사용자 브라우저가 아니라 PDF 변환 요청 과정에서 `/internal.svg` 카운터가 증가하고 유효한 PDF가 생성되는 것입니다.

### 진단 체크리스트·오탐 구분·조치

- [ ] HTML, CSS `@import`/`url()`, SVG, 폰트, 첨부 등 모든 fetch 위치를 확인했다.
- [ ] HTTP(S)뿐 아니라 `file:`, `data:`, 리다이렉트 후 주소 처리도 확인했다.
- [ ] 요청 주체가 클라이언트가 아니라 변환기 프로세스임을 서버 로그로 입증했다.
- [ ] DNS 확인 시점과 연결 시점의 IP가 바뀌는 rebinding, IPv6·정수 IP 표기도 고려했다.

```python
from urllib.parse import urlsplit
from weasyprint import default_url_fetcher

def safe_url_fetcher(url: str):
    parsed = urlsplit(url)
    if parsed.scheme != "https" or parsed.hostname not in {"static.example.com"}:
        raise ValueError("external resource blocked")
    # 실제 구현은 DNS 결과와 모든 redirect hop도 다시 검증한다.
    return default_url_fetcher(url)
```

가능하면 사용자 HTML에서 외부 리소스를 제거하고, 필요한 자산은 서버가 고정 허용 목록에서 미리 가져와 로컬 데이터로 전달합니다. URL fetcher의 스킴·호스트·해석 IP와 모든 리다이렉트 홉을 검증하고, 컨테이너의 파일·네트워크 권한과 아웃바운드 egress를 제한합니다. 탐지는 변환 작업 ID와 렌더러의 DNS/HTTP/file 접근 로그를 연결하고 localhost·사설·link-local 목적지를 차단합니다.

- 참고: [WeasyPrint Security — untrusted HTML and local/remote resources](https://doc.courtbouillon.org/weasyprint/stable/first_steps.html#security), [OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html), [CVE-2025-68616 — WeasyPrint redirect SSRF protection bypass](https://nvd.nist.gov/vuln/detail/CVE-2025-68616)
