# 2023년 4분기 (2023-10 ~ 2023-12) 주요 사건

> 작성 형식: 개요 → 왜 일어났나(직접·구조적 원인) → 침투 경로 → 어떻게 조치하나(즉시·단기·장기·탐지) → 교훈.
> 근거 표기: **확인**(벤더·정부·연구기관 직접 확인) / **보도**(2차 보도 다수) / **추정**(공개 자료에 없어 본 보고서가 추정). **조치는 본 보고서의 권고**이며 벤더 공식 지침이 아니다. ATT&CK 매핑은 `../ATTACK/매핑.psv`에 있다(v19.2 기준). '구조적 원인'은 본 보고서의 분석이며 확인된 사실이 아니다. 모든 '즉시' 조치는 증거(로그·메모리·디스크·클라우드 감사 기록)를 보존한 뒤 수행하고, 침해된 장비·계정에서 새 비밀을 발급하지 않는다.

### [INC-2023-10-okta] Okta 고객지원 시스템 침해
> 날짜: 2023-10-20 · 유형: 서드파티·신원(IdP) · 행위자: 미귀속 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 로그인 서비스 회사(Okta)의 고객지원 창구에 올라온 '문제 해결용 파일' 안에 로그인 상태 정보가 들어 있었고, 공격자가 이를 훔쳐 다른 회사 시스템에 몰래 들어갔습니다. 비밀번호가 아니라 '이미 로그인했다는 표시'를 훔친 사건입니다.

**먼저 할 일(초보용)**: 지원팀의 공식 민감정보 제거 절차를 따라 파일에서 로그인 정보(쿠키·토큰)를 지우고, 남지 않았는지 확인한 뒤 보내세요. 유출이 의심되면 로그인 세션을 모두 끊습니다.

**개요**: 2023-09-28 ~ 10-17 사이 공격자가 Okta 고객지원 시스템에서 고객 134곳 관련 지원 파일에 접근했다(세션 하이재킹이 확인된 고객은 5곳, Okta 보고). 고객이 문제 해결 때 올린 HAR 파일에는 쿠키와 세션 토큰이 들어 있었고, 이 토큰으로 1Password, BeyondTrust, Cloudflare 같은 고객 환경에 접근이 시도되거나 성공했다.

**왜 일어났나**
- 직접 원인: 서비스 계정 자격 증명이 직원의 개인 Google 계정에 저장된 사실이 확인됐다(직원이 회사 노트북 Chrome에 개인 프로필로 로그인한 채 서비스 계정을 사용). 개인 계정·기기의 침해가 유력한 노출 경로로 제시됐으나 **최초 탈취 경로가 확정된 것은 아니다**(Okta 조사 결과, 2차 보도).
- 구조적 원인(분석): (1) 지원 시스템이 세션 토큰이 담길 수 있는 HAR를 원문 그대로 보관 (2) 서비스 계정 권한이 넓었을 가능성 (3) 관리 기기에서 개인 계정 동기화를 막지 않음 (4) HAR 업로드 때 민감값을 제거하지 않는 업계 관행

**침투 경로**: 개인 Google 계정·기기 → 서비스 계정 자격 증명 → 지원 케이스 시스템 로그인 → HAR 열람 → 세션 토큰 확보 → 고객 IdP·관리 콘솔 세션 하이재킹

**어떻게 조치하나**
- 즉시: HAR 등 지원 파일에 포함됐을 수 있는 세션 토큰 폐기, 관리자 세션 강제 종료, 최근 관리 콘솔 변경 이력 감사
- 단기: HAR·로그를 지원 채널에 올리기 전 쿠키·Authorization 헤더 마스킹, 지원 시스템에서 업로드 파일 자동 정제, 서비스 계정 권한 최소화, 관리 브라우저에서 개인 프로필 로그인·비밀번호 동기화 차단
- 장기: 관리자 세션 토큰을 기기·IP에 바인딩, 관리자 접근에 피싱 저항 MFA(FIDO2. 단, 이미 발급된 세션의 재사용은 막지 못하므로 세션 폐기·재인증·바인딩을 병행), 지원 데이터 보존기간 단축
- 탐지: 같은 세션 토큰이 다른 IP·ASN에서 재사용, 관리 콘솔의 신규 API 토큰·관리자 생성 이벤트

**교훈**: 신원 공급자(IdP)의 공급망 하나가 하위 고객 수백 곳의 관리 권한으로 이어진다. "로그 파일은 비밀이다."

### [INC-2023-10-citrixbleed] Citrix Bleed (CVE-2023-4966) 대량 악용
> 날짜: 2023-10-10 · 유형: 엣지 장비 취약점 · 행위자: LockBit 계열 제휴자 외 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 회사 원격 접속 장비(Citrix)의 결함 때문에 '이미 로그인한 사람의 증표'가 밖으로 새어 나왔고, 공격자는 그 증표로 비밀번호와 2단계 인증 없이 들어왔습니다.

**먼저 할 일(초보용)**: 장비를 업데이트한 뒤 접속 중인 세션을 모두 끊고 비밀번호도 바꾸세요. 업데이트만으로는 이미 훔친 증표가 남습니다.

**개요**: NetScaler ADC/Gateway의 정보 노출 취약점이 대량 악용됐다. CISA 등의 공동 권고는 LockBit 3.0 제휴자의 이 취약점 악용과 Boeing(부품·유통 사업, 약 40GB 유출) 침해를 확인했다. ICBC 미국 법인(미 국채 시장 거래에 지장), DP World 호주, Allen & Overy는 같은 취약점과의 관련성이 보도된 사례다.

**왜 일어났나**
- 직접 원인: 조작된 요청이 장비 메모리의 세션 토큰을 그대로 돌려주는 결함. 이미 인증을 마친 세션을 가로채므로 MFA를 거치지 않는다. 공개(10/10) 이전부터 악용됐다는 보고가 있다(연구기관 보고, 원문 미확인).
- 구조적 원인: (1) VPN·게이트웨이가 인터넷에 직접 노출 (2) **패치해도 이미 탈취된 세션이 계속 유효** (3) 장비 내부에는 EDR이 없어 침해를 알기 어려움 (4) 대형 조직도 패치 지연

**침투 경로**: 노출된 NetScaler → 메모리 누수 요청으로 세션 토큰 수집 → 인증된 사용자로 접속(MFA 우회) → 내부망 이동 → 데이터 탈취·랜섬웨어

**어떻게 조치하나**
- 즉시: 패치 적용 **후** 활성·지속 세션을 모두 강제 종료(패치만으로는 탈취된 세션이 남는다). 세션 토큰·장비에 저장된 자격 증명 교체
- 단기: 장비 로그로 비정상 세션 재사용(같은 세션이 다른 IP), 장비 내 웹셸·설정 변경·잔존 지속성과 내부 이동 조사. 침해 정황이 있으면 재구축. 자격 증명 교체는 세션 종료를 대신하지 못한다
- 장기: 원격 접속 게이트웨이 앞단 관리면 분리, ZTNA·세션 기기 바인딩 도입, 엣지 장비 패치 SLA(예: 악용 확인 후 72시간)를 정책화
- 탐지: 인증 이벤트 없이 생성된 세션, 로그인 이후 다른 IP·UA로 요청이 이어지는 패턴

**교훈**: 패치 = 끝이 아니다. 세션·자격 증명 회수까지 해야 한다. 같은 제품이 2026-09에도 제로데이로 다시 나왔다(오늘 보고서 참조).
