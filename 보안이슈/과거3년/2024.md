### [INC-2024-01-ivanti] Ivanti Connect Secure 제로데이 (CVE-2023-46805 + CVE-2024-21887)
> 날짜: 2024-01-10 · 유형: 엣지 장비 취약점 · 행위자: UNC5221(중국 연계 의심) · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 회사 VPN 장비(Ivanti)의 결함 두 개를 이어 붙이면 로그인 없이 장비를 조종할 수 있었고, 실제로 많은 장비가 공격당했습니다.

**먼저 할 일(초보용)**: 제조사의 임시 조치와 업데이트를 적용하고, 의심되면 장비를 초기화한 뒤 그 장비에 저장된 비밀번호를 모두 바꾸세요.

**개요**: SSL VPN 장비에서 인증 우회(CVE-2023-46805)와 명령 주입(CVE-2024-21887)을 연쇄해 인증 없이 원격 코드 실행이 가능했다. 약 1,700대 이상이 침해됐다는 2차 자료가 있다(집계 기관·기준 미확인). UNC5221은 초기 악용 일부의 귀속이며 이후의 대규모 악용 전체를 뜻하지 않는다.

**왜 일어났나**
- 직접 원인: 인증 우회로 관리 경로에 접근한 뒤 입력 검증이 부족한 기능에 명령을 주입.
- 구조적 원인: 인터넷 노출 VPN, 패치 전 완화책(XML)에 의존, 장비 무결성 점검 도구가 우회되는 사례. 침해된 VPN 장비가 로그인 자격 증명을 가로채는 용도로 쓰였다는 분석이 있다(Mandiant 보고, 원문 미확인).

**침투 경로**: 노출된 VPN 장비 → 두 취약점 연쇄로 RCE → 웹셸 → 로그인 페이지 변조로 자격 증명 수집 → 내부망 이동

**어떻게 조치하나**
- 즉시: 격리·증거 보존 후 벤더 완화책·패치 적용. 침해 의심 장비는 공식 절차에 따른 초기화·패치(CISA ED 24-01 추가 지침, 2024-01-31. 연방 민간기관 대상 의무이며 일반 조직은 참고. 원문 미확인)
- 단기: 장비에 저장된 자격 증명·인증서·키 전체 교체, 외부 무결성 검사 도구 실행(검사 결과가 '이상 없음'이어도 비침해로 단정하지 않는다), VPN 계정 비밀번호 초기화
- 장기: VPN 관리면 비노출, 엣지 장비 로그 외부 보존, 악용이 보고된 장비는 패치 대기 중에도 격리 가능한 구조
- 탐지: 로그인 페이지 파일·JS 변조, 장비에서 시작되는 비정상 아웃바운드

**교훈**: 침해된 VPN은 "자격 증명 수집기"가 된다. 패치 후에도 자격 증명을 교체해야 한다.

### [INC-2024-01-midnight] Microsoft 사내 메일 침해 (Midnight Blizzard)
> 날짜: 2024-01-19 · 유형: 신원·클라우드 · 행위자: Midnight Blizzard(러시아 국가 지원, Microsoft 귀속) · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 마이크로소프트가 잊고 있던 '테스트용 계정'에 2단계 인증이 꺼져 있었고, 공격자가 흔한 비밀번호를 여러 계정에 시도하는 방식(비밀번호 추측 공격)으로 들어온 뒤 거기서 핵심 계정으로 번져 임원 메일을 읽었습니다.

**먼저 할 일(초보용)**: 테스트·옛 계정에도 2단계 인증을 켜고, 쓰지 않는 앱과 계정을 정리하세요.

**개요**: 2023-11 말 시작해 2024-01-12 탐지. 공격자가 Microsoft 임원·보안·법무 직원의 메일을 읽었다.

**왜 일어났나**
- 직접 원인: MFA가 꺼진 **레거시 비운영 테스트 테넌트** 계정에 패스워드 스프레이 성공. 그 계정이 가진 테스트용 OAuth 앱이 운영 환경에 높은 권한을 갖고 있었다.
- 구조적 원인: (1) 방치된 테스트 테넌트·계정 (2) MFA 예외 (3) OAuth 앱 권한 과다와 소유자 점검 부재 (4) 앱 권한(Exchange `full_access_as_app`)을 스스로 부여할 수 있는 구조

**침투 경로**: 패스워드 스프레이(주거용 프록시 사용) → 테스트 테넌트 계정 → 레거시 OAuth 앱 → 악성 OAuth 앱 생성·권한 부여 → 임원 메일함 읽기

**어떻게 조치하나**
- 즉시: 의심 OAuth 앱·서비스 주체 폐기, 자격 증명 교체, 메일 접근 감사
- 단기: 모든 테넌트의 사용자 계정(테스트 포함)에 MFA 예외 0건, 서비스 주체·앱은 MFA 대신 권한 범위·인증서/비밀 수명·접근 조건으로 통제, OAuth 앱 권한 전수조사, 미사용 앱 삭제
- 장기: 앱 권한 부여를 승인 흐름에 연결, 테스트 환경을 운영과 권한 분리, 비인가 앱 동의 차단
- 탐지: 신규 OAuth 앱 생성·관리자 동의, `full_access_as_app` 부여, 단일 IP에서 다수 계정 로그인 실패 후 성공, 비대화형 로그인·EWS 호출 급증

**교훈**: 공격자는 가장 약한 테넌트에서 시작한다. 테스트 환경이 곧 운영 환경의 입구다.

### [INC-2024-02-changehc] Change Healthcare 랜섬웨어 (ALPHV/BlackCat)
> 날짜: 2024-02-21 · 유형: 신원·랜섬웨어 · 행위자: ALPHV/BlackCat · 지역: 미국 · 근거: 확인

**쉽게 말하면**: 미국 의료비 청구 회사의 원격 접속 화면에 2단계 인증이 없었습니다. 훔친 비밀번호 하나로 들어와 9일 뒤 랜섬웨어로 서비스를 멈췄고, 병원과 약국의 업무가 마비됐습니다.

**먼저 할 일(초보용)**: 회사 바깥에서 들어오는 모든 로그인에 2단계 인증을 켜세요.

**개요**: 미국 의료 청구·결제 처리가 장기간 마비됐다. 영향받은 개인은 최종 약 1억 9,270만 명(2025-07 보고), 모회사는 랜섬 2,200만 달러를 지급한 것으로 알려졌다.

**왜 일어났나**
- 직접 원인: **MFA가 없는 Citrix 원격 접속 포털**에 탈취된 직원 자격 증명으로 로그인(UnitedHealth CEO 의회 증언). 자격 증명을 최초에 어떻게 탈취했는지는 별도 확인이 필요하다.
- 구조적 원인: (1) 외부 포털에 MFA가 일관되게 적용되지 않음(인수·통합 과정의 문제인지는 근거 없음, 추정) (2) 단일 자격 증명으로 내부 이동이 가능한 구조 (3) 의료 청구 허브에 대한 집중도(단일 장애점) (4) 침입 9일 뒤에야 랜섬웨어 실행 — 그 사이를 못 잡음

**침투 경로**: 탈취된 자격 증명 → Citrix 포털(MFA 없음) → 내부 이동 → 데이터 탈취 → 9일 뒤 랜섬웨어 배포

**어떻게 조치하나**
- 즉시: 모든 외부 접근 포털에 MFA 강제, 해당 계정 비밀번호 교체, 원격 접속 로그에서 비정상 로그인 소급 점검
- 단기: 외부 노출 서비스 전수 목록화, MFA 미적용 예외 제거, 백업 격리 확인, 포털 로그인 이후 내부 이동 탐지와 관리자 권한 분리, 청구·처방 등 핵심 서비스의 대체 업무 절차와 복구 검증
- 장기: 인수합병 시스템의 통제 수준 일치, 핵심 허브 이중화, 데이터 탈취 탐지(대량 아웃바운드)
- 탐지: 평소와 다른 시간·지역의 원격 접속, 침입 후 내부 정찰, 대용량 외부 전송

**교훈**: MFA 한 개 빠진 포털 하나가 국가 단위 장애가 됐다.

### [INC-2024-03-xz] XZ Utils 백도어 (CVE-2024-3094)
> 날짜: 2024-03-29 · 유형: 공급망(오픈소스) · 행위자: 가명 "Jia Tan"(미귀속) · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 리눅스에 널리 쓰이는 압축 프로그램에 누군가 2년에 걸쳐 신뢰를 쌓은 뒤 몰래 '뒷문'을 심었습니다. 한 개발자가 속도 이상을 눈치채서 큰 피해는 막았습니다.

**먼저 할 일(초보용)**: 영향 버전(5.6.0·5.6.1)을 쓰는지 확인하고 안전한 버전으로 바꾸세요.

**개요**: 압축 라이브러리 liblzma 5.6.0·5.6.1에 특정 빌드·연결 조건에서 sshd 인증을 우회할 수 있는 백도어가 삽입됐다. Andres Freund가 sshd의 이상한 CPU 사용을 이상하게 여겨 발견했다.

**왜 일어났나**
- 직접 원인: 약 2년간 신뢰를 쌓은 가명의 공동 유지보수자가 난독화된 테스트 파일에 페이로드를 숨기고 빌드 스크립트로 풀어 넣었다. 압력용 가짜 계정이 원 유지보수자에게 후임 지정을 재촉했다는 정황(보도).
- 구조적 원인: (1) 1인 자원봉사 유지보수 프로젝트가 핵심 인프라 (2) 릴리스 tarball과 저장소 소스가 달라도 검증하지 않는 관행 (3) 간접 의존성(systemd → liblzma → sshd) 가시성 부족

**침투 경로**: 신뢰 구축 → 유지보수 권한 획득 → 난독화된 페이로드 삽입 → 일부 배포판 개발·테스트 채널(Debian/Fedora 등) → 특정 조건에서 sshd 인증 우회. **광범위한 안정판 확산 전에 우연히 발견돼 대규모 피해를 피함.**

**어떻게 조치하나**
- 즉시: 5.6.0/5.6.1 사용 여부 점검, 5.4.x로 다운그레이드 또는 신뢰 가능한 패치 배포판으로 교체하고 sshd 등 관련 프로세스 재시작, 노출 환경 침해 조사
- 단기: SBOM으로 liblzma 의존성 추적, 빌드 시 소스 저장소와 릴리스 아티팩트 비교
- 장기: 핵심 오픈소스의 유지보수자 신원·권한 변경 모니터링, 재현 가능 빌드(reproducible build), 의존성 업데이트에 대한 이상 징후(성능 저하·새 바이너리 블롭) 검토. SBOM·재현 가능 빌드는 악성 소스 자체의 정당성을 보장하지 못하므로 코드 리뷰·유지보수 권한 변경 감시와 병행
- 탐지: sshd 로그인 지연·CPU 이상, 라이브러리 로드 체인 변경

**교훈**: 코드가 아니라 **사람(유지보수자) 신뢰**가 공격 표면이었다.

### [INC-2024-04-panos] Palo Alto PAN-OS GlobalProtect 제로데이 (CVE-2024-3400)
> 날짜: 2024-04-12 · 유형: 엣지 장비 취약점 · 행위자: UTA0218 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 회사 방화벽·VPN 장비(Palo Alto)의 입력 처리 결함 때문에 로그인 없이 관리자 권한으로 명령을 실행할 수 있었습니다.

**먼저 할 일(초보용)**: 업데이트와 제조사 지침을 적용하고, 장비 안에 저장된 비밀번호를 바꾸세요.

**개요**: GlobalProtect 게이트웨이의 명령 주입으로 인증 없이 방화벽 root 코드 실행. 2024-03-26부터 악용된 것으로 분석됐고(Unit 42), Volexity가 4/10 악용을 탐지했으며 벤더 공개는 4/12다. 일부 피해 장비에서 파이썬 백도어 UPSTYLE, 터널링 도구 GOST 설치, 설정 파일 유출, 로그 삭제가 관찰됐으며 피해 수준은 장비마다 달랐다.

**왜 일어났나**
- 직접 원인: 입력 검증 부족으로 세션 ID 처리 경로에 명령 주입. GlobalProtect 게이트웨이와 장비 텔레메트리 기능이 함께 켜져 있을 때 영향(초기 설명). 이후 안내가 정정되어 텔레메트리 비활성화만으로는 충분한 완화가 아니라고 알려졌다(원문 미확인).
- 구조적 원인: 방화벽·VPN이 인터넷 접점이면서 EDR이 없음. 패치 공개 전 제로데이 기간이 존재.

**침투 경로**: 노출된 게이트웨이 → 명령 주입으로 root 실행 → UPSTYLE 백도어 → 설정(자격 증명 포함) 탈취 → GOST로 내부망 진입

**어떻게 조치하나**
- 즉시: 패치와 벤더 완화책 적용, 침해 점검(Unit 42 지침), 장비 내 설정에 저장된 자격 증명·인증서 교체
- 단기: 장비에서 외부로 나가는 통신 제한, 비정상 파일(.pth 등) 점검, 침해 수준별 재이미징 판단, cron·비정상 프로세스·외부 연결 조사, 설정 파일의 웹 경로 복사 탐지
- 장기: 방화벽 관리·GlobalProtect 표면 최소화, 제로데이 대비 격리 절차(임시 비활성화) 문서화
- 탐지: 장비의 비정상 아웃바운드·신규 프로세스·로그 삭제

**교훈**: 보안 장비도 취약하다. 장비 설정에 담긴 비밀은 침해 시 모두 유출된 것으로 보라.

### [INC-2024-05-snowflake] Snowflake 고객 계정 대량 침해 (UNC5537)
