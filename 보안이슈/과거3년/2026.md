### [INC-2026-01-shinyhunters] ShinyHunters SSO 보이스 피싱(vishing) 캠페인
> 날짜: 2026-01 · 유형: 사회공학·신원 · 행위자: ShinyHunters · 지역: 글로벌 · 근거: 보도

**쉽게 말하면**: 공격자가 'IT 지원팀'이라며 직원에게 전화해 가짜 로그인 페이지에 비밀번호와 인증 코드를 입력하게 만들었고, 그렇게 들어가 회사 데이터를 가져갔다고 보도됐습니다.

**먼저 할 일(초보용)**: 인증 코드나 승인 알림 대신 보안키·패스키(속아도 인증되지 않는 방식)를 쓰고, 'IT는 전화로 코드를 묻지 않는다'고 모두에게 알리세요.

**개요**: 2026-01 말 약 100개 조직의 SSO 자격 증명을 노린 대규모 vishing을 시작으로 400개 이상 조직 침해가 보도됐다(공격자 주장과 보도가 섞여 있어 확인된 피해 조직 수는 별도). Charter 약 4,000만 건(4/1), Instructure(Canvas)는 5월 침해 후 5/12 몸값 합의로 알려졌다. 피해 규모 수치는 출처마다 다르다(Instructure: 3,000만 명 vs 2.75억 건·330개 기관 등).

**왜 일어났나**
- 직접 원인: IT 지원을 사칭한 전화로 직원이 피해 조직 **브랜드로 꾸민 피싱 포털**에 Okta SSO 자격 증명과 **MFA 코드까지 입력**하게 만들었다(실시간 중계). AI 음성 에이전트·VoIP 자동 발신으로 규모를 키웠다는 보도.
- 구조적 원인: (1) 일회용 코드 기반 MFA는 **중계(실시간 피싱)에 취약** (2) SSO 한 번 로그인으로 SharePoint·OneDrive·Salesforce·Slack 전체에 접근 (3) 헬프데스크·직원 교육이 전화 기반 사칭에 약함

**침투 경로**: 사칭 전화 → 가짜 SSO 포털 → 자격 증명·MFA 코드 중계 → 정상 로그인 → SaaS 데이터 대량 내보내기 → 공갈

**어떻게 조치하나**
- 즉시: 영향 계정의 세션·MFA 재등록, SaaS 감사 로그에서 대량 내보내기 점검
- 단기: **피싱 저항 MFA(FIDO2·패스키)** 로 전환(코드·푸시 승인 제거), 로그인 허용 기기·도메인 제한(조건부 접근), 직원에게 "IT는 전화로 코드를 묻지 않는다" 교육
- 장기: SSO 세션 수명 단축·재인증 요구, SaaS 데이터 반출 DLP·경보, 헬프데스크 본인 확인 절차 강화
- 탐지: 새 기기·위치에서의 SSO 로그인 직후 MFA 등록 변경, 짧은 시간에 대량 파일·레코드 다운로드

**교훈**: **MFA를 켰다고 끝이 아니다. 피싱 저항형이어야 한다.**

### [INC-2026-01-kyowon] 교원그룹 랜섬웨어
> 날짜: 2026-01-10 · 유형: 랜섬웨어·웹셸 · 행위자: 미확인 · 지역: 한국 · 근거: 보도

**쉽게 말하면**: 교원그룹이 랜섬웨어에 걸려 가상 서버 약 600대가 영향을 받았고 여러 서비스에 장애가 났습니다. 웹서버에 숨은 악성 파일(웹셸)이 사용됐다는 보도가 있으나 최초 침투 방법은 확인되지 않았습니다.

**먼저 할 일(초보용)**: 웹서버에 숨은 악성 파일이 없는지 점검하고, 백업은 업무 네트워크와 분리해 두세요.

**개요**: 1/10 이상 징후, 전체 서버 약 800대 중 가상 서버 약 600대가 영향권에 들었고 8개 이상 계열 서비스에 장애가 났다. 유출 우려 개인정보 554만 명(중복 포함 960만 명) 규모로 보도됐다.

**왜 일어났나**
- 직접 원인: 보도에 따르면 **웹셸이 사용**됐다(최초 진입 경로는 확인되지 않았다). SK텔레콤·KT에서도 웹셸이 보고됐다는 언급이 있으나 동일 공격자·동일 경로로 볼 근거는 없다. 구체적 초기 취약점은 공개되지 않았다.
- 구조적 원인: (1) 웹 서버 취약점·웹셸을 일찍 탐지하지 못함 (2) 가상 서버 다수가 동시에 암호화될 만큼 평면적 네트워크 (3) 공격자 미확인

**침투 경로**: (미공개) 웹 서버 침투 → 웹셸 → 내부 확산 → 가상 서버 600대 암호화

**어떻게 조치하나**
- 즉시: 영향 가상 서버 격리, 웹셸·신규 계정·예약 작업 점검, 백업 무결성 확인 후 복구
- 단기: 웹 루트 무결성 감시(파일 변경 탐지), 웹 서버와 내부망 분리, 하이퍼바이저 관리 접근 격리
- 장기: 가상화 호스트 백업 불변화, 정기 침투 테스트, 개인정보 최소 보관
- 탐지: 웹 서버 프로세스의 쉘 실행, 하이퍼바이저의 대량 VM 동시 암호화·정지

**교훈**: 한국 사고(SKT·롯데카드·교원 등)에서 **웹셸이 반복 보고**된다. 웹셸 탐지는 기본기다.

### [INC-2026-03-stryker] Stryker 와이퍼 공격 (Handala)
> 날짜: 2026-03-11 · 유형: 파괴 공격·클라우드 관리 · 행위자: Handala(이란 정보부 MOIS 연계, 미 법무부 귀속 보도) · 지역: 글로벌 · 근거: 보도

**쉽게 말하면**: 의료기기 기업 Stryker에서 공격자가 관리자 계정을 훔친 뒤, 기기 관리 도구(Intune)의 '원격 초기화' 기능으로 직원 기기를 대량으로 지웠습니다. 별도 악성코드 없이 정상 기능이 무기가 됐습니다.

**먼저 할 일(초보용)**: 관리자 계정에 강한 2단계 인증을 걸고, 대량 삭제는 여러 관리자의 승인이 있어야 실행되게 하세요.

**개요**: 의료기기 기업 Stryker에서 글로벌 Windows 환경의 장치가 대거 초기화됐다. 영향 직원 약 5만 6천 명(61개국 이상, 2차 자료). 별도로 일부 자료는 기기 20만 대 이상·79개국을 주장한다(직원 수와 기기 수는 서로 다른 단위이며 **수치는 출처마다 다르다**).

**왜 일어났나**
- 직접 원인: 공격자가 **관리자 계정을 탈취**한 뒤 클라우드 장치 관리 서비스(Microsoft Intune)의 **원격 초기화(remote wipe)** 기능으로 연결된 모든 기기에 명령을 내렸다. 별도 와이퍼 악성코드 없이도 파괴가 가능했다.
- 구조적 원인: (1) 장치 관리 콘솔 관리자 계정이 침해 가능(MFA·승인 부재) (2) **한 계정이 전 직원 기기를 지울 수 있는 권한 집중** (3) 지정학적 보복 동기에 의한 파괴 목적 공격

**침투 경로**: 관리자 계정 탈취 → Intune 접근 → 전체 장치에 원격 초기화 명령 → 업무 마비

**어떻게 조치하나**
- 즉시: 관리 콘솔 관리자 계정 교체·세션 폐기, 원격 초기화 정책 임시 제한, 복구 우선순위 확정
- 단기: Intune의 Multi Admin Approval 등 **적용 가능한 다중 승인 통제**를 먼저 확인해 대량 초기화·삭제를 제한(적용 가능 여부 검증 필요), 대량 wipe 권한 최소화, 비상 관리자(break-glass) 보호, 특권 관리자 PIM·시간 제한, 관리자 로그인에 피싱 저항 MFA
- 장기: 장치 관리 권한 분할(지역·그룹별), 파괴 시나리오를 포함한 복구 훈련, 오프라인 복구 이미지
- 탐지: 관리 콘솔의 대량 wipe·retire 명령, 관리 정책 변경·초기화 요청 알림, 관리자 비정상 로그인

**교훈**: **관리 콘솔 하나가 곧 무기**다. 파괴 권한은 한 사람이 쥐게 두지 마라.

### [INC-2026-03-teampcp] TeamPCP 보안·개발 도구 공급망 연쇄 (Trivy → Checkmarx → Bitwarden CLI)
> 날짜: 2026-03-16 · 유형: 공급망(CI/CD) · 행위자: TeamPCP · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 보안 점검 도구 Trivy를 시작으로 Checkmarx, Bitwarden CLI까지 개발 도구가 연달아 오염돼 개발자·CI의 비밀 키가 털렸습니다.

**먼저 할 일(초보용)**: 영향 기간에 쓴 키를 모두 바꾸되 감염이 의심되는 환경은 격리한 뒤 안전한 기기에서 바꾸고, '옛 키가 완전히 무효가 됐는지'까지 확인하세요.

**개요**: 2026-02 말 시작해 3/16 Aqua Security의 오픈소스 스캐너 **Trivy**와 관련 GitHub Action에 자격 증명 탈취 악성코드가 삽입됐다. 수확한 토큰으로 Checkmarx Action(`ast-github-action`·`kics-github-action`)과 LiteLLM, 4월 Bitwarden CLI 2026.4.0까지 오염됐다. 4/28 Checkmarx는 비공개 GitHub 데이터 96GB가 LAPSUS$ 갈취 포털에 올랐음을 확인했다. 다운스트림으로 OpenAI·Vercel 등이 영향을 받았다는 보도.

**왜 일어났나**
- 직접 원인: Trivy 저장소의 **불완전한 자격 증명 교체**(회수했다고 믿었지만 일부 남음)로 접근이 유지됐다. 이어 훔친 토큰으로 다음 도구를 오염시켰다.
- 구조적 원인: (1) 보안 스캐너·CI 도구가 비밀값에 접근하는 높은 권한 (2) 서드파티 Action을 변경 가능한 참조로 사용 (3) 한 번의 침해가 다음 저장소 토큰으로 이어지는 **연쇄 구조** (4) 보안 도구를 신뢰해 점검 대상에서 제외

**침투 경로**: 불완전한 키 교체로 접근 유지 → Trivy·Action 오염 → CI에서 개발자 비밀·클라우드 키·SSH 키·K8s 설정 수확 → 다음 도구 오염 → 데이터 유출·갈취

**어떻게 조치하나**
- 즉시: 영향 기간 CI에서 사용된 모든 비밀·토큰 교체, 오염 버전 사용 여부 점검(Microsoft 지침 등 참조)
- 단기: Action·이미지를 **다이제스트·SHA로 고정**, CI 비밀 최소화·OIDC, **키 교체 시 구 키 완전 폐기 검증**
- 장기: 보안 도구의 CI 권한 분리·네트워크 egress 제한, 도구 업데이트 자동 적용 대신 검증 후 적용
- 탐지: CI에서 예상 밖 외부 접속·비밀 열거, 새 GitHub PAT·배포 키 생성

**교훈**: **보안 도구도 공급망이다.** 키 교체는 "새 키 발급"이 아니라 "옛 키 사망 확인"이다.

### [INC-2026-04-fbi] FBI 감시 시스템 침해 ("major incident" 지정)
> 날짜: 2026-04-02 · 유형: 국가 지원 APT·서드파티 · 행위자: 중국 연계 의심(Salt Typhoon 지목 보도, 확정 아님) · 지역: 미국 · 근거: 보도

**쉽게 말하면**: FBI는 감시 시스템이 인터넷 업체의 연동 구간을 통해 침해됐다고 의회에 알렸습니다. 중국 연계 의심 보도가 있지만 확정은 아닙니다.

**먼저 할 일(초보용)**: 외부 업체와 연결된 구간의 로그인·접속 기록을 점검하세요.

**개요**: FBI가 의회에 내부 감시 시스템(Digital Collection System Network) 침입을 FISMA상 "major incident"로 통보했다. 이 시스템에는 법원 승인 감청 결과, 통신 기록 정보, FISA 영장 자료, 수사 대상 개인정보가 저장된다. 법무부는 3/23 지정을 결정했다.

**왜 일어났나**
- 직접 원인: FBI는 공격자가 **상용 인터넷 서비스 제공자(ISP)의 벤더 인프라를 이용**해 접근한 것으로 보인다고 밝혔다.
- 구조적 원인: (1) 정부 시스템과 통신사 연동 경로의 신뢰 (2) 앞선 Salt Typhoon 침해(2024)와 같은 통신 장비 취약점 부채 (3) 고가치 정보(감청 대상) 집중

**침투 경로**: 통신사·ISP 벤더 인프라 침해 → 연동 경로로 감시 시스템 접근 → 감청·메타데이터 열람

**어떻게 조치하나**
- 즉시: 영향 연동 경로 차단, 노출 가능성이 있는 수사 대상·정보원 보호 조치
- 단기: 벤더·ISP 연동 구간의 인증·로그 점검, 감청 시스템 접근 감사
- 장기: 통신사 연동 최소화·분리, 감청 데이터 암호화·접근 최소화, 공급사 침해 통지 SLA
- 탐지: 연동 계정의 비정상 조회, 평소와 다른 경로의 접속

**교훈**: 감시 인프라는 **감시당하는 대상**이 된다. 서드파티 연동 구간이 가장 약한 고리다.

### [INC-2026-05-tving] 티빙(TVING) 가입자 3,954만 계정 유출
