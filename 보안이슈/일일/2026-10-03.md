### [D20261003-fortimail] FortiMail CVE-2026-104286
> 날짜: 2026-10-01 · 유형: 엣지 장비 취약점 · 행위자: 미귀속 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 메일 보안 장비(FortiMail)에 로그인 없이 파일을 써 넣을 수 있는 결함이 있고, 실제로 공격에 쓰이고 있습니다.

**먼저 할 일(초보용)**: 제조사의 임시 조치(IBE 끄기, 관리 화면을 인터넷에서 닫기)를 적용하고, 수정 버전이 나왔는지 확인하세요.

**개요**: FortiMail에서 인증 없이 파일을 쓰는 제로데이가 악용 중이며 CISA KEV에 10/1 등재됐다(CVSS 9.8, Fortinet 공지 FG-IR-175). 영향 버전은 8.0.0–8.0.1, 7.6.0–7.6.6, 7.4.0–7.4.8, 7.2.0–7.2.9다.

**왜 일어났나**
- 직접 원인 [확인: Fortinet]: 경로 순회(CWE-22)와 널 바이트(NULL byte) 처리 오류(CWE-158)가 결합해, 조작된 HTTP(S) 요청으로 인증 없이 파일 쓰기가 가능하다. 경로 검증과 파일 쓰기 단계의 문자열 해석 차이일 가능성은 있으나 구체 메커니즘은 미공개다 [추정: 본 보고서].
- 구조적 원인 [추정]: (1) 메일 보안 장비의 웹/IBE 관리면이 인터넷에 노출 (2) 장비에 EDR이 없어 변조를 못 봄 (3) 7.2 계열은 지원 종료 성격으로 수정 대상이 아님(7.4 이상 이전 권고)

**관측된 아티팩트 [확인]** (실행 순서는 확인되지 않음): `/data/lib/liblog.so`와 `/data/etc/ld.so.preload` 추가, `/data/bin/webconsole`·`/data/bin/mailservice` 추가, `/bin/smit`·`/data/etc/httpd.conf`·`/data/migadmin.tar.gz` 변조, root cron이 `/migadmin` 참조, 의심 아카이브 계정 `archive234`가 데이터를 유출하도록 설정. IOC: IP `79.141.169.187`, `45.129.0.192`.

**침투 경로 [추정: 본 보고서]**: 노출된 웹/IBE → 임의 파일 쓰기 → `ld.so.preload`로 `liblog.so`를 프로세스에 주입 → cron으로 재부팅 후 유지 → 아카이브 계정으로 메일 수집. 각 파일의 구체 기능은 공개 자료에 없다.

**어떻게 조치하나**
- 즉시: IBE 기능 비활성화(CLI), 관리 인터페이스를 신뢰 대역으로 제한하거나 인터넷에서 제거, **수정 버전(8.0.2 / 7.6.7 / 7.4.9 이상) 출시 여부 확인 후 즉시 적용**
- 단기: `ld.so.preload`, `liblog.so`, `/migadmin` cron, `archive234`, 비인가 아카이브·전달 규칙 점검. 변조가 확인되면 **제거가 아니라 재구축**을 우선하고, 장비에 저장된 자격 증명·인증서·키 교체
- 장기: 7.2 → 7.4 이상 이전, 메일 장비 관리면 비노출, 장비 로그 외부 보존
- 탐지: 장비의 신규 공유 라이브러리·cron 변경, IBE 복호화 시 잘못된 Base64 오류, 위 IOC IP와의 통신

**교훈**: 메일 장비는 모든 메일이 지나가는 곳이다. 침해되면 **메일 내용과 인증 링크** 전부가 노출된다.

### [D20261003-citrix] Citrix NetScaler CVE-2026-88771 / -88772
> 날짜: 2026-09-27 · 유형: 엣지 장비 취약점 · 행위자: 미귀속 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 회사 원격 접속 장비(NetScaler)의 결함 두 개가 이미 공격에 쓰이고 있습니다. 공개되기 3주 전부터 악용됐다는 관측이 있습니다.

**먼저 할 일(초보용)**: 패치 직전에 가능한 범위에서 로그와 설정을 신속히 보존하고(조사는 병행) 지체 없이 패치한 뒤, 접속 중인 세션을 모두 끊으세요.

**개요**: NetScaler ADC·Gateway의 제로데이 2건이 전 세계에서 악용돼 CISA KEV에 9/27 등재됐다(CISA 공지는 CVE-2026-88771~88778 8건 중 2건이 치명적 제로데이). 벤더 공지는 CTX697096.

**왜 일어났나**
- 직접 원인 [확인]: -88771은 입력 검증 미흡으로 인증 없이 명령 실행, **기본 구성에서도 영향**. -88772는 DTLS(UDP 기반 TLS) 파싱 코드의 힙 버퍼 오버플로로, DTLS가 VPN 가상 서버에서 기본 활성화되어 있다(영향 버전 범위는 벤더 공지 확인).
- 구조적 원인: (1) VPN 포털이 인터넷에 직접 노출 (2) 기본 활성 기능이 공격 면이 됨 (3) 장비 내부에 EDR이 없음 (4) 2023 Citrix Bleed 이후에도 같은 제품군에서 반복
- 악용 시점 [관측: eSentire]: -88771은 **9월 5일부터** 악용돼 KEV 등재(9/27)보다 22일 앞섰다. 벤더 공개일이 이보다 늦었는지는 확인하지 못했다.

**관측된 공격 [확인]**: 인터넷 노출 Gateway에 조작 요청 → 인증 없이 명령 실행 → 웹셸 `/var/netscaler/logon/LogonPoint/custom/.ctxs.receiver`(확장자 없이 PHP 실행) → `/etc/httpd.conf`에서 `php_engine` 활성화(CERT-EU) → 웹셸이 `NSC_CLIENTTYPE` 헤더의 Base64 PHP 코드를 실행. 내부망 진입 가능성은 [추정]이며 후속 이동은 확인된 바 없다.

**어떻게 조치하나**
- 즉시: **패치 전에** 침해 지표 확인·포렌식 증거(로그·설정·메모리) 보존(CISA 권고), 그다음 패치. 패치 후 **활성 세션 전부 종료**, 장비 저장 자격 증명 교체
- 단기: 위 웹셸 경로·`php_engine` 설정·`NSC_CLIENTTYPE` 이상 값 점검, 침해 의심 장비는 재구축, NetScaler Console의 IOC 확인
- 장기: VPN·게이트웨이 앞단 관리면 분리, 엣지 장비 로그 외부 보존, 악용 확인 시 우선 격리·긴급 패치 SLA
- 탐지: 헤더 `NSC_CLIENTTYPE`에 Base64 문자열, `custom` 디렉터리의 비PHP 확장자 파일, 장비의 비정상 아웃바운드

**교훈**: **패치 전에 증거 보존** — 패치가 아티팩트를 지울 수 있다. 같은 제품이 3년 만에 다시 제로데이다.

### [D20261003-cisco] Cisco SD-WAN Manager CVE-2026-76504
> 날짜: 2026-09-30 · 유형: 엣지 장비 취약점 · 행위자: 미귀속 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: Cisco SD-WAN 관리 화면의 로그인 검사가 주소의 글자 하나를 다르게 쓰면(%6a) 건너뛰어져서 관리자처럼 접속할 수 있었습니다.

**먼저 할 일(초보용)**: 바로 패치(우회 방법이 없습니다)하고, 관리 화면을 인터넷에서 닫으세요.

**개요**: SD-WAN Manager API 인증 우회(CVSS 9.8). Cisco PSIRT가 9월 악용을 인지했고 CISA KEV에 9/30 등재됐다. 올해 Cisco SD-WAN 제어 구성요소의 세 번째 치명적 인증 우회라고 Rapid7이 지적했다.

**왜 일어났나**
- 직접 원인 [확인: Cisco, Rapid7]: URL 인코딩 처리 오류(CWE-177). 특정 API 엔드포인트의 인증 규칙이 `j_security_check` 경로를 `%6a`(=`j`)처럼 인코딩한 요청에는 적용되지 않고, 요청은 그대로 처리되어 admin 권한 API에 접근된다.
- 구조적 원인 [추정]: (1) 인증 검사와 라우팅이 서로 다른 단계에서 문자열을 해석 (2) SD-WAN 컨트롤러가 인터넷에 노출 (3) 같은 구성요소의 반복 취약점

**관측된 후속 행위**: 공개 자료에서 **확인되지 않음**. admin API 접근만으로 구성정보 수집이 성립하는 것은 아니다.

**어떻게 조치하나**
- 즉시: 패치 20.9.10.1 / 20.12.8.2 / 20.15.6.1 / 20.18.4.1 / 26.1.2.1 / 26.2.1 (우회책 없음). KEV 기한 10/3(2차 자료 기준)
- 단기: Manager 관리면 인터넷 비노출·허용 IP 제한, `serviceproxy-access.log`·`vmanage-server.log`에서 인코딩된 인증 경로 POST와 사용자명 `viptela-reserved-*` 점검, admin 계정·API 키 감사
- 장기: SD-WAN 컨트롤러를 관리망에만 두기, 구성 변경 승인·감사 로그 외부 보존
- 탐지: 인코딩된 `j_security_check` 요청, 평소 없던 admin API 호출

**교훈**: **인증 검사 위치와 처리 위치가 다르면** 인코딩 한 글자로 우회된다. 정규화 후 검사.

### [D20261003-wordpress] WordPress CVE-2026-87902
> 날짜: 2026-09-22 · 유형: 웹 애플리케이션 취약점 · 행위자: 미귀속 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 워드프레스의 결함으로, 특정 조건의 사이트에서는 로그인 없이 서버 코드가 실행됩니다. 패치가 공개된 당일부터 공격이 있었습니다.

**먼저 할 일(초보용)**: 워드프레스를 최신 버전으로 올리고 자동 업데이트를 켜세요.

**개요**: `get_page_template()` 템플릿 해석 로직 결함으로 인증 없이 RCE 가능(CVSS 9.2). 9/22 패치 당일 11:49 UTC에 첫 악용, 9/23~25 허니팟에서 68건 이상, KEV는 9/25.

**왜 일어났나**
- 직접 원인 [확인: Patchstack 등]: 조작된 요청으로 읽을 수 있는 임의 로컬 `.php`를 include(LFI). KEV는 "Remote File Inclusion"으로 분류하지만 이는 KEV의 표현이고, 관측된 흐름은 *로컬 include → PHP 파일 생성 → 원격 스크립트 수령*이다.
- 선행 조건 [확인]: 활성 테마 최상위 디렉터리명이 `page-`로 시작하고, 웹 서버가 읽을 수 있는 PHP(대표적으로 `pearcmd.php`)가 있을 것. 조건이 좁아 모든 사이트가 영향받지는 않는다.
- 구조적 원인 [추정]: (1) 서버에 `pearcmd.php` 같은 도구가 남아 있음 (2) 웹 서버 계정이 `/tmp`에 쓸 수 있음 (3) 공개 즉시 자동 악용 스캐너가 대응

**관측된 공격 [확인]**: 조작 요청 → `pearcmd.php` include → `/tmp`·`/var/tmp`에 PHP 파일 쓰기 → GitHub 호스팅 업로드 스크립트 수령 → 웹셸 실행.

**어떻게 조치하나**
- 즉시: 7.1.2 / 7.0.6 / 6.9.9 / 6.8.10로 업데이트, **자동 업데이트 활성화**
- 단기: 테마 디렉터리에 `page-` 접두 폴더가 있는지 점검, `/tmp`·`/var/tmp`의 PHP 파일·`wp-pear-rce-flag.php`·`poc87902.php` 점검, 웹 서버의 `/tmp` 쓰기·실행 제한
- 장기: 컨테이너에서 PEAR 제거(`pearcmd.php` 불필요 시), `open_basedir`·읽기 전용 파일 시스템, 웹셸 탐지
- 탐지: `/tmp` 아래의 PHP 생성, 웹 서버 프로세스의 외부 다운로드(GitHub)

**교훈**: **패치 공개 = 악용 시작**(몇 시간). 자동 업데이트와 불필요한 도구 제거가 가장 싼 방어다.

### [D20261003-peoplesoft] Oracle PeopleSoft CVE-2026-35273 / ShinyHunters
> 날짜: 2026-06-10 · 유형: 엣지·ERP 취약점 · 행위자: ShinyHunters(UNC6240) · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 대학·기업이 쓰는 PeopleSoft의 결함을 ShinyHunters가 악용했습니다. 방화벽(WAF)의 차단 규칙은 글자 하나를 다르게 쓰는 것만으로 피해 갔습니다.

**먼저 할 일(초보용)**: 방화벽 규칙에 기대지 말고 실제 패치를 적용하세요.

**개요**: PeopleSoft Environment Management Hub(`/PSEMHUB/`)의 인증 없는 RCE(CVSS 9.8). 5/27부터 제로데이로 악용, 6/10 Oracle 공개. Google GTIG는 ShinyHunters를 UNC6240으로 추적하며 6월 기준 100개 이상 조직이 피해를 입었다.

- 즉시: **패치 적용**(WAF 규칙으로 대체 금지), PSEMHUB 접근을 내부망·허용 IP로 제한, 로그에서 `/PSEMHUB/`와 `/%50SEMHUB/` 검색
- 단기: 웹셸(`x.jsp`, `u.jsp`, `tunnel.jsp*`), `Ple64.exe`, MeshAgent·Neo-reGeorg 흔적 점검, 의심 서버의 자격 증명 교체, 공갈 메일 수신 시 법무·수사기관 연계
- 장기: ERP 관리 기능 비노출, WAF 규칙을 **디코딩 후 정규화 기준**으로 점검, 정기 침투 테스트

## 5. 우선 대응 체크리스트

**패치와 침해 대응은 별개의 완료 조건이다.** 패치만으로 이미 설치된 웹셸·로더 변조·탈취된 인증 자료는 사라지지 않는다.

1. **오늘**: Cisco SD-WAN(KEV 기한 10/3) 패치. Citrix는 패치 **전** 로그·설정·메모리 증거 보존 및 IOC 점검 후 패치.
2. **10/5까지**: Zammad 7.2.0(기한 10/5). 패치와 함께 기존 세션 무효화, 인증 후 세션 ID 재발급 동작 확인. WordPress 최신 보안 릴리스, PeopleSoft 패치 확인.
3. **관리 평면 노출 점검**: FortiMail·NetScaler·SD-WAN 관리 인터페이스, PSEMHUB가 인터넷에 꼭 열려 있어야 하는지 확인하고 허용 출발지를 제한.
4. **FortiMail**: IBE 비활성화, 관리 인터페이스를 신뢰 대역으로 제한, `ld.so.preload`·`archive234`·`/migadmin` cron 점검, 비인가 아카이브 계정·전달 규칙 조사, 수정 버전 출시 여부 확인. 변조가 확인되면 제거보다 재구축 우선.
5. **헌팅**: WebLogic·프록시 로그의 `/PSEMHUB/`와 `/%50SEMHUB/`, 인코딩된 `j_security_check`, `NSC_CLIENTTYPE` 이상 값, `/tmp`·`/var/tmp`의 PHP 파일. 파일명 IOC만 보지 말고 **원문 URI와 실제 처리 경로를 함께 로깅**하고 `%6a`·`%50` 문자열 차단에만 의존하지 않는다.
6. **행위 탐지**: 동적 링커 설정·공유 라이브러리·cron·웹 실행 설정 변경, 웹 프로세스의 파일 생성·자식 프로세스·예상 밖 외부 통신. MeshAgent 같은 합법 원격 도구는 승인 기준과 비교.
7. **Apple**: OS 업데이트 적용 상태 확인. 표적 공격 가능성이 있는 사용자는 별도 조사 절차 검토.
8. **데이터 보호**: 민감정보(SSN 등) 최소 수집·보유기간·암호화·대량 다운로드 감사, 각 사건의 최초 악용일까지 소급 가능한 로그 보존 여부 확인.
