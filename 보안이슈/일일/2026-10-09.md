## 2. 이슈별 분석

### [D20261009-kev-legacy] CISA, 오래된 취약점 5건을 '악용 확인' 목록에 추가
> 날짜: 2026-10-08 · 유형: 오래된(레거시) 결함의 재악용 · 행위자: 미공개 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 미국 CISA가 2015~2023년에 알려진 오래된 보안 결함 5개가 지금도 실제 공격에 쓰이고 있다고 목록에 올렸습니다. 파일 전송(ProFTPD), 문서 편집(ONLYOFFICE), 웹 관리(Strapi), 웹 개발틀(Struts), 주소 서버(BIND) 프로그램입니다. 오래전에 고쳐진 결함도 업데이트하지 않은 서버가 남아 있으면 그대로 뚫립니다.

**먼저 할 일(초보용)**: 담당자는 우리 회사에서 이 다섯 프로그램을 쓰는지 자산 목록에서 찾고, 쓴다면 버전을 확인해 최신으로 올리세요. 더 이상 지원되지 않는 버전(Strapi 항목은 지원 종료 가능성이 명시됨)은 업데이트가 어려우니 교체·폐기를 검토하세요. 인터넷에 직접 열려 있다면 먼저 접근을 막으세요.

**개요**: CISA KEV 직접 확인 결과 10/8 등재 5건(CISA KEV에 기재된 조치 기한이 모두 10/11이며 모든 기업에 적용되는 법정 마감은 아니다): ① ProFTPD CVE-2015-3306 — `site cpfr/cpto` 명령으로 서버 안 파일을 복사해 읽기·쓰기(서비스 권한과 환경에 따라 정보 노출이나 코드 실행으로 이어질 수 있음) ② ONLYOFFICE Docs CVE-2021-3199 — JWT 사용 시 이미지 업로드 경로 조작(path traversal)으로 원격 코드 실행 가능 ③ Strapi CVE-2023-22894 — 관리자 화면 접근자가 쿼리 필터를 이용해 민감한 값을 알아낼 수 있고(관리자 권한에 따라 대상이 달라짐) CVE-2023-22621과 연쇄 시 원격 코드 실행 가능(KEV가 지원 종료 가능성을 명시하므로 영향받는 버전의 지원 상태 확인 필요) ④ Apache Struts CVE-2016-3081 — 동적 메서드 호출이 켜진 경우 `method:` 접두어로 코드 실행 ⑤ ISC BIND CVE-2015-5477 — TKEY 질의로 서비스 거부(DoS). 랜섬웨어 사용 여부는 목록상 '알 수 없음'이다. 누가·어디서·어떤 규모로 악용했는지는 공개되지 않았다.

**왜 일어났나**
- 직접 원인 [확인: KEV 등재 사유]: CISA가 '실제 악용 증거가 있다'고 판단한 결함이다. 구체적 공격 경위는 공개되지 않았다.
- 구조적 원인 [추정]: 피해 환경의 패치 지연 원인은 공개되지 않았다. 구버전 잔존·자산 목록 누락·지원 종료 제품 사용 여부를 점검할 필요가 있다(점검 항목이며 원인으로 확인된 것이 아니다).

**침투 경로 [확인 범위]**: 인터넷에 열린 서비스의 알려진 결함 악용(구체 경로 미공개). 5건 모두 검토한 공개 자료에는 개별 침해 경위와 피해 규모가 제시되지 않았다.

**어떻게 조치하나**
- 즉시: 자산 목록·스캐너로 제품명뿐 아니라 실제 버전·구성·인터넷 노출·내장 구성요소를 확인한다(Struts는 동적 메서드 호출 비활성화가 우회책으로 알려져 있으나 패치를 대체하지 않는다). 증거(접속 로그·설정)를 보존하되 패치를 미루지 않고 제조사 수정 버전으로 올린다. 올릴 수 없으면 인터넷 노출을 차단한다. CISA 필수 조치는 제조사 완화책 적용(없으면 사용 중단)이다.
- 단기: 해당 서비스의 과거 로그에서 비정상 파일 명령·경로 조작 요청 소급 점검, 웹셸·새 계정 확인. 침해 흔적이 있으면 그 서버에서 새 비밀을 만들지 말고 재구축을 검토한다.
- 장기: 지원 종료 소프트웨어 교체 계획, 인터넷 노출 자산 정기 점검, 신규 등재와 자산 목록의 자동 대조.
- 탐지: 해당 서비스 프로세스가 갑자기 셸을 실행하거나 낯선 파일을 쓰는 행위.

**교훈**: 새 제로데이만 위험한 것이 아니다. 10년 된 결함도 방치된 서버에서는 여전히 입구가 된다.

### [D20261009-cisco-seg] Cisco Secure Email Gateway CVE-2026-76461 — 로그인 없이 루트 명령 실행
> 날짜: 2026-09-14 · 유형: 엣지·웹 서비스 취약점 · 행위자: 미귀속 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 회사로 들어오는 메일을 걸러 주는 Cisco 장비에서, 조작된 메일 한 통만으로 장비의 최고 권한(루트)으로 명령을 실행할 수 있는 결함이 이미 악용되고 있습니다. 보안 장비 자체가 뚫리면 메일 내용 열람이나 내부망 침투의 발판이 될 수 있습니다. 한 달 가까이 지난 건이지만 아직 이 저장소에 정리하지 못해 오늘 추가합니다.

**먼저 할 일(초보용)**: 담당자는 Cisco 이메일 게이트웨이(AsyncOS)를 쓰는지 확인하고 Cisco 공지의 수정 버전으로 올리세요. 우회책이 없다고 보도됐으니 패치가 핵심입니다. 이미 침해됐을 수 있으니 패치 후에도 Cisco가 공개한 침해 지표(IOC)로 점검하되(미검출이 미침해의 증거는 아님), 장비 안의 로그는 공격자가 지울 수 있으므로 방화벽·네트워크 기록과 대조하세요.

**개요**: CISA KEV 직접 확인: CVE-2026-76461은 'Cisco Secure Email Gateway SQL 인젝션 취약점', 설명은 "인증 없는 원격 공격자가 AsyncOS의 SQL 인젝션으로 기반 OS에서 루트 권한 임의 명령을 실행할 수 있다", 2026-09-14 등재, 기한 9/17(이미 경과), 랜섬웨어 사용 '알 수 없음'. 검색으로 확인한 보도(SecurityWeek·Sophos·The Hacker News 등, 원문은 직접 열람하지 못함)에 따르면 CVSS 9.8, 물리·가상 장비 모두 영향, Secure Email and Web Manager와 Secure Web Appliance는 영향 없음, 조작된 메일로 악용, 공격자는 미상. 권고 버전 예: AsyncOS 16.5.0-780(보도 기준이며 계열별 수정 버전은 다를 수 있으니 Cisco 공지로 확인).

**왜 일어났나**
- 직접 원인 [확인: KEV 설명]: 메일 분석 코드의 SQL 삽입(SQL 인젝션: 입력값이 데이터베이스 명령으로 해석되는 결함)이 루트 명령 실행으로 이어짐.
- 구조적 원인 [추정]: (1) 외부 메일을 처음 받는 장비가 인터넷에 직접 노출되는 구조 (2) 보안 장비가 높은 권한으로 동작 (3) 장비 내부는 사용자가 점검하기 어려운 블랙박스. 분석이며 확인된 사실이 아니다.

**침투 경로 [보도 범위]**: 조작된 메일 → 장비의 메일 처리 → SQL 인젝션 → 루트 명령 실행. 이후 행위(자격 증명 탈취 등)는 확인되지 않았다.

**어떻게 조치하나**
- 즉시: 증거(장비 로그·설정·가능하면 디스크 사본)를 보존하고 수정 버전으로 올린다. 패치를 미루지 않는다.
- 단기: Cisco 공개 IOC 점검, 장비 로그만 믿지 말고 외부 방화벽·메일 시스템 기록과 대조(클러스터는 전 구성원 조사, 패치만으로 침해 제거를 단정하지 않으며 복구 후에도 모니터링). 침해가 의심되면 증거 보존 후 새 장비(가상이면 새 VM)에 설정을 다시 구축하고(Cisco 공지가 강하게 권고한다고 알려짐; 물리 장비는 Cisco 지원 문의, 클러스터는 침해 멤버가 있으면 전체를 안전하게 복구), 장비에 저장된 연동 계정·인증서·키를 깨끗한 환경에서 교체한다(비밀번호만 바꾸면 이미 발급된 토큰은 남음).
- 장기: 메일 보안 장비의 관리면 분리, 이상 행위 모니터링, 이중화로 패치 중 서비스 영향 완화.
- 탐지: 장비에서 낯선 프로세스·외부 접속, 비정상 메일 처리 오류.

**교훈**: 메일을 지켜 주는 장비가 가장 먼저 공격받을 수 있다. 보안 장비도 패치 대상이다.

## 3. 교차 분석

> 표본은 2건이며 추세를 말하지 않는다.

1. **공통점은 '노출된 서비스의 알려진 결함'**: 두 건 모두 인터넷에 열린 서비스·장비의 결함이다. 다만 하나는 10년 된 결함 묶음이고 하나는 최신 결함이다.
2. **패치 지연의 비용**: KEV 기한이 지난 뒤에도 장비를 확인하지 않은 곳은 위험이 이어진다.

## 5. 우선 대응 체크리스트

1. **레거시 5종**: 자산 목록 대조, 패치·폐기, 인터넷 노출 차단(기한 10/11).
2. **Cisco SEG**: 수정 버전, IOC 점검, 외부 기록 대조.
3. **Citrix(10/7 기한 경과)** 등 앞선 건의 후속은 [10-06](2026-10-06.md)·[10-08](2026-10-08.md) 참고.

## 6. 검증 수준과 한계

- KEV 등재(날짜·설명·기한)는 CISA 피드로 직접 확인했다. 그 외 Cisco 건의 세부(CVSS·버전·IOC)는 검색 결과의 2차 보도로 Cisco 원문 공지는 직접 열람하지 못했다.
- 레거시 5건의 악용 주체·규모·방식은 확인하지 못했다. ATT&CK 매핑은 '노출 서비스 악용' 수준이며 레거시 5건은 '후보'로 둔다(BIND는 서비스 거부 기능이라 T1499.004 후보).
- 국내: 금융·통신·이커머스·공공·교육·의료·랜섬웨어 질의를 했으나 10/8~9 신규 대형 사건은 찾지 못했다. 금융위 10/7 회의 결과 발표는 확인하지 못했다. 국내뉴스에는 10/3~6 보도 4건을 추가했다.
- 9/22~25 KEV 일부(SharePoint·MikroTik·Magento·WSO2·Check Point)는 이번에도 분석하지 못했다.
- ATT&CK는 v19.2 기준이다(공식 사이트 점검 결과는 최종 요약 참고).
