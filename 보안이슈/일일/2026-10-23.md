### [D20261023-connectwise] 커넥트와이즈 클라우드 백업 침해 — AI 에이전트 도구 '아르텍스'로 계정 탈취(Storm-0940)
> 날짜: 2026-10(9월부터 공격, 10/15 이후 수법 변화, 10/23 MS 분석 공개) · 유형: 비밀번호 대입 + 신뢰 관계 악용 · 행위자: Storm-0940(중국 정부 연계 추정) · 지역: 글로벌(한국 금융권 연관 이력 포함) · 근거: 확인

**쉽게 말하면**: 마이크로소프트(MS)가 클라우드 백업 업체 커넥트와이즈(ConnectWise)의 침해 사건을 분석한 결과, 공격자가 AI가 스스로 여러 단계를 이어서 수행하는 "에이전트형" 해킹 도구 '아르텍스(ARTEX)'로 비밀번호 대입 공격과 계정 탈취를 자동화했고, 일부에서는 공격 시작 3시간 안에 관리자급 권한까지 손에 넣었다고 밝혔습니다. 이 도구는 과거 한국 금융기관을 겨냥한 공격에도 쓰인 적이 있어, 레코디드퓨처는 최근 한국 금융권을 노리는 공격 조직을 별도로 추적하고 있습니다.

**먼저 할 일(초보용)**: 커넥트와이즈 서비스를 연동해 쓰고 있다면, 담당자는 연동 계정·토큰을 지금 재발급(회전)하고 MS 그래프·디렉터리에 낯선 계정·그룹·권한이 생기지 않았는지 확인하세요. 일반 이용자는 이 사건으로 바로 할 일은 없지만, 소속 기관이 커넥트와이즈를 쓰는지 담당 부서에 문의할 수 있습니다.

**개요**: MS 위협 인텔리전스에 따르면 '아르텍스'는 고(Go) 언어로 만든 AI 에이전트형 침투 테스트 도구로, 표적 탐색부터 비밀번호 대입, 권한 악용까지 공격 과정을 자동으로 수행한다. 맞춤 배포본은 중국 AI 모델 딥시크(DeepSeek)를 쓰도록 설정돼 있었고 일부는 GLM·그록(Grok)도 지정됐다. 9월부터 중국 정부 연계 조직 '스톰-0940(Storm-0940)'이 이 도구로 항공우주·방산·자동차·금융·정부·반도체 등 14개 분야 수백 개 조직을 공격했다. 10/10~14 사이 8개 조직 계정 327개를 대상으로 대규모 비밀번호 대입을 시도해 실패 로그인이 15만 1천 건을 넘었으나(11일 하루 11만 건 이상, 최대 분당 2,900건) 실제 로그인 성공은 없었다. 10/15 이후에는 고객사 접근에 쓰이는 애플리케이션(OAuth) 자격 증명을 확보해 대화형 사용자 로그인 없이 앱 자체 인증으로 고객 환경에 진입하는 방식이 관측됐고(두 수법의 인과관계는 MS도 명시하지 않음), 일부 사례에서는 MS 그래프·계정 디렉터리까지 들어가 인증 정보·사용자 계정·그룹·고권한 역할을 조작했다. '아르텍스'는 과거 한국 금융기관 공격에도 쓰인 전력이 있는데(이후 소스코드는 비공개 전환), 레코디드퓨처 인사이크트그룹은 한국 금융권을 노리는 별도 조직을 'TAG-217'로 추적 중이며 8/17부터 원격 접속 기반시설 테스트·인터넷 스캔을 시작한 것으로 분석했다. **MS는 스톰-0940이 한국 금융권을 공격했다고 확정하지는 않으며, 도구가 여러 조직에서 공유돼 쓰인다는 점만 확인했다.**

**왜 일어났나**
- 직접 원인 [확인: MS]: AI 에이전트 도구로 대규모 비밀번호 대입을 자동화했으나(10/10~14, 로그인 성공 없음) 이와 별도로 커넥트와이즈 연동 애플리케이션(OAuth)의 자격 증명을 확보해, 사람이 직접 로그인하는 절차 없이 앱 자체의 인증으로 고객 환경에 접근했다. 비밀번호 대입이 이 자격 증명 확보로 직접 이어졌는지는 MS도 명확히 밝히지 않았다.
- 구조적 원인 [추정]: (1) MSP·백업 업체처럼 여러 고객사에 연결된 서비스 계정은 한 번 장악되면 사용자 암호와 무관하게 모든 연결 고객사로 번질 수 있다 (2) AI 에이전트 도구는 사람이 수십 시간 걸릴 단계를 자동으로 빠르게 이어 붙여, 탐지·대응이 따라가기 전에 권한 상승까지 끝낼 수 있다 (3) 범용 AI 모델을 침투 작업에 맞게 "조립"하는 방식이라 특정 벤더 하나를 막아도 다른 조직이 같은 도구를 계속 쓸 수 있다.

**침투 경로 [확인: MS]**: 대규모 비밀번호 대입(10/10~14, 로그인 성공 없음, 별개 관측) + 커넥트와이즈 연동 애플리케이션(OAuth)의 자격 증명 확보(경로 비공개) → 대화형 사용자 로그인 없이 앱 자체 인증으로 신뢰 관계를 악용해 고객 환경 진입 → (일부) MS 그래프·디렉터리 접근으로 인증 정보·계정·그룹·고권한 역할 조작.

**어떻게 조치하나**
- 즉시: 증거(인증 로그·디렉터리 변경 이력) 보존 후 커넥트와이즈 연동 애플리케이션 계정·토큰을 전면 재발급. MS는 공격자가 추가한 인증 정보가 정리 후에도 남아 다른 계정·클라우드 서비스 접근 통로로 쓰일 수 있다고 경고했으므로, 재발급 전 디렉터리 전체(계정·그룹·권한 변경 이력)를 점검한다.
- 단기: MS 그래프·디렉터리 감사 로그에서 비정상적인 계정·그룹·권한 생성 이력 전수 조사. 애플리케이션(서비스) 계정에도 조건부 접근·이상 로그인 탐지 적용.
- 장기: MSP·백업처럼 여러 고객사를 잇는 서비스 계정은 최소 권한·단기 토큰으로 제한하고, 사용자 암호와 별개로 애플리케이션 계정 자체의 이상 행위 탐지 체계를 갖춘다.
- 탐지: 짧은 시간 내 다수 계정에 대한 대량 로그인 실패, 애플리케이션 계정의 평소와 다른 디렉터리 접근·권한 변경 시도.

**교훈**: 비밀번호 대입이 전부 실패해도 공격이 끝난 게 아니다. 이미 부여된 애플리케이션 권한 하나만 장악하면 AI 도구가 사람 없이 몇 시간 안에 관리자 권한까지 이어 붙일 수 있다.

### [D20261023-velocloud] Arista VeloCloud Orchestrator 제로데이(CVE-2026-114625)
> 날짜: 2026-10-23(벤더 공지·패치 공개) · 유형: SQL 삽입 → 권한 상승 · 행위자: 미귀속 · 지역: 글로벌 · 근거: 확인

**쉽게 말하면**: 기업 네트워크를 중앙에서 관리하는 Arista의 VeloCloud Orchestrator(VCO, 자체 설치형)에서 낮은 권한의 로그인 사용자가 데이터베이스 명령을 끼워 넣는 결함으로 "슈퍼유저" 권한까지 올라갈 수 있는 치명적 결함이 실제로 공격에 쓰이고 있습니다.

**먼저 할 일(초보용)**: VCO On-Prem을 운영한다면 지금 5.2.3.18·6.1.3.10·6.4.2.12 이상으로 업데이트하세요. 당장 패치가 어렵다면 Arista가 공개한 공격자 IP(74.82.197.86, 38.54.50.151)를 차단하고 관리 웹 화면 접근을 관리망으로만 제한하세요.

**개요**: CVE-2026-114625는 인증된 일반 사용자가 SQL 삽입으로 로컬 "슈퍼유저 운영자" 권한을 얻을 수 있는 결함이다. 공격에 필요한 조건은 기본 권한, VCO 웹 인터페이스 접근, 유효한 인증 세션뿐이며 사용자 개입(클릭 등)이 필요 없는 저난이도 공격이다. Arista는 공격이 진행 중이라고 밝히고 패치 버전과 임시 완화책(공격자 IP 차단, 관리망 제한, 접속 로그 점검)을 함께 공개했다.

**왜 일어났나**
- 직접 원인 [확인: Arista]: 웹 인터페이스의 입력값 검증 부족으로 SQL 삽입이 가능해, 인증된 일반 계정이 권한 상승 질의를 실행할 수 있었다. **공격자가 그 "인증된 일반 계정" 자체를 어떻게 처음 확보했는지는 공개되지 않았다** — 이번 사건의 결함(CVE-2026-114625)은 권한 상승 수단이며 최초 진입 수단이 아니다.
- 구조적 원인 [추정]: 네트워크 전체를 중앙에서 통제하는 관리 콘솔(오케스트레이터)은 공격 성공 시 보상이 크기 때문에 지속적으로 표적이 된다. 저난이도·무상호작용 결함일수록 자동화 스캐너로 빠르게 대량 악용되기 쉽다.

**침투 경로 [확인: Arista(권한 상승 부분만), 최초 진입은 미공개]**: (최초 접근 경로 비공개) → 인증된(낮은 권한) 세션으로 VCO 웹 인터페이스 접근 → SQL 삽입 질의 실행 → VCO 내부 "슈퍼유저 운영자" 역할 권한 획득. 획득 이후 행위(설정 변경, 터널 트래픽 열람 등)는 공개되지 않았다.

**어떻게 조치하나**
- 즉시: 증거(웹 접근 로그, 최근 관리자 활동 이력) 보존 후 패치. 공격자 IP 차단, 관리 웹 인터페이스를 관리망에서만 접근 가능하게 제한.
- 단기: 패치 전후 관리자 계정·설정 변경 이력 소급 점검, 침해 의심 시 Arista TAC에 연락.
- 장기: 네트워크 오케스트레이터 같은 단일 관리 콘솔은 외부 인터넷에 직접 노출하지 않고 전용 관리망·VPN을 통해서만 접근하도록 재설계.
- 탐지: 저권한 계정의 비정상적인 권한 상승 흔적, 알려진 공격자 IP로부터의 접속 시도.

**쉽게 말하면**: 소스코드 관리 도구 GitLab에서, 특정 형식으로 만든 정규표현식(패턴) 하나만 서버가 처리하게 만들면 로그인 없이도 서버에서 임의 코드를 실행시킬 수 있는, 벤더가 "최고 위험도(치명적)"로 분류한 결함이 발견돼 패치됐습니다. 아직 실제로 이용된 공격은 확인되지 않았습니다.

**먼저 할 일(초보용)**: GitLab을 직접 설치해 운영한다면(GitLab.com 이용자는 이미 자동 적용됨) 관리자가 지금 19.5.1·19.4.3·19.3.6·19.2.9·19.1.9·19.0.10·18.11.13 중 해당 버전으로 업데이트하도록 요청하세요.

**개요**: CVE-2026-110264는 설정 파일 속 정규표현식을 해석하는 내부 엔진(Regular Expression Compiler)의 정수 오버플로 결함으로, 특수하게 조작된 정규표현식을 컴파일할 때 인증 없이 서버에서 임의 코드를 실행시킬 수 있다. 연구자 'joaxcar'가 GitLab의 버그바운티(HackerOne)로 신고했다. GitLab.com은 이미 패치됐고, 자체 설치형(Self-managed) 사용자는 19.5.1 등으로 업데이트해야 한다. 보안업체 Shadowserver는 인터넷에 노출된 GitLab CE 인스턴스를 2,700개 이상 추적 중이다. **보도 시점까지 실제 악용 사례는 확인되지 않았다.**

**왜 일어났나**
- 직접 원인 [확인: GitLab]: 정규표현식을 처리하는 내부 컴파일러의 정수 오버플로로 메모리 처리가 어긋나 임의 코드 실행까지 이어질 수 있었다.
- 구조적 원인 [추정]: 사용자 입력(정규표현식 같은 패턴 문자열)을 해석하는 내부 엔진은 "그냥 문자열 처리"로 보이기 쉬워 외부 공격 표면으로 충분히 취급되지 않는 경우가 많다.

**침투 경로 [후보]**: 실제 악용이 확인되지 않아 이 보고서는 '후보'로만 매핑한다. 이론상: 인증 없이 조작된 정규표현식을 GitLab 서버가 처리하게 만드는 경로를 통한 악용이 가능하다고 벤더가 밝혔다.

**어떻게 조치하나**
- 즉시: 자체 설치형 GitLab을 19.5.1 등 패치 버전으로 업데이트. GitLab.com·GitLab Dedicated 이용자는 추가 조치 불필요.
- 단기: 인터넷에 노출된 GitLab 인스턴스가 있는지 확인(Shadowserver 등 외부 노출 자산 점검 활용).
- 장기: 입력값을 해석하는 내부 엔진(파서·컴파일러류)도 정기 보안 감사·퍼징 대상에 포함.
- 탐지: 해당 없음(실제 악용 미확인, 패치 적용이 핵심 대응).

**교훈**: 벤더가 매긴 "최고 위험도" 등급이 곧 "이미 악용되고 있다"는 뜻은 아니다. 다만 인증이 필요 없고 상호작용도 필요 없는 결함은 패치를 늦출수록 위험이 누적된다.

**금융권 연쇄 해킹([D20261006-finsector](../과거3년/2026.md)) 후속 — 가상자산거래소 등으로 조사·신고 대상 확대, 16개사·약 10만 건 집계**: 10/14 금융위원회 제2차 긴급 상황대응 회의에서 침해사고·접근시도가 확인돼 조사·신고 대상에 오른 금융사가 16곳으로 늘고 유출 규모가 약 10만 건으로 집계됐다고 밝혔다(개별 사건들이 같은 공격자의 연쇄 침해인지는 확인되지 않았다). 가상자산거래소 고팍스(운영사 스트리미)와 코인마켓거래소 프라뱅도 새로 포함됐는데, 고팍스는 다른 곳에서 유출된 것으로 추정되는 아이디·비밀번호 조합으로 고객 계정에 로그인을 시도한 흔적이 이상거래탐지시스템(FDS)에 포착돼 당국에 신고했다(로그인 성공·고객 자산 피해는 없다고 밝힘, 접근 경로 조사 중) — 이는 기존 사건들과 달리 서버 직접 침입이 아니라 **다른 서비스에서 유출된 계정정보로 로그인을 시도하는 방식(크리덴셜 스터핑)**이라는 점에서 공격 양상이 넓어졌음을 보여준다. 프라뱅은 이용자 20명의 개인정보(이름·성별·국적·생년월일·연락처·주소·직장 등 12개 항목)가 유출됐다고 확인했다. 금융당국이 555개 금융사를 긴급 점검한 결과 130곳에서 보안 패치 미적용 등 미흡사항이 발견됐고, 산은캐피탈(848명)·피에프씨테크놀로지스(302명) 등 개별 유출 사례도 추가 보도됐다. 이 건은 기존 사건의 규모·범위 갱신이라 새 사건으로 쓰지 않고 `국내뉴스.psv`에 기록했다.

**PHP2Shell([D20261022-php2shell](2026-10-22.md)) 국내 대응**: 과기정통부·KISA가 민간 분야 사이버위기 경보를 '주의' 단계로 올리고 기업용 PHP 취약점 대응 수칙을 배포했다. 금융보안원은 금융사에 웹 API 즉시 점검을 권고했고, 개인정보보호위원회는 이 결함으로 개인정보가 유출될 수 있다며 홈페이지 연계 DB의 접근권한 최소화를 당부했다. 새 사건이 아니라 기존 해외 사건의 국내 대응 후속이라 `국내뉴스.psv`에만 기록했다.

**국내 질의 결과**: 지침에 따라 ①금융권 ②통신·OTT·이커머스 ③공공·지자체·교육·의료 ④국내 랜섬웨어 ⑤정부 발표 ⑥기존 사건 규모 갱신, 총 6개 범주를 각각 검색했다. ①금융권은 위 가상자산거래소 확산·16개사 집계가 새로 확인됐다. ②통신·이커머스(쿠팡·티빙)는 10월 신규 사건을 찾지 못했고, 검색 결과는 모두 6~9월 티빙 유출 사건의 기존 보도였다. ③공공·지자체·교육·의료는 일반 WebSearch로는 10월 신규 사건을 찾지 못했으나, 보안뉴스(boannews.com) 기사 목록 직접 열람으로 **연세대([D20261023-yonsei](#d20261023-yonsei-연세대-학사-행정-포털-개인정보-유출-국내))·한국국제교류재단([D20261023-kfund](#d20261023-kfund-한국국제교류재단kf-메일시스템-침해-조사-국내))** 두 건을 새로 확인해 이번 보고서의 사건으로 등록했다(일반 WebSearch는 이번에도 10월 신규 공공·교육기관 사건을 찾지 못함 — boannews 직접 열람이 더 효과적이었다). ④국내 랜섬웨어 10월 통계는 공개되지 않았다(안랩 ASEC 최신 월간 보고서는 7월자, 이전과 동일). ⑤과기정통부·금융위·개인정보보호위 등의 10월 중 발표는 위 PHP2Shell 대응 수칙 배포·경보 격상 외에 추가로 확인하지 못했다. ⑥기존 사건 규모 갱신은 위 금융권 건이 해당한다.

## 5. 검증 수준과 한계

- CISA KEV는 JSON 피드를 직접 받아 10/20 등재분 이후 10/21~10/23 신규 등재가 없음을 확인했다(1차 출처).
- 해외 6건은 BleepingComputer 메인 페이지·개별 기사를 WebFetch로 직접 열람해 확인했다(일반 WebSearch는 이번에도 10/22~23 당일 소식을 거의 찾지 못함). BleepingComputer는 2차 보도이며, MS·Arista·GitLab·Capcom·Railway·LiteLLM 측 1차 발표 내용을 가능한 범위에서 교차 확인했으나 원문 공지를 전부 직접 열람하지는 못했다.
- Capcom·Railway·연세대·한국국제교류재단 4건은 **최초 침투 경로가 공개되지 않아** ATT&CK 매핑을 하지 않았다(분류 J에 준함).
- GitLab 건은 실제 악용이 확인되지 않아 매핑을 '후보'로만 두었다.
- 커넥트와이즈 건은 MS가 "스톰-0940이 한국 금융권을 공격했다"고 확정하지 않았으므로, 본 보고서도 한국 금융권과의 연관은 "아르텍스 도구의 과거 사용 이력 + 별도 조직(TAG-217) 추적 중"이라는 수준으로만 서술했다(동일 조직이라는 단정 아님).
- 한국국제교류재단 건은 "22만여 건"이 서버에 저장돼 있던 양이며 실제 유출 여부·범위는 재단도 아직 확정하지 않았다고 명시했다.
- **ATT&CK 버전이 v19.2 → v20.0으로 올라간 것을 attack.mitre.org에서 확인했다.** 이 저장소는 기존 매핑과의 일관성을 위해 당분간 v19.2 체계를 유지하며, 전술명·ID 변경 여부는 다음 작업에서 `ATTACK/_catalog.psv`·`build.mjs`의 TACTICS 갱신과 함께 검토해야 한다(오늘은 임의로 재매핑하지 않았다).
- 국내 질의 6개 범주 중 ②④는 10월 신규 사건을 찾지 못했으며, 이것이 "사건이 없다"는 뜻인지 "보도되지 않았다"는 뜻인지는 구분할 수 없다.
