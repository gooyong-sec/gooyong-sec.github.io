## 2. 이슈별 분석

### [D20261025-blackx] BlackX UEFI 부트킷 — 침해 후 지속성 도구, 2022년 "Baton Drop" 결함(CVE-2022-21894)으로 Secure Boot 우회, 중앙아시아 외교기관 스파이 활동
> 날짜: 2026년 초(스파이 활동 관측 시작, 정확한 최초 시점 비공개)~2026-10-23(Kaspersky 분석 공개) · 유형: 침해 후 UEFI 부트킷을 통한 Secure Boot 우회·지속성 확보(지정학적 첩보 목적 추정) · 행위자: 미귀속(Kaspersky가 중간 확신도로 APT41/Brass Typhoon/Wicked Panda/Barium으로 추정) · 지역: 글로벌(타지키스탄·우즈베키스탄·투르크메니스탄 외교기관 표적) · 근거: 확인(Kaspersky 분석)

**쉽게 말하면**: 공격자가 이미 어떤 방법으로든 기업망에 침투해 관리자 권한까지 확보한 뒤, 거기서 더 깊고 오래 숨어 있기 위해 컴퓨터가 켜질 때 윈도우보다 먼저 실행되는 "부팅 단계"에 몰래 끼어드는 악성코드(UEFI 부트킷) "BlackX"를 심는 사례가 발견됐습니다. 이 부트킷은 윈도우의 보안 기능인 Secure Boot(서명되지 않은 프로그램은 부팅 단계에서 실행하지 못하게 막는 기능)를, 2022년에 이미 알려진 낡은 결함("Baton Drop")을 이용해 우회합니다. 문제는 그 결함을 막는 조치(인증서 폐기)가 자동으로 적용되지 않고 관리자가 수동으로 한 단계를 더 처리해야 한다는 점인데, 이걸 하지 않은 "완전히 패치된" 윈도우 PC들도 그대로 당했습니다. 다만 이 부트킷이 보안 소프트웨어를 끄려고 시도한 기능은 Kaspersky 자체 분석에서 정작 Kaspersky 제품에는 효과가 없었던 것으로 확인됐습니다(다른 보안제품 대상 효과는 별도로 공개되지 않음). 중앙아시아 외교기관을 겨냥한 스파이(정보 수집) 활동에 실제로 쓰였습니다.

**먼저 할 일(초보용)**: 일반 개인 이용자가 당장 할 일은 없습니다(이 공격은 특정 외교기관을 겨냥한 표적형입니다). 회사·기관의 윈도우 PC를 관리한다면, 담당자에게 마이크로소프트의 "취약한 윈도우 부트매니저 인증서 폐기" 안내(Tech Community 블로그)를 지금 수동으로 적용했는지 확인해 달라고 요청하세요. Windows Update만으로는 이 폐기 절차가 자동 실행되지 않습니다.

**개요**: Kaspersky는 2026년 초 중앙아시아(타지키스탄·우즈베키스탄·투르크메니스탄) 외교기관을 표적으로 한 스파이 활동을 분석해 신종 UEFI 부트킷 "BlackX"를 공개했다(securelist.com, 10/23 보도 인용). 공격자는 **이미 해당 기관 망을 침해하고 관리자 권한을 확보한 뒤** BlackX를 설치했다고 Kaspersky는 밝혔다 — 즉 BlackX 자체가 최초 침입 수단은 아니고, 침해 이후 더 깊은 지속성을 확보하기 위한 도구다. BlackX는 2022년부터 알려진 부트킷 "BlackLotus"와 구조가 "놀랍도록 비슷"하며, BlackLotus의 공개 유출 소스코드에는 없지만 일부 BlackLotus 샘플에는 있던 코드가 BlackX에도 있어, 제작자가 BlackLotus를 역분석했거나 원본 소스코드를 입수한 것으로 보인다. BlackX는 "Baton Drop"(CVE-2022-21894)이라는 기존에 알려진 결함을 이용해 맞춤 MOK(Machine Owner Key, 기기 소유자 키)를 등록하고 임의의 EFI 파일을 불러와 Secure Boot를 우회한다. Kaspersky는 BlackX 피해자 전원이 "완전히 패치된" 윈도우를 쓰고 있었다고 밝혔는데, 이는 Baton Drop 패치가 취약한 "Windows Production PCA 2011" 인증서를 자동으로 폐기(차단)하지 않고, 관리자가 수동으로 폐기를 적용해야 하는 구조적 공백 때문이다(이 인증서는 보도 시점 기준 발급기관에 의해 폐기된 상태였으나, 공격 당시 폐기 여부·시점은 공개되지 않았다). 폐기된 인증서로 서명된 커널 드라이버가 보안 프로세스 비활성화·레지스트리 콜백·ETW(이벤트 추적) 변조를 시도하도록 설계됐지만, **Kaspersky는 동적 분석에서 이 기능이 자사 제품(Kaspersky)을 방해하는 데는 효과가 없었다고 밝혔다**(Avast 대상 결과는 보도에서 확인되지 않음). APT41(Brass Typhoon·Wicked Panda·Barium) 귀속은 Kaspersky가 **중간 확신도**로만 평가한 것이다.

**왜 일어났나**
- 직접 원인 [확인: Kaspersky]: 이미 관리자 권한을 확보한 공격자가 BlackX를 설치해, Baton Drop 취약점으로 맞춤 MOK를 등록·임의 EFI 파일을 로드함으로써 Secure Boot의 서명 검증을 우회하고 OS보다 낮은 단계에서 지속성을 확보했다. 함께 설치된 커널 드라이버는 보안 소프트웨어 방해·추적 기능 변조를 시도하도록 설계됐으나, 적어도 Kaspersky 제품을 상대로는 효과가 없었던 것으로 분석에서 확인됐다.
- 구조적 원인 [추정]: (1) 패치가 나와도 "자동 적용"이 아니라 관리자의 추가 조치(인증서 폐기)가 필요한 경우, 패치 적용률 통계만으로는 실제 보호 여부를 알 수 없다 (2) 부팅 단계 보안(UEFI·Secure Boot)은 운영체제보다 더 낮은 계층이라, OS용 백신·EDR이 여기까지 보지 못하는 경우가 많다 (3) 이미 몇 년 전 공개된 결함(Baton Drop, 2022년)이라도 수동 조치율이 낮으면 공격자에게는 여전히 "새 결함"처럼 쓸 수 있다. 이 분석이 실제 피해 기관의 미조치 이유와 일치하는지는 확인되지 않았다.

**침투 경로 [확인/일부: Kaspersky]**: (최초 네트워크 침입 경로는 이번 보도에서 공개되지 않음) → 공격자가 관리자 권한 확보 → BlackX 부트킷 설치, Baton Drop(CVE-2022-21894) 취약점으로 Secure Boot 우회(맞춤 MOK 등록, 임의 EFI 파일 로드) → 폐기된 인증서로 서명된 커널 드라이버 설치(보안 소프트웨어 방해·ETW 변조 시도, Kaspersky 제품 대상은 효과 없음 확인) → 사이드로드 DLL(OxiDLLRunner)이 셸코드·Rust 페이로드 실행 → RAT가 Google Drive·OneDrive·Yandex.Disk 같은 정상 클라우드 서비스를 명령·제어(C2) 통로로 사용(추가 플러그인을 내려받는 기능은 설계상 확인됐으나 실제 내려받기·실행이 관측됐는지는 보도에 명시되지 않음).

**어떻게 조치하나**
- 즉시: 윈도우 PC 환경에서 마이크로소프트가 안내한 취약 부트매니저 인증서("Windows Production PCA 2011") 폐기 절차를 공식 안내에 따라 수동으로 적용했는지 확인하고, 미적용 상태라면 지금 적용한다. 적용 후 부팅·복구 매체(복구 USB 등)와의 호환성도 함께 점검한다(해당 인증서를 차단 목록에 추가하는 것만으로는 복구 매체가 영향받을 수 있다).
- 단기: 외교·공공기관처럼 표적이 될 가능성이 높은 조직은 부팅 로그·펌웨어 변조 흔적(비표준 EFI 파일, 알려지지 않은 MOK 등록) 점검. BlackX는 침해 이후 도구이므로, 이미 망에 다른 침입 흔적이 있는지도 함께 조사한다.
- 장기: 패치의 "자동 적용"과 "수동 폐기 필요" 항목을 구분해 관리하는 패치 관리 체계 마련, 부팅 단계 보안(UEFI 측정 부팅, TPM 연동 점검)을 OS 수준 보안과 별도로 점검.
- 탐지: 비정상 MOK 등록, 알려지지 않은 서명 커널 드라이버 로드, 보안 프로세스가 특정 조건에서만 꺼지는 패턴, Google Drive·OneDrive·Yandex.Disk로의 비정상 트래픽.

**교훈**: "패치가 나왔다"와 "내 PC에 실제로 적용됐다"는 다른 문제다. 특히 관리자가 수동으로 한 단계를 더 눌러야 하는 패치는, 몇 년이 지나도 미적용 상태로 남아 있는 PC가 생긴다.

### [D20261025-phprce] PHP 세션 처리 결함(CVE-2026-115560) — PHP2Shell과 별개의 미패치 RCE, 특정 설정 조합에서만 작동
> 날짜: 2026-10-23(보안 공지 공개, 패치는 아직 없음) · 유형: 세션 핸들러 런타임 전환 처리 결함 → 원격 코드 실행(미패치) · 행위자: 해당 없음 · 지역: 글로벌 · 근거: 확인(PHP 보안팀 공지, 실제 악용 미확인)

**쉽게 말하면**: 웹사이트의 약 70%가 쓰는 프로그래밍 언어 PHP에서, [D20261022-php2shell](2026-10-22.md)(PHP2Shell)과는 별개인 새로운 원격 코드 실행 결함(CVE-2026-115560)이 발견됐습니다. 아직 수정판이 나오지 않았지만, PHP 보안팀은 "특이한 설정과 코드 조합"에서만 공격이 가능하다고 밝혔습니다. 즉 모든 PHP 사이트가 위험한 게 아니라, 특정 방식으로 세션을 다루는 일부 사이트만 해당됩니다.

**먼저 할 일(초보용)**: 일반 이용자가 당장 할 일은 없습니다. 자체 웹서버를 운영하는 개발자·관리자라면, 서버의 세션 설정 중 `session.upload_progress.enabled`를 지금 0으로 꺼 두는 것이 안전합니다(이 기능을 런타임에 끄고 켜는 코드를 쓰지 않는다면 끄는 데 문제가 없습니다).

**개요**: BleepingComputer(10/23)에 따르면 CVE-2026-115560은 PHP 세션 처리 결함으로, PHP 보안팀은 "설정과 애플리케이션 코드의 이례적인 조합"에서만 악용 가능하다고 밝혔다. 구체적으로, 설정 파일에서 `session.serialize_handler`를 `php_binary` 또는 `php_serialize`로 지정해 두고, 애플리케이션 코드가 `session_start()` 호출 전에 `ini_set()`으로 이 값을 `php`로 런타임 전환하면서도 세션 업로드 진행률(`session.upload_progress`) 기능은 계속 켜 둔 경우에만 문제가 생긴다. PHP 팀은 금요일(10/23) 공지로 이를 밝혔고, 패치는 아직 없으며(정규 릴리스 주기에 맞춰 다음 버전에서 공개 예정이라고 보도됨), 이 완화 조치는 PHP2Shell(CVE-2026-109618·109619) 패치가 나온 수요일(10/21)과 같은 시점에 함께 적용했어야 한다고 보도는 설명했다. VirusTotal 집계로 인터넷에 노출된 PHP 호스트는 510만 대 이상, 그중 약 380만 대는 공격 가능한 포트가 열려 있다고 보도됐으나, 이는 PHP 전체 노출 규모이며 이번 CVE의 실제 영향 대상(특정 설정 조합 사용 서버) 규모는 별도로 공개되지 않았다. **이 CVE에 대한 실제 악용 사례는 보도 시점까지 확인되지 않았다.**

**왜 일어났나**
- 직접 원인 [확인: PHP 보안팀]: 세션 직렬화 핸들러를 설정 시점과 런타임 시점에 다르게 지정하는 특정 코드 패턴이, 세션 업로드 진행률 기능과 결합할 때 메모리 처리 오류로 이어져 원격 코드 실행이 가능하다.
- 구조적 원인 [추정]: (1) 설정(ini)에서 정한 값과 코드가 런타임에 바꾸는 값이 일치하지 않는 조합은, 개발자가 "설정대로 동작한다"고 가정하기 쉬워 놓치는 경우가 많다 (2) 레거시 세션 기능(업로드 진행률 표시)처럼 오래되고 잘 쓰이지 않는 기능이 계속 기본값으로 남아 있으면, 그 기능을 잊고 있던 다른 코드 변경(런타임 핸들러 전환)과 뒤늦게 충돌할 수 있다.

**침투 경로 [후보]**: 실제 악용이 확인되지 않아 이 보고서는 '후보'로만 매핑한다. 이론상: 공격자가 위 설정 조합(세션 직렬화 핸들러 런타임 전환 + 업로드 진행률 활성화)을 쓰는 서버를 찾아 조작된 세션 업로드 요청을 보내면 메모리 처리 오류로 코드 실행이 가능하다고 벤더가 설명했다.

**어떻게 조치하나**
- 즉시: 애플리케이션 코드가 세션 시작 전 `ini_set()`으로 `session.serialize_handler`를 런타임에 바꾸는지 점검하고, 해당한다면 실제 요청을 처리하는 모든 PHP 환경에 `session.upload_progress.enabled=0`을 적용한 뒤 설정 반영 여부(프로세스·PHP-FPM 재시작 등)를 확인한다. 이 기능을 쓰지 않는 서버는 이번 건의 영향을 받지 않는다고 PHP 팀은 밝혔다.
- 단기: PHP의 다음 정규 릴리스에서 정식 패치가 나오는지 확인하고 공개 즉시 적용. PHP2Shell(CVE-2026-109618·109619) 패치 적용 여부도 함께 재확인.
- 장기: 세션 관련 설정값을 ini 파일과 런타임 코드 양쪽에서 동시에 바꾸는 패턴을 코드 리뷰 체크리스트에 포함.
- 탐지: 해당 없음(실제 악용 미확인, 완화 조치 적용이 핵심 대응).

**교훈**: "패치가 없다"는 "할 수 있는 일이 없다"는 뜻이 아니다. 벤더가 구체적인 설정 조건을 공개하면, 그 조건에 해당하는지만 확인해도 위험을 크게 줄일 수 있다.

- 탐지: 해당 없음(실제 악용 미확인, 이미 연구자가 업데이트 기능을 선제적으로 비활성화한 사건).

**교훈**: 공격의 "목적"이 개인정보 탈취가 아니었어도(이번엔 채굴이 목적) 같은 공간에 보관된 개인정보는 함께 노출된다. 더는 쓰지 않는 데이터를 치우지 않는 것도 유출 규모를 키우는 원인이 된다.

## 3. 국내 소식

**국내 질의 결과**: 지침에 따라 ①금융권 ②통신·OTT·이커머스 ③공공·지자체·교육·의료 ④국내 랜섬웨어 ⑤정부 발표 ⑥기존 사건 규모 갱신, 총 6개 범주를 각각 검색했다. ①금융권은 10/19 국감 이후 10/24~25 사이의 새로운 당국 발표나 추가 피해 기관을 찾지 못했다(가장 최근은 [10-24 보고서](2026-10-24.md)에 기록된 10/19 금감원 국감 내용과 동일). ②통신·이커머스(쿠팡·티빙·통신 3사)는 10월 신규 침해사고를 찾지 못했고, 검색 결과는 9월 발표된 티빙 사건(3,954만 계정, 민관합동조사단 최종 집계)과 10/6 국정감사 소환 관련 기존 보도의 재인용이었다. ③공공·지자체·교육·의료는 일반 WebSearch로 10월 24~25일 신규 공공·교육기관 사건을 찾지 못했으나, **할리스 커피(식음료 프랜차이즈) 멤버십 해킹**을 새로 확인해 이번 보고서의 사건으로 등록했다(10/16 인지·10/19 공식 입장, 276만 건 유출). ④국내 랜섬웨어 10월 전국 통계는 공개되지 않았다(안랩 ASEC 최신 월간 보고서는 7월자로 변동 없음). ⑤과기정통부·금융위·개인정보보호위원회·금융감독원의 10월 24~25일 신규 발표는 확인하지 못했다. ⑥기존 사건 규모 갱신은 이번 조사에서는 확인되지 않았다(금융권·티빙 사건 모두 10/19~9월 집계 이후 추가 갱신 보도를 찾지 못했다).

할리스 사건은 유출 규모(약 276만 건)와 비밀번호를 포함한 유출 항목이 분명해 이번 보고서의 사건(D20261025-hollys)으로 등록했고, `국내뉴스.psv`에는 별도로 적지 않았다(이미 사건으로 다뤘으므로 중복 기재하지 않음).

## 4. 우선 대응 체크리스트

1. **윈도우 PC 다수 운영 기관(특히 외교·공공·연구기관)**: 마이크로소프트의 취약 부트매니저 인증서("Windows Production PCA 2011") 폐기 절차를 수동으로 적용했는지 지금 확인.
2. **PHP 개발자·서버 관리자**: 세션 직렬화 핸들러를 런타임에 바꾸는 코드가 있는지 점검하고, 해당하면 `session.upload_progress.enabled=0` 즉시 적용.
3. **Time4Popcorn 등 관리 중단 Popcorn Time 계열 앱 사용자**: 지금 완전 삭제(윈도·맥·안드로이드 모두).
4. **할리스 멤버십 이용자(2020년 2월 이전 가입)**: 할리스 비밀번호 변경, 동일 비밀번호를 쓰는 다른 서비스도 변경.
5. [10-17](2026-10-17.md)~[10-24](2026-10-24.md) 보고서의 Ivanti·Atlassian·Ahsay·PAN-OS·Cisco SEG·BeyondTrust·Fortinet·SiteGuard·Plex·Siemens·PHP(PHP2Shell)·SafePay·UpdraftCentral·eMudhra·Onamae·커넥트와이즈·Arista VCO·LiteLLM·GitLab·Collabora·HPE ArubaOS·Node.js/Bun — 기한이 지났거나 임박한 건이 많으므로 미조치 상태라면 우선 처리.

## 5. 검증 수준과 한계

- CISA KEV는 JSON 피드를 직접 받아 10/23 등재분 이후 10/24~25 신규 등재가 없음을 확인했다(1차 출처, 피드가 매우 커 전체를 한 번에 읽지는 못했고 날짜순 최신 구간을 확인했다).
- BlackX·PHP·Time4Popcorn 3건은 BleepingComputer 기사를 WebFetch로 직접 열람해 확인했다(2차 보도). BlackX는 Kaspersky의 원문 분석(securelist.com)도 WebFetch로 직접 열람해 보도 내용을 교차 확인했다(1차 출처 확인 과정에서 보안 소프트웨어 무력화 실패·침해 후 설치라는 점을 추가로 확인해 본문에 반영). PHP 보안팀·Eye Security의 원문 공지·분석 페이지는 직접 열람하지 못하고 보도 인용으로만 확인했다.
- BlackX는 공격자가 이미 관리자 권한을 확보한 뒤 설치한 침해 후 도구로, 최초 네트워크 침입 경로는 보도에서 공개되지 않아 ATT&CK 매핑에서 초기 접근(Initial Access) 전술은 제외했다. APT41 귀속은 Kaspersky가 "중간 확신도"로 밝힌 것으로 확정적이지 않다. 보안 소프트웨어 비활성화 시도는 Kaspersky 자체 분석에서 Kaspersky 제품에는 효과가 없었던 것으로 확인됐고, 사이드로드 DLL의 추가 플러그인 내려받기도 설계상 확인됐을 뿐 실제 사용 여부는 보도에 명시되지 않았다(T1105은 '추정'으로 하향).
- 할리스 건은 "가상화폐 채굴 목적 클라우드 비정상 접근"이라는 목적·결과만 공개됐고 구체적 침투 경로(계정 탈취·설정 오류·취약점 등)가 공개되지 않아 ATT&CK 매핑을 하지 않았다(분류 J에 준함).
- 국내 질의 중 ①⑥(금융권 신규 발표·기존 사건 규모 갱신)은 10/19 국감 이후 새로운 자료를 찾지 못했으며, 이것이 "추가 집계가 없다"는 뜻인지 "아직 보도되지 않았다"는 뜻인지는 구분할 수 없다.
- ②(쿠팡·티빙·통신 3사)와 ③(공공·교육)의 보안뉴스(boannews.com) 등 전문 매체 기사 목록 직접 열람은 이번 조사에서 WebSearch로 대체했고, 지난 보고서들처럼 사이트를 직접 열람하지는 못했다. 전문 매체 직접 열람이 가능했다면 추가 국내 사건이 더 확인됐을 가능성이 있다.
