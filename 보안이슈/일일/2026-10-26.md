## 2. 이슈별 분석

### [D20261026-agentsmd] AI 코딩 에이전트(Claude Code·Codex 등) 하이재킹 — Downloads 폴더의 악성 AGENTS.md·CLAUDE.md 지침 파일을 에이전트가 그대로 신뢰
> 날짜: 발견 시점 비공개(연구사 보고서는 보도 주간 내 공개)·2026-10-25(BleepingComputer 보도) · 유형: AI 코딩 에이전트가 작업 디렉터리의 지침 파일(AGENTS.md·CLAUDE.md)을 자동으로 읽고 그 지시에 따라 명령 실행을 시도해 악성 패키지 설치·OAuth 토큰 노출로 이어질 수 있는 설계상 신뢰 경계 문제 · 행위자: 미귀속(실제 공격자 불명, 연구는 보안기업 Forever Security) · 지역: 글로벌 · 근거: 확인(Forever Security가 관측했다고 보고, 고객 PC에서 설치 시도 1건)

**쉽게 말하면**: 최근 개발자들이 많이 쓰는 "AI 코딩 에이전트"(OpenAI Codex, Anthropic Claude Code 등)는 작업을 시작할 폴더에 `AGENTS.md`나 `CLAUDE.md`라는 이름의 "안내 파일"이 있으면 그 내용을 사람의 지시만큼 신뢰하고 그대로 따릅니다. 보안회사 Forever Security는, 누군가의 PC에서 이 안내 파일이 몰래 다운로드 폴더(Downloads)에 들어가 있었고, 그 폴더에서 에이전트를 실행했더니 안내 파일의 지시에 따라 악성 프로그램(npm 패키지)을 설치하려 한 사례를 실제로 발견했습니다. 더 나아가 연구진은, 이런 방식으로 Claude Code의 통신을 공격자 서버로 몰래 우회시켜 로그인 정보(OAuth 토큰)를 빼낼 수 있다는 것도 실험으로 보여줬습니다(이건 아직 실제 공격 사례는 아니고 연구 시범입니다). OpenAI와 Anthropic은 이걸 "고쳐야 할 결함"이 아니라 "에이전트가 설계대로 동작한 것"이라는 입장이어서, 패치로 해결되지 않고 사용자가 사용 습관을 바꿔야 하는 문제입니다.

**먼저 할 일(초보용)**: AI 코딩 에이전트(Claude Code, Codex, Cursor 등)를 쓰고 있다면, 지금부터는 다운로드 폴더(Downloads)나 홈 폴더처럼 넓은 범위가 아니라, 실제 작업할 프로젝트 폴더 안에서만 실행하세요. 낯선 `AGENTS.md`·`CLAUDE.md` 파일이 작업 폴더에 보이면 내용을 먼저 열어서 확인하고, 이상한 지시(패키지 설치, 외부 서버 접속 등)가 있으면 그 폴더에서 에이전트를 실행하지 마세요.

**개요**: BleepingComputer(10/25) 보도에 따르면, AI 에이전트 위험을 연구하는 보안기업 Forever Security(연구원 Gal Weizman 등)는 고객 PC에서 악성 `AGENTS.md` 파일이 `~/Downloads` 폴더에 들어 있고, 이 폴더가 코딩 에이전트의 작업 디렉터리로 쓰이고 있던 사례를 발견했다. 코딩 에이전트는 작업 디렉터리에 있는 `AGENTS.md`·`CLAUDE.md` 같은 지침 파일을 시작할 때 자동으로 읽고 따르도록 설계돼 있는데, 이 사례에서는 그 지침에 따라 악성 npm 패키지 **`function-color`** 설치가 시도된 것이 확인됐다. 이 파일이 애초에 어떻게 Downloads 폴더에 들어갔는지는 확인되지 않았으며, 연구진은 "웹페이지가 방문자 몰래 Downloads에 이런 파일을 내려받게 만들 수 있다"고 주장했을 뿐 이번 사례의 실제 유입 경로는 밝혀지지 않았다. 연구진은 OpenAI Codex와 Claude Code를 대상으로 자체 PoC 실험에서 재현에 성공했다고 보고했다(Codex는 무해한 계산기 앱 실행 페이로드로 90% 성공). Claude Code의 경우, 악성 `CLAUDE.md`로 API 트래픽을 공격자 서버로 우회시켜 OAuth 토큰(앱이 서버에 접속할 때 쓰는 인증 정보)을 노출시키고 공격자가 모델을 사칭해 도구 호출(코드 실행)을 반환하는 시나리오를, 연구진의 해당 PoC 실험에서 약 50% 확률로 성공시켰다고 보고했다. **이 토큰 탈취 시나리오는 연구 시연이며, 실제 공격에서 관측된 사례는 아니다.** Forever Security 내부 통계로는 Downloads 폴더에서 Claude Code·Codex·Cursor CLI 등을 실행한 고객이 수백 명이고, Claude Code만 해당 위치에서 1,300회 이상 세션이 열렸다고 한다. **OpenAI와 Anthropic 양사는 연구진에게 "패치할 결함이 아니라 설계된 동작"이라는 입장을 밝혔고**(기사에 두 회사의 별도 공식 성명은 인용되지 않음), 에이전트를 프로젝트 디렉터리에서 실행하라고 권고한다고 보도됐다.

**왜 일어났나**
- 직접 원인 [확인: Forever Security]: AI 코딩 에이전트가 작업 디렉터리에 있는 지침 파일(AGENTS.md·CLAUDE.md)의 내용을 사람의 지시와 동등하게 신뢰하고 자동으로 따르도록 설계돼 있어, 그 폴더에 악성 지침 파일이 놓이면(유입 경로는 이번 사례에서 불명) 에이전트가 이를 그대로 수행한다.
- 구조적 원인 [추정]: (1) "지침 파일을 작업 디렉터리에서 자동으로 읽는다"는 편의 기능은, 그 디렉터리에 누가 무엇을 놓을 수 있는지에 대한 신뢰 경계를 따로 두지 않는다 (2) Downloads 폴더는 브라우저·설치 프로그램 등 다양한 경로로 외부 콘텐츠가 들어오는 "신뢰도가 낮은" 위치인데도, 사용자들이 편의상 그 폴더에서 바로 에이전트를 실행하는 습관이 있다(Forever Security 집계로 수백 명·1,300여 세션) (3) 벤더가 "설계된 동작"이라고 보는 이상, 이 문제는 패치가 아니라 사용자 행동(실행 위치 제한)으로만 줄일 수 있다.

**침투 경로 [확인·일부 후보]**: (파일이 Downloads 폴더에 들어간 경로는 이번 사례에서 확인되지 않음 — Downloads는 노출 조건일 뿐이고, 연구진이 주장한 "웹페이지가 몰래 저장" 가능성은 가설이며 실제 유입 원인으로 확인된 것은 아님 → [후보]) → 사용자가 Downloads 폴더(또는 악성 파일이 있는 폴더)를 작업 디렉터리로 지정해 AI 코딩 에이전트 실행 → 에이전트가 그 폴더의 AGENTS.md·CLAUDE.md를 자동으로 읽고 지침으로 신뢰 [확인] → 지침에 따라 악성 npm 패키지(`function-color`) 설치 명령 실행을 시도 [확인, Forever Security가 관측했다고 보고] / 또는 API 트래픽을 공격자 서버로 우회시켜 OAuth 토큰 노출 후 공격자가 모델을 사칭해 코드 실행 [연구 PoC, 별도 실험이며 이번 실제 사건에 적용됐다는 근거는 없음].

**어떻게 조치하나**
- 즉시: AI 코딩 에이전트를 Downloads·홈 디렉터리처럼 넓은 폴더가 아니라 신뢰할 수 있는 프로젝트 루트 폴더에서만 실행하도록 습관·정책을 바꾼다(프로젝트 루트라고 무조건 안전한 것은 아니며, 에이전트가 함께 읽는 상위·전역 설정·지침 파일까지 점검해야 한다). 처음 보는 AGENTS.md·CLAUDE.md 파일은 에이전트를 실행하기 전에 내용을 먼저 읽고 검토한다.
- 단기: 에이전트의 승인 프롬프트(명령 실행 전 확인)와 샌드박스·격리 실행 기능을 켜 두고 임의로 우회·비활성화하지 않는다. 조직 차원에서는 개발자 PC의 에이전트 실행 디렉터리와 상위·전역 설정 파일을 조사해 Downloads·홈 폴더에서 실행된 이력이 있는지, 지침 파일이 변조됐는지 점검한다. 이미 Downloads 등 넓은 폴더에서 에이전트를 돌린 적이 있다면 해당 에이전트가 쓰던 OAuth 토큰·API 키를 폐기하고 재인증하며, 의도치 않은 패키지가 설치됐는지 확인한다.
- 장기: AI 코딩 에이전트 도입 가이드라인에 "지침 파일은 작업 디렉터리 안의 콘텐츠이므로 그 디렉터리(와 상위 경로)의 출처를 신뢰할 수 있어야 한다"는 원칙을 포함한다. 신뢰할 수 없는 코드·저장소는 격리된 환경(컨테이너 등)에서 먼저 테스트한다.
- 탐지: 에이전트가 설치를 시도하는 패키지명이 평소 프로젝트의 의존성 목록에 없는 경우, 에이전트 프로세스가 평소와 다른 외부 서버로 API 트래픽을 보내거나 API 목적지(엔드포인트) 설정이 바뀐 경우.

**교훈**: AI 에이전트에게 "작업 폴더 안의 문서는 믿을 만하다"는 가정은, 그 폴더가 사람이 신중하게 고른 프로젝트가 아니라 브라우저가 아무거나 받아 두는 Downloads 폴더일 때는 깨진다. 벤더가 "설계된 동작"이라고 선을 그은 문제는, 패치를 기다리지 말고 사용자가 먼저 실행 위치를 바꿔야 한다.

### 참고 기록 — PHP2Shell: AI가 발견했고, 3개국 정부가 선제적으로 웹사이트를 내렸다

[D20261022-php2shell](2026-10-22.md) 결함(CVE-2026-109618·109619)에 대한 추가 사실이 decrypt.co(AP 통신 재배급, 10/21)를 통해 확인됐다. OpenAI는 자사 AI 모델(GPT-5.6 "Sol")이 이 결함을 찾아내는 데 핵심적인 역할을 했다고 밝혔다 — 보안업체 Calif가 8월에 1차 버전을, OpenAI 팀이 9월에 더 완전한 버전을 GPT-5.6으로 찾았고, 클라우드 보안업체 Wiz도 독립적으로 두 결함을 모두 발견했다. OpenAI의 Greg Brockman은 "Patch the Planet" 이니셔티브 아래 두 달간 대응 연합을 이끌었다고 밝혔다(해당 결함은 PHP에 14년간 존재했고 2024년에 제한된 형태가 한 차례 나왔으나 당시엔 중대하게 평가되지 않았다고 보도됐다). 패치 세부 내용이 조기 유출되자 PHP 유지관리팀은 원래 목표였던 10/22보다 하루 앞당긴 **10/21**에 패치를 공개했다. 핀란드·네덜란드·프랑스 정부는 패치 공개 당일(수요일) 자국 정부 웹사이트 일부를 선제적으로 오프라인 전환했다고 보도됐다 — 누구든 PHP 서버에서 임의 코드를 실행할 수 있는 결함이었기 때문이다. **이 기사에서도 실제 악용(ITW) 사례는 보고되지 않았다.** 기존 매핑(TA0001|T1190|확인)과 분류(A)는 그대로 유지하며 별도 사건으로 분리하지 않는다. "AI가 취약점을 찾아 수정 연합을 이끈" 보기 드문 사례로 기록해 둔다.

## 3. 국내 소식

**국내 질의 결과**: 지침에 따라 ①금융권 ②통신·OTT·이커머스 ③공공·지자체·교육·의료 ④국내 랜섬웨어 ⑤정부 발표 ⑥기존 사건 규모 갱신, 총 6개 범주를 각각 검색했다(검색어에 "2026년 10월" 포함). ①금융권(검색어: "2026년 10월 금융권 해킹 개인정보 유출 은행 카드 저축은행")은 10/19 국감 이후 새로운 당국 발표·추가 피해 기관을 찾지 못했다 — 가장 최근 수치는 [10-23 보고서](2026-10-23.md)에 기록된 16개사·약 10만 건(10/14 집계)과 동일했다. ②통신·이커머스(검색어: "2026년 10월 쿠팡 티빙 통신사 침해사고 개인정보 유출")는 10월 신규 침해사고를 찾지 못했고, 결과는 모두 기존 티빙 사건(민관합동조사단 최종 집계 3,954만 계정)의 재인용·국정감사 후속 보도였다. ③공공·지자체·교육·의료(검색어: "2026년 10월 공공기관 대학 의료기관 개인정보 유출 해킹")는 10월 신규 사건을 찾지 못했고, 검색된 것은 모두 과거 사건(2026-01 해킹포럼 탈취, 2026-07 국립외교원 해킹, 2024년 전북대 사건 등)의 재인용이었다. ④국내 랜섬웨어(검색어: "2026년 10월 국내 랜섬웨어 피해")는 결과가 없었다 — 검색 결과는 전부 해외(미국·글로벌) 통계였다. ⑤정부 발표(검색어: "과기정통부 KISA 개인정보보호위원회 금융위 금감원 2026년 10월 발표 제재")는 10/24~26 구간의 신규 발표를 찾지 못했으나, 10/13 국정감사에서 **개인정보보호위원회 송경희 위원장**이 금융권·공공기관 유출 사고에 매출 최대 10% 과징금과 조사 비협조 시 이행강제금을 적용하고, 대규모 유출엔 전담 조사단을 꾸리겠다고 밝힌 발언을 새로 확인해 `국내뉴스.psv`에 기록했다(아직 법안·시행 여부가 아니라 국감 발언 단계임을 유의). ⑥기존 사건 규모 갱신(검색어: "금융권 해킹 16개사 10만건 추가 집계 10월 24일 25일 26일")은 10/24~26 구간의 추가 갱신 보도를 찾지 못했다.

오늘 조사에서는 사건으로 등록할 만큼 크고 새로운 국내 사건은 확인되지 않았다(어제 할리스 커피 멤버십 해킹이 이미 등록됨).

## 4. 우선 대응 체크리스트

1. **AI 코딩 에이전트(Claude Code·Codex·Cursor 등) 사용자·개발팀**: 에이전트를 Downloads·홈 폴더가 아니라 프로젝트 루트 폴더에서만 실행하도록 지금 점검·변경.
2. **PHP 운영 조직**: [D20261022-php2shell](2026-10-22.md) 패치(10/21 공개) 적용 여부 재확인 — 국내 패치율이 낮았던 전례([10-24 보고서](2026-10-24.md) 3.8%)가 있다.
3. [10-17](2026-10-17.md)~[10-25](2026-10-25.md) 보고서의 Ivanti·Atlassian·Ahsay·PAN-OS·Cisco SEG·BeyondTrust·Fortinet·SiteGuard·Plex·Siemens·PHP(PHP2Shell)·SafePay·UpdraftCentral·eMudhra·Onamae·커넥트와이즈·Arista VCO·LiteLLM·GitLab·Collabora·HPE ArubaOS·Node.js/Bun·Time4Popcorn — 기한이 지났거나 임박한 건이 많으므로 미조치 상태라면 우선 처리.

## 5. 검증 수준과 한계

- CISA KEV는 JSON 피드를 직접 받아 10/23 등재분 이후 10/24~26 신규 등재가 없음을 확인했다(1차 출처, 피드가 매우 커 날짜순 최신 구간만 확인했다).
- AGENTS.md/CLAUDE.md 하이재킹은 BleepingComputer 기사(2차 보도, 연구사 인터뷰 기반)를 WebFetch로 직접 열람해 확인했다. Forever Security의 원문 보고서는 직접 열람하지 못했다. 이 사건은 ATT&CK Enterprise 매트릭스가 원래 사람이 조직 내부망에서 공격받는 상황을 전제로 만들어져, "AI 에이전트가 로컬 지침 파일을 자동으로 따르는" 이번 공격 방식과 완전히 일치하는 공식 기법이 없다. 아래 매핑은 가장 가까운 기법에 대한 유비이며, 공식 사이트(attack.mitre.org)에서 재확인했다.
  - T1204.002(악성 파일, User Execution)는 원래 "사람"이 파일을 열어 실행하는 상황을 가리킨다. 에이전트가 지침에 따라 설치 명령 실행을 시도한 행위 자체는 실제 관측됐지만, 이를 T1204.002로 대응시키는 것은 분석상의 유비이지 공식 기법 정의와의 일치가 아니므로 — 행위 관측과 매핑 확신을 분리해 — 근거를 후보로 표기했다(Codex 검토에서 "확인"은 과도하다는 지적을 반영해 하향).
  - T1189(드라이브 바이 컴프로마이즈)는 "웹페이지가 Downloads에 몰래 파일을 저장"한다는 연구진의 가설적 주장일 뿐, 이번 실제 사례의 유입 경로는 확인되지 않아 후보로만 표기했다(Downloads 폴더라는 점은 노출 조건이지 확인된 유입 원인이 아니다).
  - T1528(앱 접속 토큰 훔치기)은 Claude Code OAuth 토큰 탈취가 연구진의 별도 PoC 실험(약 50% 성공률)으로만 시연됐고, 이번 실제 관측 사건(npm 패키지 설치 시도)에 이 기법이 적용됐다는 근거는 없어 후보로 표기했다.
- PHP2Shell 후속 보강 내용은 decrypt.co(AP 통신 재배급) 1건만 WebFetch로 확인했고, OpenAI·PHP 유지관리팀의 원문 발표는 직접 열람하지 못했다. CVE 번호는 이 기사에 나오지 않아 기존 저장소 기록([D20261022-php2shell](2026-10-22.md))을 그대로 따랐다.
- 국내 질의 중 ①②③④⑥은 WebSearch만으로 수행했고(보안뉴스 등 전문 매체 직접 열람은 이번 조사에서 하지 못함), 결과 없음이 "사건이 실제로 없다"는 뜻인지 "아직 보도되지 않았다"는 뜻인지는 구분할 수 없다.
- 해외 랜섬웨어·대형 유출 일반 검색에서는 10월 24~26일 날짜로 특정되는 새로운 대형 사건을 추가로 찾지 못했다(검토했으나 채택하지 않음: 날짜·근거가 불충분한 보도 몇 건).
