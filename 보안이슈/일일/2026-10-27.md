### [D20261027-copenhagen] 코펜하겐대학교(덴마크) 테스트 환경 해킹 — 학생·교직원 약 54만5천 명 정보 노출
> 날짜: 발견·공개 정확한 날짜는 비공개(보도 기준 '지난 화요일' 발견, '금요일' 1차 공개, 그다음 날 추가 공개)·2026-10-26(BleepingComputer 보도) · 유형: 테스트 환경 무단 접근(초기 침투 경로 비공개) · 행위자: 미귀속 · 지역: 덴마크(해외) · 근거: 확인(코펜하겐대학교 공지, 보도)

**쉽게 말하면**: 덴마크 코펜하겐대학교가 쓰던 "테스트용" 시스템에 공격자가 들어가, 학생·교직원 등 약 54만5천 명의 이름, 덴마크의 주민등록번호 성격인 CPR 번호, 전화번호, 이메일이 노출됐을 수 있다는 사실이 확인됐습니다. 이 중 약 2만 명은 건물 출입에 쓰는 PIN 코드까지 노출돼, 대학은 일부 건물 출입을 임시로 제한했습니다. 공격자가 애초에 어떻게 들어왔는지는 아직 공개되지 않았습니다.

**먼저 할 일(초보용)**: 코펜하겐대학교 재학생·교직원이라면 대학의 공식 공지로 본인 정보가 포함됐는지 확인하고, 안내받은 대로 출입 PIN 코드를 새로 발급받으세요(아직 안내받지 못했다면 공식 채널로 직접 확인). 대학을 사칭해 개인정보나 비밀번호를 요구하는 메일·문자에는 응답하지 말고 공식 공지로만 확인하세요.

**개요**: BleepingComputer(10/26) 보도에 따르면, 코펜하겐대학교는 자사의 한 "테스트 환경"(test environment)에 공격자가 접근했다고 확인했다. 이 환경에는 학생·교직원 등 약 52만5천 명의 개인정보(이름, CPR 번호, 전화번호, 이메일)가 들어 있었는데, 다음 날 대학은 추가로 약 2만 명의 출입용 PIN 코드도 노출됐을 가능성이 있다고 밝혔다. 보도는 두 수치를 더해 전체 영향 범위를 약 54만5천 명으로 밝혔으나, **두 집단이 서로 겹치는지는 보도에 명시되지 않았다.** 대학은 공격을 봉쇄하고 공격자의 접근을 차단했다고 밝혔으며, 평소 업무를 지원하는 핵심 시스템까지 공격자가 도달했거나 대학 운영이 중단된 흔적은 없다고 설명했다. 예방 조치로 일부 핵심 건물의 물리적 출입을 제한했고, 새 출입 코드를 배포하며 순차적으로 재개방하고 있다. 대학은 이 사건을 덴마크 개인정보보호청(Datatilsynet)에 신고했으며 GDPR 적용 대상이라고 밝혔다. **공격자가 테스트 환경에 처음 접근한 경로(초기 침투 방법)는 보도 시점까지 공개되지 않았다.** 공격자 귀속도 밝혀지지 않았다. PIN 코드가 노출됐다는 사실 자체는 "노출된 PIN으로 무단 출입이 가능해졌다"는 위험을 뜻하며, 실제 무단 출입이 일어났다는 증거는 보도에 없다.

**왜 일어났나**
- 직접 원인 [비공개]: 공격자가 테스트 환경에 접근한 구체적인 방법(취약점, 탈취한 인증정보 등)이 대학 공지·보도에서 밝혀지지 않았다.
- 구조적 원인 [추정 — 확인된 사실이 아니라 일반적인 위험 가설]: (1) "테스트 환경"이라는 이름 때문에 실제 운영 시스템보다 접근 통제·모니터링 수준이 낮게 설정되는 경우가 흔히 있는데, 그런 환경에 실제 개인정보(또는 그에 준하는 데이터)가 그대로 들어 있다면 노출 시 피해가 운영 시스템 수준으로 커질 수 있다(이번 사건에서 실제로 그런 통제 격차가 있었는지는 공개되지 않았다) (2) 물리적 출입 PIN이 같은 개인정보와 함께 노출됐다는 사실은, IT 시스템 침해가 건물 출입 보안 문제로 번질 수 있음을 보여준다(이 사건에서 PIN이 테스트 환경과 같은 시스템·데이터베이스에 있었는지는 공개되지 않았다).

**침투 경로 [비공개]**: 초기 침투 방법이 공개되지 않아 이 보고서는 매핑하지 않는다. 확인된 것은 "테스트 환경"이 공격 대상이 됐고, 그 안의 개인정보(및 일부 출입 PIN)가 노출됐다는 사실뿐이다.

**어떻게 조치하나**
- 즉시: (대학이 공개한 바로는 이미 수행) 공격자 접근 차단, 영향 범위 확정을 위한 내부 조사. (본 보고서의 권고) 로그 등 증거를 신속히 보존하고, 노출된 PIN은 폐기 후 전면 재발급하며(이미 진행 중이라고 밝힘) 해당 PIN으로 이뤄진 과거 출입 기록을 점검한다.
- 단기: 영향받은 개인별 통지 완료, 피싱·사칭 시도 모니터링 안내.
- 장기: 테스트·비운영 환경에 실제 개인정보를 두지 않도록 데이터 거버넌스(가명처리·마스킹 또는 합성 데이터 사용)를 정비하고, 테스트 환경에도 운영 환경과 동등한 접근 통제·로깅을 적용.
- 탐지: 테스트·비운영 환경에 대한 비정상 접근은 운영 환경보다 모니터링 수준이 낮아 놓치기 쉬우므로, 테스트 환경도 동일한 이상 접근 탐지 체계에 포함.

**교훈**: "테스트 환경"이라는 이름이 "덜 중요한 데이터"를 뜻하지는 않는다. 실제 개인정보가 들어가는 순간 그 환경은 운영 시스템과 같은 수준의 보호가 필요하다.

### 참고 기록 — PHP2Shell, 패치 5일 만에 "가장 신뢰할 만한" 실제 악용(RCE) 확인 + 패치 없는 새 결함 추가 공개

[D20261022-php2shell](2026-10-22.md) 사건(CVE-2026-109618·109619)에 중요한 후속 사실이 BleepingComputer(10/26)를 통해 확인됐다. Perplexity의 탐지·대응 리드 Adel Karimi가 허니팟(공격을 유인하기 위한 가짜 시스템) 데이터에서 Apache mod_php(PHP 8.4.26) 대상 실제 원격 코드 실행(RCE) 흔적을 발견했고, Expel의 위협 연구자 Marcus Hutchins는 이를 "지금까지 본 PHP2Shell 실제 악용 중 가장 신뢰할 만한 확인"이라고 평가했다. 공격자는 공개된 PoC의 오프셋을 활용해 약 800KiB 분량의 쿠키(메모리 일부)를 빼낸 뒤, 그 안에서 함수 주소를 추출해 후속 실행 명령에 사용한 것으로 분석됐다. **Karimi 본인은 이 확인이 공격에 유리한 "단일 워커(single-worker)" 구성에서 나온 것이라, 다른 서버 구성에서도 같은 성공률을 보장하지는 않는다고 밝혔다.** 아마존 위협 인텔리전스에 따르면 패치(10/21) 약 나흘 전부터 표적 공격이 시작됐다. CISA는 탐지용 SIGMA 규칙을 배포했는데, **본 보고서가 CISA KEV JSON 피드를 직접 확인한 결과 10/26 CVE-2026-109618·109619 두 건 모두 KEV(실제 악용 확인 취약점 목록)에 신규 등재된 것을 확인했다** — 미국 정부 차원에서도 실제 악용으로 공식 인정된 것이다. 아울러 PHP 보안팀은 아직 패치가 없는 새 RCE 결함(CVE-2026-115560, 특정 설정·애플리케이션 코드 조합에서만 영향)을 추가로 공개했으며, 패치 전까지 `session.upload_progress.enabled=0` 설정을 임시 완화책으로 권고했다. 기존 매핑(TA0001\|T1190\|확인)과 분류(A)는 그대로 유지한다. 이번에 확인된 메모리 노출(쿠키 800KiB)→함수 주소 추출 과정은 "공개 웹 애플리케이션 악용(T1190)"이라는 관찰 범위에서 벗어나지 않는다고 판단해 별도 기법을 추가하지 않았다. CVE-2026-115560은 아직 공격에 쓰였다는 사례나 구체적인 공격 행위가 보고되지 않아 이번 보고서에서는 매핑하지 않으며(패치 여부 자체가 매핑 기준은 아니다), 실제 악용이 확인되면 별도로 검토한다. 패치 전 완화책(`session.upload_progress.enabled=0`)은 §4 체크리스트에 별도로 담았다.

### 참고 기록 — Node2Shell(Brotli 디코더 결함), .NET·Python까지 영향 확산 확인(CVE-2026-111497)

[D20261024-node2shell](2026-10-24.md) 사건의 Brotli 디코더 버퍼 오버플로 결함이, 기존에 확인된 Node.js·Bun 외에 **.NET**과 **Python의 HTTP 클라이언트 라이브러리들(urllib3[brotli], requests, httpx, aiohttp[speedups] 등, Brotli 디코더를 설정해 쓰는 경우에 한정)**에도 영향을 준다는 사실이 보도(10/26)로 추가 확인됐다. 마이크로소프트는 영향받는 .NET 버전에 긴급 패치를 배포했고(보도에는 권한 상승 위험으로 설명됨), 보안업체 Imperva는 이 결함이 실제로 원격 코드 실행(RCE)까지 이어질 수 있다고 확인했다. **다만 실제 공격(ITW) 사례는 이번 보도 시점까지도 확인되지 않았다.** .NET에서 보도된 위험은 권한 상승이고 Node.js·Bun·Imperva가 확인한 원격 코드 실행(RCE)과는 성격이 다르며, Python 영향도 취약한 Brotli 디코더를 실제로 설정해 쓰는 경우에만 해당한다. 기존 매핑(TA0001\|T1190\|후보, 공개 HTTP 엔드포인트가 요청 본문을 자동 해제하는 경로에 한정 — 아웃바운드 `fetch()` 등 클라이언트 쪽 처리는 별개 메커니즘으로 매핑 범위에서 계속 제외)과 분류(A)는 영향 범위만 넓어진 것으로 보고 그대로 유지하며(실제 악용 증거가 늘지 않아 '후보' 등급은 유지), 별도 사건으로 분리하지 않는다. .NET·Python 사용 조직도 Node.js·Bun과 같은 긴급도로 패치 여부를 확인해야 한다.

## 3. 국내 소식

## 4. 우선 대응 체크리스트

1. **코펜하겐대학교 관계자(해외 참고)**: 안내받은 출입 PIN 재발급을 즉시 적용하고, 대학을 사칭한 메일·문자 주의.
2. **PHP 운영 조직**: [D20261022-php2shell](2026-10-22.md) 패치(10/21 공개) 미적용 상태라면 최우선 적용 — 이제 CISA KEV에 정식 등재된 실제 악용 취약점이다. `session.upload_progress.enabled`를 쓰는 조직은 신규 미패치 결함(CVE-2026-115560) 대비로 `session.upload_progress.enabled=0` 설정 검토.
3. **Node.js·Bun·.NET·Python(Brotli 압축 해제 사용) 조직**: [D20261024-node2shell](2026-10-24.md) 패치 적용 여부 재확인 — 오늘부로 .NET·Python 사용 조직도 대상에 포함된다.
4. [10-17](2026-10-17.md)~[10-26](2026-10-26.md) 보고서의 Ivanti·Atlassian·Ahsay·PAN-OS·Cisco SEG·BeyondTrust·Fortinet·SiteGuard·Plex·Siemens·UpdraftCentral·eMudhra·Onamae·커넥트와이즈·Arista VCO·LiteLLM·GitLab·Collabora·HPE ArubaOS·Time4Popcorn — 기한이 지났거나 임박한 건이 많으므로 미조치 상태라면 우선 처리.

## 5. 검증 수준과 한계

- CISA KEV는 JSON 피드를 직접 받아 10/26 등재분(PHP2Shell 2건)을 확인했고 10/27 신규 등재는 없음을 확인했다(1차 출처, 피드가 매우 커 날짜순 최신 구간만 확인했다).
- 코펜하겐대학교 사건은 BleepingComputer 기사(2차 보도) 1건만 WebFetch로 직접 열람해 확인했다. 대학의 공식 원문 공지는 직접 열람하지 못했으며, 정확한 발견·공개 날짜(요일만 보도됨)는 확인하지 못해 지어내지 않고 비공개로 표기했다. 초기 침투 경로가 공개되지 않아 ATT&CK 매핑은 하지 않았다(분류는 J·경위 미공개).
- PHP2Shell 후속 확인은 BleepingComputer 기사 1건을 WebFetch로 직접 열람했고, CISA KEV 등재 사실은 JSON 피드를 직접 재확인했다. Perplexity·Expel의 원문 분석 게시물은 직접 열람하지 못했다.
- Node2Shell(.NET·Python 영향 확산) 소식도 같은 BleepingComputer 기사 1건에서 함께 확인했으며, Microsoft·Imperva의 원문 공지는 직접 열람하지 못했다.
- 국내 질의 6개 범주 모두 WebSearch만으로 수행했고(전문 매체 직접 열람은 이번 조사에서 하지 못함), 결과 없음이 "사건이 실제로 없다"는 뜻인지 "아직 보도되지 않았다"는 뜻인지는 구분할 수 없다.
- 검토했으나 채택하지 않음: 호스팅업체 DreamHost가 File Manager 장애 이후 이메일·FTP/SFTP 비밀번호 전면 재설정을 강제한 사건(BleepingComputer, 10/26) — DreamHost는 이를 "예방 조치"라고만 밝혔고 실제 침해 여부·영향 범위를 확인·공개하지 않아, 사건으로 등록하기엔 근거가 아직 불충분하다고 판단했다.
- 해외 랜섬웨어·대형 유출 일반 검색에서는 10월 24~27일 날짜로 명확히 특정되는 새로운 대형 사건을 추가로 찾지 못했다.
