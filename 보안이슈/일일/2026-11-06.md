**개요**: EFS는 2026-11-03 성명에서, 11월 2일 자사 생물학적 시료·혈액 제품을 보관하는 3개 시설의 저온 보관실 온도 및 제상 설정값이 비정상적으로 올라갔다고 밝혔다. 직접 침해당한 곳은 EFS가 아니라 냉장 설비 공급·관리 업체인 Coolworld Rentals로, 자사가 직접 통제하지 않는 제3자 구성요소의 취약점이 악용됐다고 설명했다. 수혈용 혈장과 의약품 제조용 혈장은 다른 시설로 옮기거나 보관해 손상을 막았고, 채혈·공급은 중단 없이 계속됐다. **침투 경로 [부분 확인]**: Coolworld가 통제하지 않는 "제3자 구성요소"의 취약점이 악용됐다는 점만 확인됐다. 구체적인 취약점 종류, Danfoss 등 10월 사건과 동일한 결함인지는 공개되지 않아, 이 사건 단독으로는 구체적 초기접근 기법을 특정하지 않는다. 다만 온도·제상 설정을 변경한 결과(데이터 조작)는 EFS·FBI/CISA가 공통으로 확인했다.

**어떻게 조치하나**

**쉽게 말하면**: 리눅스 서버를 관리하는 무료 제어판 소프트웨어 CWP(Control Web Panel, 구 CentOS Web Panel)의 핵심 웹서버 프로그램(cwpsrv)이 악성 버전으로 바뀌어 있는 사례가 발견됐습니다. 연구자들은 이를 'CWPdoor'라고 이름 붙였는데, 평소에는 조용히 숨어 있다가 공격자가 특수하게 꾸민 요청을 보내면 암호화된 명령을 받아 실행하는 방식입니다. 명령을 실행한 흔적(로그·타임스탬프)도 스스로 지워 매우 은밀합니다. 전 세계에 공개적으로 노출된 CWP 설치 대수가 34만 개가 넘는 것으로 집계됐지만, 이 중 실제로 이 백도어에 감염된 서버가 몇 대인지는 아직 공개되지 않았습니다.
**먼저 할 일(초보용)**: CWP(Control Web Panel)를 쓰는 서버 관리자는 지금 바로 cwpsrv 바이너리에 수상한 유닉스 소켓(`ngx_http_integrity_helper`)이나 의심스러운 헬퍼 프로세스가 있는지 확인하고, 감염이 확인되면 정상 버전으로 교체한 뒤 제어판 관련 자격 증명을 전부 새로 발급하세요(기존 값은 공격자가 이미 알고 있을 수 있습니다).

**개요**: 보안연구진은 2026년 6월 29일, CWP 업데이트처럼 위장한 스크립트가 cwpsrv(버전 1.15.10, 1.24.0)를 악성 버전으로 교체하는 것을 포착했다. 이 스크립트는 파일·디렉터리의 타임스탬프를 원래대로 되돌리고, 임시 파일을 지우고, 명령 기록을 삭제해 흔적을 숨긴다. 9월 30일에는 Ebury 백도어가 든 압축 파일 안에 담긴 악성 cwpsrv 샘플(파일명 cwpsrv.suspeito)이 VirusTotal에 올라온 것도 확인됐는데, 당시 탐지 엔진 검출 건수는 0건이었다. 변조된 백도어는 평소 휴면 상태로 있다가, 공격자가 보낸 특수 HTTP 헤더(암호화된 명령·타임스탬프·RSA 서명 포함)에 반응한다. 타임스탬프가 전후 5분 이내인지 확인하고 서명을 검증한 뒤 명령을 복호화해 헬퍼 프로세스로 실행하며, 명령과 출력은 AES-256-CBC로 암호화돼 오간다. 또한 로깅 모듈을 방해해 트리거 요청이 접근 로그에 남지 않게 한다. 연구진은 CWPdoor가 수동적으로 동작해 매우 은밀하다고 평가했다. XLab 집계에 따르면 최근 한 달간 공개 웹에 노출된 CWP 인스턴스는 34만 개가 넘지만, 이는 노출 규모일 뿐 실제 CWPdoor 감염 수는 공개되지 않았고, CWPdoor와 Ebury 백도어의 정확한 연관성도 아직 불분명하다. CWP 개발사의 공식 대응은 보도에서 확인되지 않았다.

**왜 일어났나**
- 직접 원인 [확인]: CWP의 핵심 웹서버 바이너리(cwpsrv)가 변조된 버전으로 교체돼 백도어 기능을 갖게 됐다(연구진 확인). 이 교체가 CWP의 공식 배포망을 통한 것인지, 이미 침해된 개별 서버에서 수동으로 교체된 것인지는 보도에서 명확히 구분되지 않는다.
- 구조적 원인 [추정 — 분석]: 서버 관리 패널은 그 자체가 root 권한에 가까운 통제권을 갖는 소프트웨어다. 이런 핵심 구성요소 하나가 변조되면, 로그 조작·흔적 삭제 기능까지 함께 심어져 있어 장기간 탐지를 피할 수 있는 구조적 위험이 크다.

**침투 경로 [확인 — 변조 메커니즘 한정]**: 변조된 업데이터 스크립트가 cwpsrv 바이너리를 악성 버전으로 교체(공급망 변조) → 백도어는 휴면 상태 유지 → 공격자가 RSA 서명·타임스탬프가 포함된 특수 HTTP 헤더 요청 전송 → 서명·시간 검증 후 암호화된 명령 복호화·실행 → 명령 실행 흔적(로그·타임스탬프·임시파일) 자동 삭제. 이 변조가 애초에 어떤 경로로 각 서버에 심어졌는지(최초 침투)는 공개되지 않았다.

**어떻게 조치하나**
- 즉시: (연구진 권고) `ngx_http_integrity_helper` 유닉스 소켓, 의심스러운 cwpsrv 헬퍼 프로세스, 서버 바이너리 내 X-Ngx-Integrity 문자열을 확인한다. 감염이 확인되면 패치 전 증거(바이너리 사본, 로그)를 먼저 보존한다.
- 단기: 감염된 바이너리를 정상 사본으로 교체하고 최신 버전으로 업그레이드하며, 제어판 관련 자격 증명을 전부 새로 발급한다(해당 서버 안에서 새로 만들지 않는다). 다른 악성코드가 함께 심어졌는지 호스트 전체를 조사한다.
- 장기: 서버 관리 패널처럼 root급 통제권을 갖는 소프트웨어의 업데이트 배포 과정에 무결성 서명 검증을 의무화하고, 정기적으로 핵심 바이너리의 체크섬을 알려진 정상값과 비교한다.
- 탐지: 평소와 다른 아웃바운드 HTTP 요청 패턴, 접근 로그에 남지 않는 서버 활동(로그 공백)을 모니터링한다.

**교훈**: "흔적을 스스로 지우는 백도어"가 발견되기까지 감염 시작(6월 말로 추정)부터 보도(11월)까지 수개월이 걸렸다는 것은, 로그 조작 기능이 포함된 악성코드가 얼마나 오래 숨어 있을 수 있는지를 보여준다. 노출된 인스턴스가 34만 개라는 숫자는 실제 피해 규모가 아니라 "공격 가능한 표면"의 크기일 뿐이라는 점도 구분해서 읽어야 한다.

### [D20261106-zyxel] Zyxel GS1900 스위치 제로데이, 6월 패치를 우회해 약 1,000대 침해
> 날짜: 공격 관측 시작(추정) 2026-08-17 · GreyNoise의 기존 CVE 연결·CISA KEV 등재 2026-09-21 · Binarly 제보 2026-09-29 · Zyxel 신규 CVE 확인 2026-10-11 · 패치 배포 2026-10-22 · 보안 권고 공개 2026-11-03 · 유형: 네트워크 장비 웹 관리 인터페이스 결함(실제 악용 확인) · 행위자: Kapibala(중국어 사용 위협 행위자, GreyNoise 명명) · 지역: 전 세계(해외, 48개국 약 996대) · 근거: 확인(벤더·GreyNoise·Binarly 확인)

**쉽게 말하면**: 중소기업·사무실에서 많이 쓰는 Zyxel GS1900 시리즈 네트워크 스위치(10개 모델)가, 지난 6월에 이미 패치했던 결함을 "우회"하는 새로운 제로데이 공격을 받아 48개국에서 약 1,000대가 뚫렸습니다. 공격자('Kapibala'라는 중국어 사용 행위자로 추정)는 인증 없이 특수하게 조작된 웹 요청만으로 장비에 명령을 실행시켜, 설정값과 암호화된 관리자(root) 비밀번호, 네트워크 정보를 빼갔습니다. 연구팀이 분석한 끝에 "6월 패치로는 막히지 않는" 새 결함(CVE-2026-107441)이라는 사실이 10월 11일 확인됐고, Zyxel은 10월 22일 이를 막는 새 펌웨어를 배포했습니다.
**먼저 할 일(초보용)**: Zyxel GS1900 스위치를 쓰는 관리자는 지금 바로 11월 3일 보안 권고에 안내된 최신 펌웨어로 업데이트하세요. 6월에 이미 한 번 업데이트했더라도 이번 결함은 그것으로 막히지 않으므로 다시 확인해야 합니다.

**개요**: 보안 위협 모니터링 업체 GreyNoise는 2026년 8월 17일경부터 중국어 사용 위협 행위자(자체 명명 'Kapibala')가 Zyxel GS1900 스위치를 겨냥한 공격 활동을 관찰했다고 밝혔다. 공격자는 원격으로 명령을 실행한 뒤 장비 설정, 해시된 root 자격 증명, 네트워크 정보를 수집하는 스크립트를 내려받게 했으며, 48개국에서 996대가 침해됐다. 9월 21일 GreyNoise는 이 공격을 기존에 알려진 결함(CVE-2026-7273, 6월 패치됨)과 연결했고, CISA는 같은 날 이를 KEV(실제 악용 확인) 카탈로그에 등재했다. 이후 보안업체 Binarly가 회수한 익스플로잇을 분석한 결과, 공격자가 실제로는 6월 패치가 추가한 검증 절차를 우회하는 별도의 미패치 취약점(파라미터 카운터를 검증 전에 손상시키는 out-of-bounds write 결함)을 쓰고 있다는 사실을 확인했다. Binarly는 9월 29일 이를 Zyxel에 제보했고, Zyxel은 10월 11일 새로운 결함으로 확인하며 CVE-2026-107441 번호를 부여했다. Zyxel은 10월 22일 파라미터 크기를 제한하고 메모리 복사 전 파라미터 개수를 검증하는 새 펌웨어를 배포했으며, 11월 3일 보안 권고문을 공개했다. 즉 6월 패치(CVE-2026-7273용)만 적용한 장비는 여전히 이번 결함에 취약할 수 있다.

**왜 일어났나**
- 직접 원인 [확인]: GS1900 웹 관리 인터페이스의 out-of-bounds write 결함으로, 인증되지 않은 공격자가 특수하게 조작된 HTTP 요청만으로 OS 명령을 실행할 수 있었다(벤더·Binarly 확인).
- 구조적 원인 [추정 — 분석]: 공격자가 "패치됐다고 알려진" 취약점의 수정 코드를 역으로 분석해, 그 수정이 막지 못하는 우회 경로(파라미터 검증 순서의 틈)를 찾아낸 사례다. 한 번의 패치로 안심하기보다, 패치 이후에도 같은 코드 경로를 공격자가 계속 분석할 수 있다는 전제가 필요하다.

**침투 경로 [확인 — 벤더·연구진 확인]**: 인증 없는 공격자가 조작된 HTTP 요청 전송 → out-of-bounds write로 OS 명령 실행 → 장비 설정·해시된 root 자격 증명·네트워크 정보를 수집하는 스크립트 실행 → 수집 데이터 외부 전송(세부 방식은 공개되지 않음).

**어떻게 조치하나**
- 즉시: (벤더 권고) 11월 3일 보안 권고의 신규 펌웨어로 즉시 업데이트한다. 6월 패치만 적용된 장비도 여전히 취약할 수 있으므로 반드시 재확인한다.
- 단기: 영향 가능 기간에 노출됐던 장비는 관리자 비밀번호를 전부 교체하고, 알 수 없는 설정 변경이나 추가 계정이 있는지 점검한다.
- 장기: 네트워크 장비의 웹 관리 인터페이스를 인터넷에 직접 노출하지 않는 것을 기본 원칙으로 삼고, 관리 접근을 VPN·사설망으로 제한한다.
- 탐지: 정상적이지 않은 대량의 설정 조회·다운로드 요청, 짧은 시간 내 다수 장비에서 반복되는 동일 패턴의 요청을 모니터링한다.

**교훈**: 패치했다는 사실 자체가 안전을 보장하지 않는다. 특히 "같은 결함을 막기 위한 다른 우회로"가 존재할 수 있다는 점에서, 벤더의 공식 권고에 안내된 정확한 버전·날짜를 확인하는 습관이 중요하다.

### [D20261106-digicert] 인증기관 DigiCert, 내부 시스템 노출로 고객정보·신원확인문서 유출

## 5. 검증 수준과 한계

- CISA KEV는 공식 카탈로그 웹페이지를 WebFetch로 직접 열람해 11/4~11/6 등재분을 확인했다. 신규 등재는 Apple CVE-2024-27834(포인터 인증 우회) 1건뿐이다. 이 결함은 2024년 Pwn2Own에서 발견돼 당시(Safari 17.5, iOS/iPadOS 16.7.8·17.5, macOS Sonoma 14.5, tvOS·watchOS 10.5 등)에 이미 패치됐다 — 거의 2년 전에 수정 배포가 끝난 결함이라, 그 사이 공식 업데이트를 적용한 기기라면 추가 조치가 필요 없다고 판단해 별도 전체 항목으로 다루지 않았다. CISA가 2026년 11월에야 KEV에 등재한 이유(새로운 악용 확인 시점, 연방기관 규정 준수 목적 등)는 카탈로그 페이지만으로는 확인되지 않았다.
- SonicWall GMS(9.5.2 이하)의 미패치 결함(CVE-2026-109593·109594)은 검토했으나 전체 이슈로 채택하지 않았다 — 벤더가 실제 악용을 보도하지 않았고, 해당 제품이 이미 지원종료(EOL)돼 "패치가 나오지 않는다"는 사실 자체가 핵심이라 다른 이슈만큼 사건으로서의 역동성이 적다고 판단했다. 다만 조치 필요성은 있어 체크리스트에만 남겼다.
- 메타(Meta)의 AI 개발환경 내부 보안 취약점(내부 대화·인증 토큰 노출 위험) 보도는 국내 매체에서 언급됐으나, 메타 자체 확인이나 영향 범위가 명확하지 않은 2차 보도 수준이라 이번 보고서에는 포함하지 않았다.
- 더존비즈온 사태(`D20261104-douzone`)는 여전히 피해(의심) 기업 목록이 늘어나는 '진행 중'인 사건이며, 더존비즈온 자체의 최초 침투 경로는 이번 조사에서도 공개되지 않았다.
- 프랑스 아르케아 은행 사건은 피해 규모(1억 3,300만 달러)가 은행의 공식 확인이 아니라 블록체인 추적가의 추산이며, 은행은 "규모가 맞다"고만 인정했을 뿐 정확한 금액은 밝히지 않았다. 최초 침투 지점(포르튀네오 경유 여부)도 현지 언론과 은행의 설명이 엇갈린다.
- 국내 의료기관 랜섬웨어 협박(`D20261106-obsoft`)은 전적으로 공격자의 다크웹 게시물에 근거한다. 피해 병원명조차 보도의 "추정 후보"일 뿐 확인되지 않았으며, 본 보고서는 이를 명확히 [주장]으로 구분하고 ATT&CK 매핑을 하지 않았다.
- 한패스 사건은 구체적인 API 결함·영향 규모가 공개되지 않아, ATT&CK 매핑을 T1190(공개 애플리케이션 악용) 수준으로만 제한했다.
- 국내 질의 중 WebSearch 결과 일부가 질의에 "2026년"을 넣었는데도 2025년 사건(KT 펨토셀 중간조사, LG유플러스 APPM 사고)을 반환해, 과거3년 기록과 대조해 걸러내는 과정을 거쳤다. 이런 날짜 혼선은 검색 결과를 원문에서 재확인하지 않으면 과거 사건을 "오늘의 신규 사건"으로 오인할 위험이 있다는 점을 보여준다.
- **GPT(Codex) 검토 미실시**: `ask_codex` 호출을 시도했으나 "사용량 한도(usage limit)"에 걸려 실패했다(사용자 CLAUDE.md 지침에 따라 반복 재시도하지 않았다). 따라서 이번 보고서는 독립적인 GPT 교차 검토 없이 발행된다 — 위 사건별 원인 논리·근거 표기·ATT&CK 매핑·조치 적절성은 본 보고서 작성자의 자체 점검에만 의존했다는 한계가 있다.
