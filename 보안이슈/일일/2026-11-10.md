## 2. 이슈별 분석

### [D20261110-rsupport] 원격지원 SaaS '리모트콜'(알서포트) 침해, 고객사 상담원·관리자 정보 유출
> 날짜: 비정상 징후 발견 2026-10-28 · KISA 신고 2026-10-29 · 보도 2026-11-01·11-10 · 유형: SaaS(원격지원) 벤더 침해(고객사 다수 영향, 경위 조사 중) · 행위자: 미귀속 · 지역: 한국 · 근거: 확인(회사 자체 확인, KISA 신고)

**쉽게 말하면**: 국내 기업들이 상담센터·원격지원에 쓰는 소프트웨어 회사 알서포트의 서비스 '리모트콜' 운영 사이트가 외부 공격자에게 뚫렸습니다. 내부 개발자 PC에서 이상 징후가 발견돼 조사가 시작됐고, 그 결과 리모트콜을 쓰는 고객사들의 회사명, 고객사 운영관리자 연락처, 상담원 이메일 주소가 유출된 것으로 확인됐습니다. 다행히 지금까지는 최종 소비자(상담을 받은 일반 고객)의 개인정보나 원격지원 중 오간 데이터가 유출된 흔적은 없다고 회사가 밝혔습니다. 다만 공격자가 정확히 어떤 경로로 침투했는지는 아직 조사 중입니다.
**먼저 할 일(초보용)**: 리모트콜을 쓰는 고객사의 운영관리자·상담원은 출처가 불분명한 이메일·문자의 링크나 첨부파일을 지금부터 열지 마세요. 유출된 연락처·이메일을 이용한 표적 피싱(회사 관계자 사칭)이 우려됩니다.

**개요**: 알서포트는 2026년 10월 28일, 원격지원 SaaS '리모트콜'의 운영 사이트에 외부 공격자가 비인가 접근한 사실을 확인했고, 다음 날 KISA(한국인터넷진흥원)에 신고했다. 조사는 내부 개발자 PC에서 발견된 이상 징후를 계기로 시작됐다. 확인된 유출 정보는 고객사명, 고객사 운영관리자의 연락처, 상담원 이메일 주소다. 피해 고객사 수와 정확한 유출 규모는 공개되지 않았으며, 최종 소비자의 개인정보나 원격지원 관련 데이터(상담 내용, 원격 제어 기록 등)가 유출된 정황은 현재까지 확인되지 않았다고 밝혔다. 공격 경로가 개발자 PC를 거친 것인지, 개발자의 계정·인증정보가 먼저 탈취된 것인지는 조사 중이다. 회사는 비인가 접근 경로를 차단했고, 고객에게 출처가 불분명한 이메일·문자의 링크·첨부파일을 열지 말라고 당부했다.

**왜 일어났나**
- 직접 원인 [확인 — 세부는 조사 중]: 리모트콜 운영 사이트에 외부 공격자의 비인가 접근이 있었다는 사실은 확인됐지만, 최초 침투 경로(개발자 PC 경유 여부 등)는 아직 조사 중이다.
- 구조적 원인 [추정 — 분석]: 원격지원 SaaS는 그 자체로 고객사의 상담원·관리자 계정 정보를 다루며 고객사 시스템에 원격으로 접속하는 권한을 가진다. 이런 벤더 하나가 침해되면, 직접 공격받지 않은 여러 고객사의 임직원 연락처까지 한꺼번에 노출될 수 있는 공급망형 위험을 안고 있다.

**침투 경로 [매핑 안 함 — 경위 조사 중, 미공개]**: 내부 개발자 PC의 이상 징후를 계기로 침해가 드러났다는 사실 외에, 최초 침투 방법과 공격 경로는 공개되지 않았다. 본 저장소는 경위가 공개되지 않은 사건에 ATT&CK 기법을 매핑하지 않는다.

**어떻게 조치하나**
- 즉시: (회사 조치) 비인가 접근 경로 차단, KISA 신고, 고객 대상 피싱 주의 안내. (본 보고서의 권고) 유출된 연락처를 보유한 고객사는 담당 상담원·관리자에게 사칭 피싱 위험을 선제적으로 공지한다.
- 단기: 조사 결과가 나오면 개발자 PC·계정이 최초 침투 경로였는지 확정하고, 관련 인증정보를 전부 교체한다.
- 장기: SaaS 벤더는 개발자 PC·내부 계정처럼 고객 데이터에 간접 접근할 수 있는 경로에도 고객 데이터베이스와 동등한 접근 통제·모니터링을 적용한다.
- 탐지: 리모트콜 관련 연락처를 겨냥한 표적 피싱 시도, 고객사 시스템에 대한 비정상 원격 접속 요청을 모니터링한다.

**교훈**: "최종 소비자 데이터는 안전하다"는 설명만으로 이 사건이 작다고 보기는 어렵다. 유출된 것이 상담원·관리자의 연락처라 해도, 이는 다음 단계 표적 피싱의 재료가 될 수 있다. 원격지원 SaaS처럼 여러 고객사의 '통로' 역할을 하는 서비스는 그 자체가 공급망 위험의 축소판이라는 점을 보여준다.

### [D20261110-cryptoexch] 가상자산거래소 연쇄 피해(고팍스 협박메일·거래중단, 프라뱅 자산탈취), 금감원 CISO 소집
> 날짜: 고팍스 비인가 접근(추정) 2026년 9월 초 · 고팍스 협박메일·거래중단 2026-11-06 · 프라뱅 자산 탈취(시점 미공개) · 금융위 전 금융권(가상자산 포함) 보안점검 발표 2026-11-05 · 금감원 CISO 소집 공지 2026-11-08(회의 11-19) · 유형: 가상자산거래소 침해·갈취(경위 대부분 미공개) · 행위자: 미귀속 · 지역: 한국 · 근거: 확인(거래소 자체 공지·금융당국 발표)

**쉽게 말하면**: 국내 가상자산(암호화폐) 거래소들이 잇따라 피해를 입으면서 금융감독원이 모든 국내 가상자산사업자의 정보보호최고책임자(CISO)를 11월 19일 긴급 소집하기로 했습니다. 거래소 '고팍스'는 9월 초 일부 계정에 비인가 접근이 있어 이용자 7,000명과 임직원 2명의 개인정보가 유출됐는데, 11월 6일에는 공격자로부터 금품을 요구하는 협박 이메일을 받고 모든 입출금·거래를 중단하며 자산을 콜드월렛(인터넷과 분리된 저장장치)으로 옮기고 있습니다. 코인마켓 거래소 '프라뱅'은 약 1억 원 상당의 자산을 탈취당했습니다. (참고로 한 보도에는 '바이낸스가 북한 추정 공격으로 63억 달러를 잃었다'는 내용도 섞여 있었는데, 정작 바이낸스는 해킹 자체를 부인하고 있어 — 서로 다른 보도가 충돌해 이 부분은 이번 보고서에서 제외했습니다.)
**먼저 할 일(초보용)**: 고팍스 이용자는 거래소의 공식 공지를 확인하고 자산 이동(콜드월렛 전환) 상황을 지켜보세요. 프라뱅 이용자는 거래소의 공식 공지를 확인하세요. 두 거래소 모두 사칭 피싱에 특히 주의하세요.

### [D20261110-gpustack] GPUStack 루프백 헤더 신뢰 인증 우회·원격 코드 실행(CVE-2026-102895) 실제 악용
> 날짜: 취약점 공개 2026-11-04 · CISA KEV 등재 2026-11-09(조치 기한 2026-11-23) · 유형: AI·GPU 클러스터 관리 플랫폼 인증 우회 및 원격 코드 실행(실제 악용 확인) · 행위자: 미귀속 · 지역: 전 세계(해외) · 근거: 확인(벤더 보안 권고·CISA KEV 등재)

**쉽게 말하면**: 여러 대의 GPU 서버에서 AI 모델을 돌리고 관리하는 오픈소스 플랫폼 'GPUStack'(2.2.0 미만)에서, 외부 요청에 `X-GPUStack-Real-IP: 127.0.0.1`이라는 헤더 한 줄만 붙여 보내면 서버가 이를 "자기 자신(로컬호스트)이 보낸 요청"으로 믿고 로그인 없이 관리자 권한을 내주는 결함(CVE-2026-102895)이 실제 공격에 악용되고 있습니다. 관리자 권한을 얻은 공격자는 저장된 클라우드·API 비밀값을 읽거나 추론 백엔드 설정(YAML)을 등록해 서버에서 원하는 명령을 실행할 수 있습니다.

**개요**: GPUStack 2.2.0 미만 버전은 기본 설정(`force_auth_localhost=false`)에서 로컬호스트(127.0.0.1) 발신 요청에 대해 인증을 생략하고 내장 관리자 권한을 부여한다. 이때 동일 호스트 리버스 프록시를 거치거나 클라이언트가 조작한 `X-GPUStack-Real-IP` 헤더의 루프백 주소를 검증 없이 신뢰해, 인증되지 않은 원격 공격자가 내장 관리자로 가장할 수 있다(CVSS 9.8). 관리자 권한 획득 후에는 등록된 비밀값(HuggingFace 토큰·클라우드 자격 증명 등) 조회와 커스텀 추론 백엔드 YAML 등록을 통한 임의 코드 실행이 가능하다. **왜 일어났나**
- 직접 원인 [확인]: 로컬호스트 요청의 인증을 면제하는 기본 설정과, 클라이언트가 위조 가능한 `X-GPUStack-Real-IP` 헤더를 신뢰 프록시 검증 없이 그대로 받아들인 구현 결함(벤더·NVD 확인).
- 구조적 원인 [추정 — 분석]: AI 인프라 관리 도구는 빠른 로컬 개발 편의를 위해 로컬 인증을 기본 비활성화하는 경우가 많으나, 컨테이너·리버스 프록시 환경에 배포될 때 프록시 헤더 신뢰 경계가 무너지면 곧바로 전체 GPU 클러스터 장악으로 이어진다.

**침투 경로 [확인 — 벤더·KEV 기준]**: 외부 노출된 GPUStack 엔드포인트에 `X-GPUStack-Real-IP: 127.0.0.1` 헤더를 포함한 요청 전송(T1190) → 인증 없이 내장 관리자 권한 획득 → 추론 백엔드 YAML 등록 등을 통해 호스트/컨테이너 명령 실행(T1059).

**어떻게 조치하나**
- 즉시: (벤더·CISA 권고) GPUStack 2.2.0 이상으로 즉시 업데이트하고, `force_auth_localhost=true`를 활성화한다. 업그레이드 전이라도 접근 로그와 등록된 추론 백엔드 목록을 먼저 보존한다.
- 단기: GPUStack에 저장돼 있던 API 키·모델 저장소 토큰·클라우드 자격 증명을 전부 유출 가정하에 폐기·재발급한다.
- 장기: AI 클러스터 관리 콘솔을 공용 인터넷에 직접 노출하지 않고 내부망·VPN 뒤로 격리한다.
- 탐지: 외부 인입 트래픽에 포함된 `X-GPUStack-Real-IP: 127.0.0.1` 헤더 및 비정상 추론 백엔드 등록 이벤트를 모니터링한다.

**교훈**: "로컬호스트는 안전하다"는 가정과 "프록시 헤더에 적힌 IP가 실제 IP다"라는 가정이 만나면 인증 체계 전체가 헤더 한 줄로 무력화된다.

### [D20261110-freeswitch] SignalWire FreeSWITCH SIP MESSAGE API 명령 실행(CVE-2026-116779) 실제 악용
> 날짜: 취약점 공개 2026-11-05 · CISA KEV 등재 2026-11-09(조치 기한 2026-11-23) · 유형: 오픈소스 통신(VoIP/SIP) 플랫폼 원격 코드 실행(실제 악용 확인) · 행위자: 미귀속 · 지역: 전 세계(해외) · 근거: 확인(벤더 보안 권고·CISA KEV 등재)

**쉽게 말하면**: 인터넷 전화(VoIP)·고객센터 시스템에 널리 쓰이는 오픈소스 통신 플랫폼 'FreeSWITCH'(1.11.3 미만)에서, 공격자가 수신자 주소(`To`)에 `api+명령어` 형식을 넣은 SIP 문자 메시지(MESSAGE)를 보내면 FreeSWITCH 내부 API와 운영체제 명령이 그대로 실행되는 결함(CVE-2026-116779)이 발견돼 실제 공격에 악용되고 있습니다. SIP 메시지 수락이 열려 있는 프로파일에서는 로그인 없이도 공격이 성립할 수 있습니다.
**먼저 할 일(초보용)**: FreeSWITCH를 운영하는 관리자는 지금 바로 1.11.3 이상으로 업데이트하고, 비인증 SIP 프로파일에서 외부 SIP MESSAGE를 처리하지 않도록 접근 통제(ACL)를 점검하세요.

**개요**: FreeSWITCH 1.11.3 미만에서 수신된 SIP `MESSAGE` 요청의 `To` 사용자 문자열을 더하기(`+`) 기호 기준으로 분리해 왼쪽 값을 채팅 프로토콜 선택자(chat proto)로 라우팅할 때, 공격자가 `api` 프로토콜을 지정하면 내부 `switch_api_execute()` 함수에 도달해 FreeSWITCH 데몬 권한으로 임의의 FreeSWITCH API 명령(예: `system` 모듈을 통한 OS 명령 포함)을 실행할 수 있다(CVSS 9.8). 공개 PoC 코드가 함께 유포됐으며, CISA는 2026-11-09 실제 악용을 확인해 KEV에 등재했다(기한 11/23).

**왜 일어났나**
- 직접 원인 [확인]: SIP `MESSAGE`의 사용자 입력(`To` 헤더 프로토콜 접두사)을 허용 목록 검증 없이 내부 채팅/API 디스패처에 전달해 관리용 `api` 인터페이스가 호출되도록 허용한 결함(벤더 확인).
- 구조적 원인 [추정 — 분석]: 통신 미들웨어에서 외부 시그널링 메시지(SIP) 파서와 내부 관리 API 실행기가 같은 디스패치 테이블을 공유하면, 구분자(`+`) 하나만으로 외부 입력이 내부 특권 인터페이스로 넘어갈 수 있다.

**침투 경로 [확인 — 벤더·KEV 기준]**: 외부에 노출된 SIP 포트로 `To: <api+...>` 형식의 조작된 SIP MESSAGE 전송(T1190) → `switch_api_execute()` 호출을 통한 FreeSWITCH API 및 OS 명령 실행(T1059).

**어떻게 조치하나**
- 즉시: (벤더·CISA 권고) FreeSWITCH 1.11.3 이상으로 즉시 업데이트한다. 패치 전 SIP 시그널링 로그와 프로세스 실행 이력을 보존한다.
- 단기: 외부 SIP 프로파일(external)에서 신뢰할 수 없는 발신지의 SIP MESSAGE를 ACL로 차단하고, 불필요한 `system` 등 명령 실행 모듈 노출을 점검한다.
- 장기: VoIP 시그널링 서버를 인터넷에 전체 개방하지 않고 SIP 트렁크 제공사 IP 대역으로 방화벽을 제한한다.
- 탐지: SIP `MESSAGE` 요청의 `To` 헤더에 `api+` 문자열이 포함된 패킷을 네트워크·방화벽에서 탐지·차단한다.

**교훈**: 웹(HTTP)뿐 아니라 SIP 같은 통신 프로토콜도 외부 입력이 내부 명령 실행기로 이어질 수 있는 똑같은 공격 표면이다.
