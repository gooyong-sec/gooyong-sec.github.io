### [D20261111-fsec] 금융보안원 '정보보호 상시평가 지원시스템' 해킹, 행정서식·담당자 정보 유출
> 날짜: 비정상 접근·인지 2026-11-09 15:00경 · 보도·공식 설명 2026-11-10~11 · 유형: 금융보안 전담기관 평가 지원 시스템 침해(경위 조사 중) · 행위자: 미귀속 · 지역: 한국 · 근거: 확인(금융보안원 공식 확인, 금융위·KISA 신고)

**쉽게 말하면**: 은행·증권사 등 금융권의 보안 관제와 평가를 담당하는 전문기관인 '금융보안원'이 운영하는 '정보보호 상시평가 지원시스템'이 외부 해킹 공격을 받아 일부 자료가 유출됐습니다. 금융보안원에 따르면 유출된 자료는 개인신용정보 동의서 샘플 등 행정서식 약 200건과 그 안에 적힌 이름·생년월일 등 개인정보 300여 건, 그리고 마스킹(가림) 처리된 금융사 평가 담당 직원들의 시스템 이용자 정보 350여 건입니다. 다행히 일반 금융 소비자의 계좌·신용정보나 금융사 시스템 구성도 같은 핵심 보안 자료는 이 시스템에 보관되지 않아 유출되지 않았다고 밝혔지만, 금융권 보안을 감독·지원하는 기관 자체가 뚫렸다는 점에서 파장이 큽니다.
**먼저 할 일(초보용)**: 금융보안원 상시평가 시스템을 이용한 금융사 담당자는 유출된 연락처·이메일을 노린 금융당국·금융보안원 사칭 피싱 연락에 각별히 주의하세요. 해당 시스템과 같은 비밀번호를 다른 업무 사이트에서 쓰고 있다면 안전한 기기에서 비밀번호를 바꾸고 기존 로그인 세션을 초기화하세요.

**개요**: 금융보안원은 2026년 11월 9일 오후 3시경, 금융회사들의 개인신용정보 보호 실태 평가(올해 대상 약 3,000개사) 자료 제출을 지원하는 '정보보호 상시평가 지원시스템'에서 외부의 비정상적인 접근을 통한 정보 유출 사실을 확인하고 즉시 시스템 접속을 차단한 뒤 금융위원회와 한국인터넷진흥원(KISA)에 신고했다. 11월 10~11일 금융보안원과 금융당국 발표(연합뉴스·뉴시스·보안뉴스·데일리시큐 보도)에 따르면, 현재까지 확인된 유출 규모는 ①광고성 이벤트 전송 내역·개인신용정보 동의서 샘플 등 행정서식 약 200건, ②해당 서식에 포함된 이름·생년월일 등 개인정보 300여 건, ③마스킹 처리된 이름·휴대전화번호·이메일 등 시스템 이용자(주로 금융사 상시평가 담당 직원) 정보 350여 건 등 총 850여 건이다. 금융보안원은 취약점 분석·평가 결과나 금융사 시스템 구성도 같은 핵심 보안 정보는 이 시스템에서 수집하지 않으며, 주민등록번호 등 일반 금융소비자의 민감한 금융거래 정보도 포함되지 않았다고 설명했다. 공격자는 IP 주소를 수시로 바꿔 가며 정상 접근인 것처럼 위장해 접근한 것으로 전해졌으며, 일부 보도에서는 감독당국 관계자 계정이 악용된 정황도 거론됐으나 구체적인 최초 침투 경로(웹 취약점인지 계정 탈취인지)는 정밀 조사 중이다. 한편 이 사고 직후 KISA도 자체 점검 차원에서 ISMS-P 누리집·개인정보침해 신고센터 등 대민 웹 서비스 7곳을 일시 중단하고 긴급 보안점검에 들어갔다.

**왜 일어났나**
- 직접 원인 [확인 — 세부 침투 경로는 조사 중]: 외부 공격자가 IP를 수시로 변경하며 정보보호 상시평가 지원시스템에 비정상 접근해 행정서식과 이용자 정보를 반출했다(금융보안원 확인). 어떤 취약점이나 계정 경로로 인증·접근 통제를 통과했는지는 조사 중이어서 단정하지 않는다.
- 구조적 원인 [추정 — 분석]: 핵심 보안관제망이 아닌 '자료 제출·평가 지원용 대외 웹 시스템'은 수천 개 회원사 담당자가 접속해야 하므로 인터넷에 열려 있는 접점이 된다. 또한 제출된 '동의서 샘플·증빙 서식'에 실제 개인정보(300여 건)가 가명·비식별 처리 없이 그대로 들어 있었다는 점은, 평가·감사 증빙 과정의 개인정보 최소화 원칙이 현장에서 느슨했음을 보여준다.

**침투 경로 [매핑 안 함 — 경위 조사 중, 미공개]**: 공격자가 IP를 바꿔 가며 상시평가 시스템에 비정상 접근해 자료를 반출했다는 사실은 확인됐으나, 최초 침투 수단(공개 웹 애플리케이션 결함 악용인지 유효 계정 악용인지)이 공식 확정되지 않았다. 본 저장소는 경위가 공개되지 않은 사건에 ATT&CK 기법을 추측으로 매핑하지 않는다.

**어떻게 조치하나** (본 보고서의 권고이며 당국·기관 지침이 우선)
- 즉시: (기관 조치) 상시평가 시스템 접속 차단, 웹 서버·접근 로그·세션 기록 등 포렌식 증거 보존 후 취약점 점검, 관계기관 신고 및 피해 금융사·정보주체 개별 통지. 침해가 의심되는 서버에서 새 인증키나 비밀번호를 발급하지 않는다.
- 단기: 상시평가 시스템의 전체 이용자 세션·토큰을 무효화하고, 접근 권한(특히 감독·관리자 계정)과 웹셸 등 지속성 흔적을 전수 조사한다. 유출된 담당자 연락처를 악용한 2차 사칭 피싱 경보를 전 금융사에 발령한다.
- 장기: 평가·감사 증빙 서류 제출 시 실제 고객 개인정보가 포함된 샘플 제출을 금지(자동 마스킹·검증 필터 적용)하고, 대외 평가 지원 시스템에도 핵심 시스템에 준하는 비정상 대량 조회 차단·MFA를 의무화한다.
- 탐지: 다수 IP에서 분산 유입되는 반복 조회·다운로드 패턴, 비정상 시간대 평가 서식 일괄 열람 이벤트를 모니터링한다.

**교훈**: 금융권 보안을 점검하는 기관의 '평가 자료 제출 사이트' 자체가 공격 표적이 됐다. 핵심 관제망이 안전하더라도 외곽의 대외 지원 시스템이 뚫리면 기관의 신뢰 전체가 흔들리며, 증빙용 샘플 서류에 실제 개인정보를 넣어 제출하는 관행도 함께 고쳐야 한다.

**개요**: CISA는 2026-11-10 통신·메시징 인프라 취약점 2건을 KEV 카탈로그에 추가했다(기한 11/24). 첫째, **Cisco BroadWorks(CVE-2026-20320, CVSS 7.5)**는 Open Client Interface(OCI) XML 파서에서 외부 개체 참조(XXE, XML External Entity)가 기본 허용되어 발생한 결함이다. 인증되지 않은 원격 공격자가 OCI-P(Provisioning) 서비스에 조작된 XML 메시지를 보내면 BroadWorks 사용자 권한으로 파일 시스템의 민감한 설정 정보를 읽을 수 있다. 둘째, **Openwave Messaging Limited의 Webtop Media Transcoder(CVE-2026-111793, CVSS 4.3, CWE-669)**는 관리자가 지정한 변환 허용 파일 형식 제한을 서버 측에서 제대로 강제하지 않은 결함으로, 인증된 사용자가 표준 웹메일 UI를 우회해 요청을 보내면 의도하지 않은 문서 형식을 변환·처리하게 만들 수 있다. 두 취약점 모두 8월·10월에 각각 공개된 N-day 결함이나 실제 악용이 확인돼 KEV에 올랐다.

- 장기: XML 파서의 외부 개체(DTD/XXE) 처리를 코드 전반에서 기본 비활성화하고, 파일 형식·권한 검증은 프런트엔드(웹메일 UI)가 아닌 백엔드 처리 엔진에서 직접 강제하도록 아키텍처를 검증한다.
- 탐지: OCI-P 엔드포인트로 유입되는 XML 본문 내 `<!ENTITY` 또는 `SYSTEM` 키워드 포함 요청, 웹메일 세션을 거치지 않은 직접 트랜스코더 API 호출을 탐지한다.

**교훈**: BroadWorks의 설정 읽기 결함(CVSS 7.5)이나 Openwave의 파일 제한 우회(CVSS 4.3)는 단독 점수로만 보면 '최고 위험(Critical)'이 아니지만, 실제 공격자는 설정 파일을 읽어 다음 단계의 자격 증명을 얻거나 내부 변환기를 공격 디딤돌로 삼기 위해 이런 결함을 골라 쓴다.

## 3. 교차 분석 — 오늘의 사례에서 보이는 패턴

> 선정된 국내외 6건의 공통점이며 전체 공격의 통계가 아니다.

1. **'패치 공개 = 공격 시작'과 중간 위험도 결함의 실전 악용**: 바라쿠다 ESG 체인(`D20261111-barracuda`)은 11/3 패치 공개 후 단 7일 만에 실제 악용이 확인돼 KEV에 올랐고, Outlook(`D20261111-outlook`, CVSS 6.5)·BroadWorks(`D20261111-broadworks`, CVSS 7.5)·Openwave(CVSS 4.3)처럼 원격 코드 실행이 아닌 '인증 해시 노출·설정 파일 열람·변환 제한 우회' 결함들도 실제 공격 체인의 부품으로 활발히 쓰이고 있다.
2. **국내 보안·공공 플랫폼의 '주변부'와 '안 지운 데이터'**: 금융보안원(`D20261111-fsec`)은 핵심 관제망이 아닌 대외 '상시평가 자료 제출 시스템'과 샘플 서식 내 실제 개인정보가 약점이 됐고, 대구로(`D20261111-daeguro`)는 폐업 가맹점 계좌와 전직 직원 계정이 남아 있어 노출 범위를 키웠다.
3. **클라이언트(브라우저·메일) 제로데이 동시 패치**: Chrome XML UAF(`D20261111-chrome`)와 Outlook 강제 인증(`D20261111-outlook`)이 같은 날 KEV에 등재돼, 서버·엣지 장비뿐 아니라 임직원 PC의 브라우저와 메일 클라이언트를 통한 초기 침투·자격 증명 탈취 위협도 동시에 높아졌다.

## 6. 검증 수준과 한계

- CISA KEV 2026-11-10 등재 6건은 CISA 공식 피드(`known_exploited_vulnerabilities.json`), MITRE CVE API 레코드, BleepingComputer 1차 보도를 직접 조회해 교차 확인했다. 수정 버전 번호는 발표 당시 기준이므로 실제 조치 시 각 벤더의 최신 보안 권고를 재확인해야 한다.
- 금융보안원(`D20261111-fsec`)과 대구로(`D20261111-daeguro`) 사건은 기관·운영사 확인 및 복수 언론 보도로 피해 사실과 유출 항목이 확인됐으나, 최초 침투 경로(구체적 취약점·계정 탈취 경위)는 조사·수사 중이어서 ATT&CK 기법을 매핑하지 않았다.
- **ATT&CK 버전 확인 결과**: https://attack.mitre.org/tactics/enterprise/ 에서 현재 공식 버전이 **v20.1**임을 확인했다(작업 지침은 v19.2 기준, 본 저장소 카탈로그는 v20.0 기준). 전술 15개 체계는 동일하므로 임의 대규모 재매핑은 하지 않고 기존 카탈로그 범위에서 매핑했다.
- **독립 교차 검토**: 현재 실행 환경이 Gemini(Antigravity)여서 지침 8번에 따라 Gemini 자체 체크리스트 교차 검토를 수행해 사실관계·근거 표기·ATT&CK 전술-기법 일치·초보용 문장 정확성을 점검했다.
