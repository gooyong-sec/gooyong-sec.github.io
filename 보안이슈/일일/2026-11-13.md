### [D20261113-multicampus] 삼성SDS 자회사 '멀티캠퍼스' 온라인 교육 플랫폼 해킹 — 고객사 임직원 약 7만 명 이름·사번·부서·직급 등 유출
> 날짜: 비인가 접근 발생 2026-11-09 · 고객사 통지 및 개인정보위 신고 2026-11-11 야간(보도 11-12~13) · 유형: 기업·공공 위탁 온라인 교육 플랫폼 비인가 접근 및 임직원 정보 유출 · 행위자: 미귀속 · 지역: 한국 · 근거: 확인(멀티캠퍼스 고객사 통지·개인정보위 신고, 데일리시큐·비즈중앙 보도)

**쉽게 말하면**: 삼성SDS의 자회사이자 주요 대기업·시중은행·공공기관 임직원 교육을 위탁받아 운영하는 '멀티캠퍼스'의 온라인 교육 사이트('러닝플랫폼')가 해킹당해 수강생 약 7만 명의 개인정보가 유출됐습니다. 유출된 정보에는 이름·전화번호·이메일뿐 아니라 소속 부서명·사번·아이디·직급·직위 같은 회사 내부 인사 정보까지 포함돼 있어, 해커가 실제 직장 상사나 인사팀을 정교하게 사칭해 보이스피싱이나 악성 메일 공격(스피어 피싱)을 시도할 위험이 큽니다.
**먼저 할 일(초보용)**: 멀티캠퍼스 러닝플랫폼을 이용하는 기업·기관 임직원은 감염되지 않은 안전한 기기에서 교육 사이트 비밀번호와 같은 비밀번호를 쓰는 사내·외부 계정 비밀번호를 즉시 바꾸고, 기존 로그인 세션을 모두 로그아웃(무효화)하세요. 내 사번·부서·직급을 정확히 대면서 "인사팀·교육담당자입니다" 또는 "부서장인데 급히 처리할 일이 있다"고 연락해 오는 문자·메일·메신저는 반드시 사내 내선 전화 등 별도 통로로 진짜 본인인지 먼저 확인하세요.

**개요**: 기업·공공기관 교육 전문 기업 멀티캠퍼스(삼성SDS 자회사)가 운영하는 온라인 교육 플랫폼 '러닝플랫폼'에서 2026년 11월 9일 외부의 인가받지 않은 비인가 접근(해킹)이 발생해 약 **7만 명(사람 기준)** 규모의 수강생(고객사 임직원 등) 개인정보가 유출됐다(데일리시큐·비즈중앙 11/12~13 보도). 멀티캠퍼스는 침해 사실을 인지한 뒤 11월 11일 밤 고객사들에 유출 사실을 통지하고 개인정보보호위원회에 신고했다. 통지된 유출 항목은 **이름, 전화번호, 이메일 주소, 부서명, 사번, 아이디(ID), 직급, 직위** 등이다(주민등록번호 등 고유식별정보나 결제·금융정보는 포함되지 않았다고 회사 측은 밝혔다). 멀티캠퍼스는 삼성 주요 계열사를 비롯해 다수의 시중은행과 공공기관 임직원 직무·법정 의무 교육을 위탁 수행하는 국내 대표 기업 교육(B2B) 플랫폼이어서, 여러 기업·금융사·공공기관의 조직도 및 임직원 식별 정보가 한꺼번에 외부로 노출됐을 우려가 제기됐다.

**왜 일어났나**
- 직접 원인 [확인 — 세부 침투 경로는 미공개]: 멀티캠퍼스 온라인 교육 플랫폼('러닝플랫폼')에 외부 비인가 접근이 발생해 수강생 약 7만 명의 개인·인사 정보가 조회·유출됐다(회사 통지 및 개인정보위 신고 확인). 공격자가 웹/API 취약점을 악용했는지, 관리자·위탁 운영 계정을 탈취했는지는 공개되지 않아 단정하지 않는다.
- 구조적 원인 [추정 — 분석]: (1) 다수의 대기업·금융사·공공기관이 임직원 교육 편의를 위해 인사 시스템(HR)의 사번·부서·직급 데이터를 외부 위탁 교육 플랫폼에 그대로 연동·보관하는 구조여서, 위탁 플랫폼 한 곳이 뚫리면 수십 개 고객사의 조직도가 동시에 노출된다 (2) 올해 하반기 한국은행 온라인 연수 수탁업체(186명 노출), KISA 위탁 한국정보보호교육센터 외주 사이트, 국립외교원 온라인교육시스템(`D20261006-mofa`) 등 본원 업무망보다 보안 통제가 느슨한 '온라인 교육·연수 시스템'이 반복해서 공격 통로가 되고 있다(본 보고서의 분석).

**침투 경로 [매핑 안 함 — 경위 미공개]**: 외부 비인가 접근으로 교육 플랫폼 내 개인·인사 정보가 유출된 사실만 확인됐고, 구체적인 최초 침투 수단은 공개되지 않아 ATT&CK 기법을 추측으로 매핑하지 않는다.

**어떻게 조치하나** (본 보고서의 권고)
- 즉시: (멀티캠퍼스) 러닝플랫폼 웹·API·DB 접근 로그와 메모리·디스크 포렌식 증거를 신속히 보존하고 비인가 접근 경로를 차단한다. 침해된 서버나 관리자 환경에서 새 인증키·비밀번호를 발급하지 않는다.
- 단기: 비밀번호 변경만으로는 이미 발급된 세션 쿠키·모바일 앱 토큰·고객사 SSO 연동 토큰이 살아남을 수 있으므로, **전체 수강생·관리자 계정의 활성 세션과 연동 토큰을 일괄 무효화**하고 안전한 환경에서 비밀번호 및 고객사 인사 연동 API 키를 재발급한다. 서버 내 웹셸·비인가 관리자 계정 등 지속성 흔적을 전수 점검해 침해가 확인되면 시스템을 재구축한다. 고객사(기업·금융사·공공기관) 보안팀은 유출된 임직원의 **이메일·사번·아이디**가 사내 그룹웨어·VPN 로그인 아이디와 동일한지 확인해 패스워드 스프레이·크리덴셜 스터핑 감시를 강화하고 피싱 저항 MFA를 적용한다.
- 장기: 외부 위탁 교육 플랫폼에 전달하는 임직원 정보에서 사번·세부 부서명·직급 등 불필요한 인사 속성 전달을 최소화(가명·고유 교육 식별자로 대체)하고, 위탁사 보안 실사와 대량 조회 차단 통제를 계약 요건으로 강제한다.
- 탐지: 고객사 사내 메일·메신저로 유입되는 부서·직급·사번 맞춤형 스피어 피싱과, 유출된 사번·이메일 계정에 대한 외부 VPN·웹메일 로그인 시도를 집중 모니터링한다.

**교훈**: 이름과 전화번호만 유출됐을 때보다 **'어느 회사 무슨 부서 누구(사번·직급)'**까지 함께 유출됐을 때가 기업 보안에는 훨씬 위험하다. 공격자가 그 회사의 실제 조직도와 직급 체계를 보고 내부 직원을 감쪽같이 속이는 표적 공격(스피어 피싱·헬프데스크 사칭)의 설계도로 쓸 수 있기 때문이다.

### [D20261113-github-ci] 탈취된 GitHub 계정 4,837개로 1,806개 저장소 오염 — 가짜 PR(`docs: dependency audit notes`)로 CI 시크릿 탈취 및 클라우드 IAM 백도어 설치
> 날짜: 캠페인 시작 2026-11-11 · 위협 분석 공개·보도 2026-11-12~13 · 유형: 개발자 계정 및 CI/CD 파이프라인 대규모 공급망 침해(실제 악용 확인) · 행위자: 미귀속(지난 10월 GhostAction 캠페인 피해 계정과 일부 중첩) · 지역: 전 세계(해외) · 근거: 확인(Aviatrix Threat Research Center 분석·The Hacker News 보도)

**쉽게 말하면**: 해커가 이미 훔쳐 둔 깃허브(GitHub) 개발자 계정 4,837개를 동원해, 전 세계 6만 개가 넘는 오픈소스·기업 코드 저장소에 '문서 점검 메모(`docs: dependency audit notes`)'라는 제목의 시험용 수정 요청(PR)을 자동으로 보내 어느 저장소를 마음대로 고칠 수 있는지 훑었습니다. 그중 수정 권한이 확인된 1,806개 이상의 저장소에 악성 자동화 작업(GitHub Actions)을 몰래 심어 클라우드(AWS·Azure·GCP) 접속 열쇠와 비밀 토큰을 싹쓸이한 뒤, 심지어 피해 회사가 나중에 비밀번호를 바꿔도 계속 들어올 수 있도록 클라우드의 '신뢰 정책(IAM)'까지 몰래 고쳐 놓았습니다.
**먼저 할 일(초보용)**: GitHub 저장소와 AWS·Azure·GCP 클라우드를 연동해 쓰는 개발·보안팀은 저장소에 `wfx-docs`라는 브랜치나 `docs: dependency audit notes` 제목의 PR, 또는 몰래 추가됐다가 되돌려진(revert) 커밋 기록이 없는지 즉시 검색하세요. 흔적이 있다면 **단순히 시크릿(비밀키)만 바꾸면 소용이 없으므로**, 먼저 안전한 기기에서 AWS IAM 역할의 신뢰 정책(Trust Policy)과 Azure(Entra ID)의 `wfx-ci-`로 시작하는 외부 연동 자격 증명을 찾아 삭제한 뒤 모든 클라우드 키·토큰·세션을 폐기하고 재발급하세요.

**개요**: 클라우드 보안 기업 Aviatrix의 위협연구센터(Threat Research Center)는 2026년 11월 12일, 지난 11월 11일부터 시작된 대규모 소프트웨어 공급망 및 CI/CD 시크릿 탈취 캠페인을 포착해 공개했다(The Hacker News 등 보도). 공격자는(지난 10월 발생한 'GhostAction' 캠페인 피해 계정과 일부 겹치는) 탈취된 **4,837개의 GitHub 계정 자격 증명**을 사용해 총 **61,764개 저장소**를 대상으로 `wfx-docs`라는 이름의 브랜치에서 `'docs: dependency audit notes'`라는 제목의 테스트 풀 리퀘스트(PR)를 자동으로 생성하며 쓰기(write) 권한 유무를 탐색했다. 쓰기 권한이 확인된 **1,806개 이상의 저장소**(공개 저장소 전체에서는 **8,093개**에서 악성 커밋 관측)에 대해 공격자는 기존 GitHub Actions 워크플로 파일이나 `npm postinstall` 훅에 시크릿 탈취 악성코드를 삽입했으며, 이는 npm·Go·Packagist·PyPI 패키지 생태계로도 빠르게 파급됐다. GitHub Actions 러너(Runner) 안에서 실행된 악성코드는 저장소의 GitHub Actions 시크릿, OIDC(OpenID Connect) 토큰, AWS·Azure·GCP 클라우드 자격 증명, SSH 키, 패키지 레지스트리 배포 토큰을 수확해 공격자 제어 서버(HTTP POST)와 텔레그램(Telegram) 채널로 빼돌린 뒤, **증거를 지우기 위해 악성 커밋을 즉시 되돌렸다(revert)**. 특히 공격자는 탈취한 클라우드 권한으로 **AWS IAM 역할의 신뢰 정책(Trust Policy)을 변조**하고 **Azure AD(현 Entra ID)에 `wfx-ci-` 접두사가 붙은 페더레이션 자격 증명(Federated Identity Credential)을 추가**해, 피해 조직이 추후 GitHub 시크릿이나 액세스 키를 교체하더라도 클라우드 접근 권한을 계속 유지하는 지속성 백도어를 심었다.

**왜 일어났나**

### [D20261113-apache-http2] Apache HTTP Server `mod_http2` 비인증 원격 코드 실행 결함(CVE-2026-119618, CVSS 9.8) 긴급 패치 — 병렬 요청 레이스 컨디션
> 날짜: Apache 2.4.71 패치 및 CVE 공개 2026-11-11 · 보안 업계 분석·대량 스캔 보도 2026-11-12~13 · 유형: 웹서버 HTTP/2 모듈 레이스 컨디션 및 힙 메모리 오염 원격 코드 실행(CVSS 9.8) · 행위자: — (대량 스캔 및 PoC 연구 포착, 실제 침투 악용은 미확인) · 지역: 전 세계(해외) · 근거: 확인(Apache Software Foundation·MITRE CVE·Red Hat 확인)

**쉽게 말하면**: 전 세계 웹사이트의 상당수가 사용하는 대표 웹서버 프로그램 '아파치(Apache HTTP Server)'의 고속 통신 기능(HTTP/2 모듈, `mod_http2`)에서, 해커가 로그인 없이 원격에서 서버를 장악할 수 있는 위험도 9.8점(10점 만점)짜리 치명적 결함(CVE-2026-119618)이 발견돼 긴급 패치(2.4.71 버전)가 나왔습니다. 동시에 여러 개의 요청을 빠르게 쏟아부어 서버가 요청 머리글(헤더)을 처리하는 순서를 꼬이게(레이스 컨디션) 만들면, 서버 메모리가 망가지면서 공격자가 원하는 명령어를 실행할 수 있습니다.
**먼저 할 일(초보용)**: Apache HTTP Server(2.4.55~2.4.70 버전)를 운영하는 관리자는 즉시 수정 버전인 **2.4.71 이상**(또는 우분투·레드햇 등 리눅스 배포판이 제공하는 최신 보안 백포트 패키지)으로 업데이트하세요. 당장 업데이트가 어렵다면 아파치 설정(`Protocols` 지시자)에서 `h2`와 `h2c`(HTTP/2 기능)를 임시로 빼서 HTTP/1.1로만 동작하게 바꾸고, 만약 비정상 크래시 등 침해가 의심된다면 패치 후 기존 웹 세션·인증키를 안전한 기기에서 교체하세요.

**개요**: 아파치 소프트웨어 재단(Apache Software Foundation)은 2026-11-11(현지시간) **Apache HTTP Server 2.4.71**을 배포하고, HTTP/2 프로토콜을 처리하는 `mod_http2` 모듈의 치명적 원격 코드 실행(RCE) 취약점 **CVE-2026-119618**(Red Hat 등 기준 **CVSS 9.8**, CWE-362)을 수정했다(MITRE CVE 공식 레코드 및 SecurityWeek·The Hacker News·BleepingComputer 11/12~13 보도). 이 취약점은 AI 기업 앤트로픽(Anthropic)의 오픈소스 스캐너(OSS Scanner)와 구글 클라우드 취약점 연구팀(Anthony Weems, Simon Scannell)이 공동으로 발굴·제보했다. 결함은 `mod_http2` 모듈의 `assign_headers()` 함수에서 공유 자원을 적절한 동기화 없이 동시에 실행할 때 발생하는 **레이스 컨디션(경쟁 조건)**이다. 서버에 HTTP/2(`h2` 또는 `h2c`)가 활성화되어 있을 때 인증되지 않은 원격 공격자가 특수 조작된 병렬 HTTP/2 요청을 보내면 서버의 힙(heap) 메모리를 오염시켜 임의 코드 실행(RCE)에 이를 수 있다. 영향 범위는 **Apache HTTP Server 2.4.55부터 2.4.70까지**(및 GitHub 독립 배포 `mod_h2` 2.0.8~2.0.42)다. 클라우드 보안 기업 Wiz는 다수의 클라우드 환경에 취약한 버전의 아파치 인스턴스가 노출돼 있다고 경고했으며, 11월 12일 기준 개념증명(PoC) 연구와 인터넷 대량 스캔 시도가 포착됐으나 실제 침투 악용은 아직 공식 확인되지 않았다.

**왜 일어났나**
- 직접 원인 [확인: Apache, MITRE CVE]: `mod_http2`의 `assign_headers()` 함수에서 병렬 HTTP/2 스트림의 헤더 처리 시 공유 자원에 대한 동기화(락·격리)가 불완전해 동시 실행 중 힙 메모리 오염이 발생했다.
- 구조적 원인 [추정 — 분석]: 하나의 연결 안에서 수많은 스트림을 동시에 다중화(multiplexing)해 성능을 높이는 HTTP/2 프로토콜의 특성상, C 언어로 작성된 웹서버 모듈에서 미세한 스레드 동기화 실수가 곧바로 비인증 원격 메모리 오염 및 코드 실행으로 이어지기 쉽다(본 보고서의 분석).

**침투 경로 [후보 — 대량 스캔 포착, 실제 침투 악용은 미확인]**: 외부에 노출된 Apache HTTP Server(HTTP/2 활성화 상태)에 조작된 동시 HTTP/2 요청을 전송해 `mod_http2` 레이스 컨디션 유발(T1190, 후보) → 힙 메모리 오염을 통해 웹서버 프로세스 권한으로 원격 코드·명령 실행(T1059, 후보). 실제 공격 침투 사례는 아직 공식 확인되지 않아 `후보`로 매핑한다.

**어떻게 조치하나** (벤더 권고 및 본 보고서 권고)
- 즉시: Apache HTTP Server를 **2.4.71 이상**(또는 독립 `mod_h2` 2.0.43 이상, Red Hat·Ubuntu·Debian·Amazon Linux 등 각 OS 배포판의 `CVE-2026-119618` 수정 패키지 — 당시 기준)으로 즉시 패치한다. 패치 전 아파치 에러 로그(워커 프로세스 세그멘테이션 오류·크래시 기록)와 접속 로그를 보존한다. 즉시 패치가 불가능한 운영 서버는 아파치 설정 파일의 `Protocols` 지시자에서 `h2` 및 `h2c`를 제거해 HTTP/2를 임시 비활성화하고 서비스를 재시작한다.
- 단기: 11월 11일 이후 아파치 워커 프로세스의 반복적인 비정상 종료(`AH00051: child pid ... exit signal Segmentation fault` 등)나 웹서버 계정(`www-data`, `apache` 등)이 실행한 비정상 하위 프로세스·웹셸 생성 흔적이 있는지 점검한다. 침해 정황이 발견되면 패치만으로는 불충분하므로 웹서버가 접근할 수 있었던 API 키·DB 비밀번호·TLS 개인키·세션 서명 키를 안전한 환경에서 전면 재발급하고 서버를 재구축한다.
- 장기: 웹서버 앞단의 CDN·리버스 프록시·WAF에서 비정상적인 고빈도 병렬 HTTP/2 스트림 생성 및 헤더 플러드 요청을 제한하고, 웹서버 프로세스를 컨테이너·최소 권한 샌드박스로 격리해 RCE가 발생하더라도 호스트 장악으로 번지지 않게 한다.

**개요**: 보안 연구자 압델하미드 나세리(Abdelhamid Naceri, 별칭 Nightmare Eclipse)가 2026년 11월 마이크로소프트 윈도우의 공통 로그 파일 시스템(CLFS, `clfs.sys`) 커널 드라이버를 겨냥한 새로운 로컬 권한 상승(LPE) 제로데이 기법 **'SignDrop'**의 분석과 작동하는 개념증명(PoC) 익스플로잇 코드를 공개했다(The Hacker News·BleepingComputer 11/12 보도). 윈도우의 `clfs.sys`는 최근 수년간 랜섬웨어 그룹과 APT 조직이 일반 권한에서 최고 권한으로 올라갈 때 가장 빈번하게 악용해 온 단골 표적이다. 마이크로소프트는 반복되는 CLFS 메모리 오염 공격을 막기 위해 드라이버 내에 로그 파일의 무결성을 검증하는 '로그 인증(log-authentication) 및 동반 파일(companion file)' 보안 메커니즘을 도입했는데, SignDrop은 바로 이 **보안 기능 자체를 공격 도구로 역이용**했다. 구체적으로 높은 권한(`SYSTEM`)을 가진 프로세스가 조작된 CLFS 로그 파일을 열 때 드라이버가 인증용 동반 파일을 자동 생성하는 과정에서, 공격자가 **경로 리디렉션(path redirection)** 기법을 써서 원래 허용되지 않은 임의의 시스템 경로에 파일이 생성·조작되도록 유도함으로써 프로세스 흐름을 가로채고 로컬 일반 사용자 권한에서 최고 권한인 **`NT AUTHORITY\SYSTEM`**을 획득한다. 공개 시점(11/12~13) 기준 마이크로소프트의 공식 CVE 번호나 보안 패치는 아직 발표되지 않은 상태다.

**왜 일어났나**
- 직접 원인 [확인: 연구자 PoC·보안매체 분석]: `clfs.sys` 드라이버가 로그 인증을 위해 동반 파일을 생성·처리할 때 객체 경로(path redirection 등)에 대한 검증이 불완전해, 특권 프로세스의 파일 생성 동작을 공격자가 지정한 경로로 유도할 수 있는 결함이 발생했다.
- 구조적 원인 [추정 — 분석]: 레거시 커널 드라이버(`clfs.sys`)의 근본 구조를 유지한 채 그 위에 사후 보완용 검증 로직(로그 인증 파일 생성)을 덧대면서, 새로 추가된 보안 코드가 오히려 커널 권한으로 파일을 생성해 주는 새로운 공격 표면(Gadget)이 된 역설적 사례다(본 보고서의 분석).

**침투 경로 [후보 — 공개 PoC 기준, 실제 공격 악용은 미확인]**: 로컬 일반 권한을 확보한 상태에서 조작된 CLFS 로그와 경로 리디렉션을 이용해 `clfs.sys`의 로그 인증 동반 파일 생성을 악용, `NT AUTHORITY\SYSTEM` 권한으로 상승(T1068, 후보). 실제 공격 캠페인에서의 악용은 아직 확인되지 않아 `후보`로 매핑한다.

**어떻게 조치하나** (본 보고서의 권고)
- 즉시: 현재 공식 패치가 없는 제로데이 상태이므로, 엔드포인트 보안 솔루션(EDR·백신)의 행위 기반 탐지 및 변조 방지(Tamper Protection) 기능을 최고 수준으로 유지하고 마이크로소프트의 공식 패치 발표를 모니터링해 출시 즉시 적용할 준비를 갖춘다. 침해 정황이 포착된 단말은 메모리·디스크·이벤트 로그를 보존한 뒤 즉시 격리한다.
- 단기: 이 취약점은 원격에서 단독으로 실행되는 것이 아니라 피싱·초기 침투 등으로 먼저 로컬 실행 권한을 얻어야 작동하므로, 애플리케이션 제어(AppLocker, WDAC) 및 공격 표면 축소(ASR) 규칙을 통해 일반 사용자 영역(`AppData`, `Temp` 등)에서의 비신뢰 실행 파일·스크립트 구동과 심볼릭 링크·정션(Junction) 악용을 차단한다. 만약 로컬 권한 상승 침해가 확인된 단말이 있다면 해당 PC에 캐시된 도메인 자격 증명·세션·토큰이 모두 탈취됐을 수 있으므로 안전한 환경에서 관련 계정 비밀번호·세션을 전면 폐기하고 단말을 재설치(재구축)한다.
- 장기: 업무상 불필요한 로컬 사용자 권한과 스크립트 실행 도구를 최소화하고, 커널 드라이버 취약점이 악용되더라도 측면 이동을 막을 수 있도록 로컬 관리자 비밀번호 개별 관리(LAPS) 및 특권 계정 분리(Tiering)를 적용한다.
- 탐지: 비특권 프로세스가 생성한 `.blf`·`.regtrans-ms` 등 CLFS 관련 파일에 대해 `SYSTEM` 프로세스가 접근하며 재분석 지점(Reparse Point / Object Manager 심볼릭 링크)을 통해 시스템 디렉터리에 파일을 생성하는 비정상 이벤트를 EDR에서 집중 탐지한다.

**교훈**: "보안을 강화하려고 넣은 기능(로그 인증 파일 생성)이 해커에게 최고 권한을 주는 지름길이 됐다"는 점은 보안 설계가 얼마나 정교해야 하는지 보여준다. 특히 CLFS는 랜섬웨어 조직들이 공개된 PoC를 불과 며칠 만에 자기들 공격 도구에 끼워 넣는 단골 영역이므로 패치 전까지는 초기 침투 차단과 EDR 행위 감시가 유일한 방패다.

### [D20261113-nodejs-http2] Node.js 보안 업데이트(16건): HTTP/2 다른 연결의 응답 메모리 노출(CVE-2026-123866) 및 파일 다운로드 취소 시 서버 강제 종료(CVE-2026-123863·123875) 수정
> 날짜: OpenJS Foundation 보안 권고·패치 및 CVE 공개 2026-11-11 · 보도 2026-11-12~13 · 유형: 서버 런타임(Node.js) HTTP/2 메모리 노출(UAF) 및 원격 서비스 거부(DoS) 등 16건 · 행위자: — (실제 악용 미확인) · 지역: 전 세계(해외) · 근거: 확인(Node.js 공식 보안 권고·MITRE CVE 확인)

**쉽게 말하면**: 수많은 웹 서비스와 앱의 백엔드 서버로 쓰이는 '노드제이에스(Node.js)'에서 한꺼번에 16개의 보안 결함을 고친 긴급 업데이트가 나왔습니다. 가장 위험한 것은 HTTP/2 통신 중 연결이 끊어질 때 이미 반납한 메모리를 다시 쓰는 결함(CVE-2026-123866)으로, 엉뚱하게 **다른 사용자의 통신 응답 내용(메모리 조각)이 공격자에게 섞여 전달될 수 있는 정보 노출 위험**이 있습니다. 또한 공격자가 로그인도 하지 않고 파일 다운로드를 요청했다가 취소하는 것만으로 서버 전체를 강제로 꺼버릴 수 있는 결함(CVE-2026-123863, CVE-2026-123875)도 함께 수정됐습니다.
**먼저 할 일(초보용)**: Node.js(22.x, 24.x, 26.x 계열)로 웹·API 서버를 운영하는 개발·인프라팀은 즉시 수정 버전(**v26.13.1, v24.22.3, v22.23.5 이상** — 당시 기준)으로 업데이트하세요. 특히 HTTP/2를 켜 둔 서버에서는 다른 이용자의 응답 데이터(토큰·개인정보 등)가 섞여 나갔을 가능성을 배제할 수 없으므로, 비정상 스트림 종료 로그가 많았다면 패치 후 주요 세션·토큰을 재발급하는 것이 안전합니다.

**개요**: OpenJS 재단(Node.js 프로젝트)은 2026-11-11 지원 대상 릴리스 라인 전반(26.x, 24.x, 22.x)에 걸쳐 총 **16건의 보안 취약점**을 수정한 보안 업데이트(**v26.13.1, v24.22.3, v22.23.5**)를 배포했다(MITRE CVE 공식 레코드 및 The Hacker News·Tenable·KISA 보호나라 11/12~13 공지·보도). 이번 패치에서 가장 주목해야 할 핵심 결함 3건은 모두 기본 HTTP/2 구현에서 발생했다.
1. **다른 연결의 응답 버퍼 메모리 노출 — CVE-2026-123866(Use-After-Free, 영향: 26.x, 24.x, 22.x)**: HTTP/2 스트림에서 쓰기(write) 작업이 배압(backpressure)으로 대기 중일 때 상대방(peer)이 `RST_STREAM`을 보내거나 서버 자체의 스트림 유휴 타임아웃 등으로 스트림이 해제되면, 스트림의 응답 버퍼 메모리는 해제(free)되지만 그에 대한 참조가 그대로 남는다. 그 결과 원래 보내려던 응답 대신 **이미 해제된 힙 메모리나 다른 연결(다른 사용자)의 응답 버퍼 내용**이 소켓에 기록돼 원격 상대방에게 그대로 노출될 수 있다. 특히 26.x(26.9.0 이후)와 24.x(24.22.0 이후)에서는 원격 클라이언트가 단독으로 이 조건을 유도할 수 있다.
2. **세션 종료 시 어설션 실패를 통한 원격 서버 강제 종료 — CVE-2026-123863(Reachable Assertion, 영향: 26.9.0~26.13.0, 24.22.0~24.22.2)**: 과거 CVE-2024-27983 패치가 놓친 변종 결함이다. 비인증 클라이언트가 요청 본문(body)이 끝나기 전에 서버가 먼저 응답하는 흔한 HTTP/2 핸들러를 상대로, `nghttp2`가 할당한 헤더 버퍼를 쥔 `Http2Stream`이 세션보다 오래 남도록 유도할 수 있다. 이후 `~Http2Session()` 소멸자가 실행될 때 메모리 계산값이 0이 아니어서 `CHECK_EQ(current_nghttp2_memory_, 0)` 어설션이 실패하며 Node.js 서버 프로세스 전체가 즉시 강제 종료(abort)된다.
3. **파일 다운로드 취소 시 NULL 포인터 역참조 서버 크래시 — CVE-2026-123875(NULL Pointer Dereference, 영향: 26.x, 24.x, 22.x)**: 서버가 `stream.respondWithFile()` 또는 `stream.respondWithFD()`로 파일을 전송하는 도중 비인증 클라이언트가 요청을 취소하면, 전송에 쓰이던 `StreamPipe` 해제 순서가 꼬이면서 NULL 포인터를 역참조해 프로세스가 즉시 종료된다. 특수 조작된 프레임조차 필요 없고 기본 파일 제공 서버에 몇 번 다운로드 취소를 반복하는 것만으로 서버를 멈추게 할 수 있다.

**왜 일어났나**
- 직접 원인 [확인: Node.js, MITRE CVE]: 비동기 입출력과 다중 스트림이 얽힌 HTTP/2 세션·스트림 해제(teardown) 과정에서 ① 배압 상태 버퍼의 생명주기 관리 오류로 인한 UAF(CVE-2026-123866), ② 세션 추적 목록에서 빠진 스트림의 미분리 및 어설션 검사 실패(CVE-2026-123863), ③ 파일 스트림 파이프 해제 순서 오류(CVE-2026-123875)가 발생했다.
- 구조적 원인 [추정 — 분석]: 단일 프로세스(이벤트 루프) 안에서 수천 명의 고객 요청과 메모리 풀을 함께 처리하는 Node.js 특성상, 스트림 해제 시점의 포인터·버퍼 관리 실수 하나가 프로세스 전체 중단(DoS)이나 고객 간 응답 메모리 혼선(Cross-connection leak)으로 이어질 수 있다(본 보고서의 분석).

**침투 경로 [후보 — 공개 시점 실제 악용 미확인, 취약점 메커니즘 기준]**: 외부에 노출된 Node.js HTTP/2 서버에 비정상 스트림 해제(`RST_STREAM` 등)를 유도해 다른 연결의 응답 버퍼 메모리를 열람(T1190, 후보)하거나, 요청 조기 응답·파일 다운로드 취소를 반복해 서버 프로세스를 강제 종료시켜 서비스 거부 유발(T1499, 후보). 실제 악용은 확인되지 않아 `후보`로 매핑한다.

**침투 경로 [확인 — Apify 공지 기준]**: 침해된 자격 증명을 이용해 Apify 내부 시스템에 비인가 로그인(T1078, 확인 — 최초 자격 증명 탈취 수단은 미공개) → 내부 시스템에서 다수 고객 계정의 자격 증명(API 토큰·프록시 비밀번호·2FA 관련 정보 등)에 접근·수집(T1552, 확인).

**어떻게 조치하나** (벤더 권고 및 본 보고서 권고)
- 즉시: Apify로부터 통지를 받았거나 해당 기간 플랫폼을 사용한 조직은 11월 9일~11일 사이 자사 Apify 계정에서 비정상 Actor 실행·스케줄 변경·데이터 내보내기 및 연결됐던 GitHub 비공개 저장소에 대한 비인가 접근 로그가 있는지 신속히 보존·점검한다. 침해가 의심되는 기기에서 새 비밀을 발급하지 않는다.
- 단기: Apify가 API 토큰·프록시 비밀번호를 강제 회전하고 GitHub OAuth 연동을 해제했더라도, 공격자가 **2FA 설정 정보**나 **고객이 Actor 환경변수·코드 안에 직접 적어 둔 제3자 서비스 비밀키(OpenAI·클라우드·사내 DB 키 등)**에 접근했을 가능성에 대비해야 한다. 따라서 ① 안전한 기기에서 Apify 콘솔의 **2FA를 즉시 초기화·재등록**하고 기존 웹 세션을 모두 로그아웃하며, ② Apify 환경변수(Secret)·스토리지에 저장해 두었던 모든 외부 API 키·크리덴셜을 별도로 전면 폐기·재발급한다. ③ GitHub 연동을 다시 연결할 때는 조직 전체가 아닌 꼭 필요한 단일 저장소에만 최소 권한으로 재승인한다.
- 장기: 외부 자동화·스크래핑 SaaS에 사내 핵심 DB나 클라우드 장기 자격 증명을 직접 저장하지 않고 단기 토큰·제한된 수집 전용 계정을 사용하며, 서드파티 OAuth 앱의 접근 범위를 정기 감사한다.
- 탐지: 11월 9일 이후 기존 Apify API 토큰이나 프록시 계정을 사용한 비정상 IP의 호출 시도 및 Apify에 저장됐던 타 서비스 API 키의 미승인 사용 이력을 모니터링한다.

**교훈**: 클라우드 자동화 서비스(Apify)가 고객의 API 토큰과 GitHub 연동을 빠르게 일괄 회수(강제 회전)한 조치는 2차 피해를 줄이는 모범적인 초동 대응이다. 그러나 이용자 입장에서는 플랫폼이 바꿔 준 'Apify 자체 토큰'만 믿고 끝낼 것이 아니라, **내가 그 플랫폼 안에 넣어 두었던 다른 서비스의 비밀키들**과 **2단계 인증(2FA) 시드**까지 직접 갈아 끼워야 진짜 마무리가 된다.

## 3. 교차 분석 — 오늘의 사례에서 보이는 패턴

> 선정된 국내외 8건의 공통점이며 전체 공격의 통계가 아니다.

1. **'비밀번호·시크릿만 바꾸면 끝'이라는 착각을 무너뜨리는 지속성과 2차 노출**: 오늘의 GitHub 4,837개 계정 캠페인(`D20261113-github-ci`)은 클라우드 시크릿과 OIDC 토큰을 훔친 뒤 곧바로 **AWS IAM 신뢰 정책과 Azure(Entra ID) 페더레이션 자격 증명(`wfx-ci-`)을 변조**해 두었다. 이 백도어를 먼저 지우지 않고 시크릿만 바꾸면 공격자는 바뀐 환경을 그대로 다시 장악한다. 또한 커밋을 즉시 되돌려(revert) 현재 코드 화면만 봐서는 침투 흔적이 보이지 않는다. Apify 침해(`D20261113-apify`) 역시 2FA 설정 정보까지 노출 우려가 제기돼 2FA 재등록이 함께 요구됐다.
2. **웹의 대문(HTTP/2)과 화상회의 서버에서 동시에 터진 비인증 치명적 결함**: 전 세계 웹서버의 기둥인 Apache HTTP Server(`D20261113-apache-http2`, CVE-2026-119618, CVSS 9.8)와 백엔드 런타임 Node.js(`D20261113-nodejs-http2`, CVE-2026-123866 등)에서 나란히 **HTTP/2 스트림·세션 처리의 비동기/동시성 메모리 결함(레이스 컨디션·UAF)**이 수정됐다. 여기에 자체 호스팅 화상회의 서버 Adobe Connect(`D20261113-adobeconnect`)에서도 CVSS 10.0 만점 결함 4건이 한꺼번에 공개됐다.
3. **'보안 기능'과 '주변 위탁·내부관리 시스템'의 역설**: Windows CLFS 제로데이 'SignDrop'(`D20261113-signdrop`)은 과거 해킹을 막으려고 추가한 '로그 인증 파일 생성' 기능을 거꾸로 이용해 `SYSTEM` 권한을 탈취했다. 국내에서는 대기업·은행·공공기관이 믿고 교육을 맡긴 삼성SDS 자회사 멀티캠퍼스(`D20261113-multicampus`, 약 7만 명)와 KB캐피탈의 자동차 임대자산관리시스템(`D20261113-kbcapital`, 1,811명)처럼 핵심 코어망이 아닌 **위탁 교육·부수적 자산관리 시스템**에서 임직원 사번·부서·직급·계정 정보가 대거 유출돼 표적형 2차 공격의 발판이 될 위험을 드러냈다.

## 6. 검증 수준과 한계

- CISA KEV 카탈로그를 2026-11-13 직접 조회한 결과 11-10 등재분 이후 신규 등재 항목은 없었다.
- Apache HTTP Server(`CVE-2026-119618`), Node.js(`CVE-2026-123863`, `CVE-2026-123866`, `CVE-2026-123875`), Adobe Connect(`CVE-2026-121351`, `CVE-2026-121352`, `CVE-2026-121353`, `CVE-2026-121354`, `CVE-2026-121355`, `CVE-2026-121356`, `CVE-2026-121896`) 취약점은 MITRE CVE 공식 API 레코드와 벤더 보안 권고를 직접 대조해 확인했다(일부 이차 요약 자료에서 Adobe Connect 결함으로 잘못 묶인 `CVE-2026-121389`는 MITRE 원문 확인 결과 FreeRDP 결함이어서 제외하고 실제 CVSS 10.0 결함인 `CVE-2026-121353`을 정확히 반영했다). 세 건 모두 공개 시점 실제 침투 악용은 공식 확인되지 않아 ATT&CK 매핑에서 `후보`로 구분했다. 수정 버전 번호는 발표 당시 기준이므로 실제 조치 시 각 벤더·OS 배포판의 최신 보안 권고를 재확인해야 한다.
- Windows CLFS 'SignDrop'(`D20261113-signdrop`)은 공개 시점 공식 CVE 번호와 마이크로소프트 패치가 부여되지 않은 상태이며, PoC 공개는 확인됐으나 실제 공격 악용은 미확인이어서 `후보`로 매핑했다.
- 국내 사건 중 멀티캠퍼스(`D20261113-multicampus`)와 KB캐피탈(`D20261113-kbcapital`)은 비인가 접근 및 정보 유출 사실과 규모·항목은 회사 공지·당국 신고로 확인됐으나, 최초 침투 기법(웹·API 취약점 여부 또는 계정 탈취 여부)이 공개되지 않아 지침에 따라 ATT&CK 기법을 추측으로 매핑하지 않았다.
- **ATT&CK 버전 확인 결과**: https://attack.mitre.org/tactics/enterprise/ 에서 현재 공식 버전이 **v20.1**임을 확인했다(작업 지침은 v19.2 기준, 본 저장소 카탈로그는 v20.0 기준). 전술 15개 체계는 동일하므로 임의 대규모 재매핑 없이 기존 카탈로그 범위에서 매핑했다.
- **독립 교차 검토**: 현재 실행 환경이 Gemini(Antigravity)여서 지침 8번에 따라 Gemini 자체 교차 검토를 수행해 사실관계·근거 표기·ATT&CK 전술-기법 일치·초보용 문장 정확성을 점검했다.
