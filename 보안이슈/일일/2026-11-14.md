**쉽게 말하면**: 카카오 그룹의 기업용 업무 메신저·협업 플랫폼인 '카카오워크'(운영사 디케이테크인) 시스템이 외부 해커에게 뚫려, 이를 사내 업무용으로 쓰는 카카오엔터프라이즈 전·현직 임직원과 외부 협업 인원 등의 개인정보뿐 아니라 **업무용 이메일 본문·제목과 메시지 첨부파일 원본**까지 유출됐습니다. 그동안 회사 측이 "자체 종단간 암호화(E3) 기술 덕분에 물리적 해킹이 일어나도 누구도 고객 데이터를 볼 수 없다"고 강조해 왔음에도 실제 메일 본문과 첨부파일 원본이 노출되면서 기업 내부 기밀과 2차 침투 위험에 대한 우려가 커졌습니다.
**먼저 할 일(초보용)**: 카카오워크 유출 통지를 받은 임직원·외부 협업자 및 메일 수신자는 감염되지 않은 안전한 기기에서 계정 비밀번호를 즉시 변경하고 기존 로그인 세션과 모바일 기기 연동을 모두 로그아웃(초기화)하세요. 특히 **유출된 업무 메일 본문이나 메신저 첨부파일 안에 사내 서버 접속 정보, API 키, 고객사 자료, 계약서 등이 들어 있었다면 계정 비밀번호만 바꿔서는 막을 수 없으므로** 해당 문서에 적혀 있던 모든 비밀키·접속 정보도 즉시 폐기·재발급하고, 실제 업무 대화를 인용한 정교한 사칭 메일(스피어 피싱)을 철저히 의심하세요.

**개요**: 카카오엔터프라이즈와 카카오워크 서비스 제공사인 **디케이테크인**(카카오 그룹 자회사)은 2026년 11월 12~13일 공식 홈페이지 공지를 통해, 지난 **11월 9일** 디케이테크인의 카카오워크 시스템에 외부 공격자의 비정상적인 접근이 발생해 일부 이용자의 개인정보 및 업무 관련 정보가 유출됐다고 발표하고 개인정보보호위원회와 한국인터넷진흥원(KISA)에 신고했다(보안뉴스·매일경제·한겨레·지디넷코리아·더일렉 11/13 보도). 유출 대상은 카카오엔터프라이즈 전·현직 임직원, 회사 계정을 이용한 외부 인원, 일부 메일 수신자 등이며 개인별 유출 항목과 범위는 상이해 세부 규모를 조사 중이다(현재까지 이용자 비밀번호 유출은 확인되지 않았다고 공지). 그러나 확인된 유출 항목에는 △이름 △닉네임 △소속 부서 △휴대전화번호 △이메일 주소 같은 기본 인적사항을 넘어 **△업무용 메일 본문 및 제목 △메일 첨부파일명 △암호화된 메시지 △메시지 내 첨부파일명 및 첨부파일 원본**이 포함됐다. 디케이테크인은 그동안 카카오워크가 기업용 종단간 암호화 보안 시스템 **'E3(Enterprise Endpoint Encryption)'**를 갖춰 "물리적 해킹에서도 정보 유출이 불가능하며 누구도 고객 데이터를 볼 수 없다"고 홍보해 왔으나, 이번 사고로 메일 원문과 첨부파일 원본이 노출되면서 암호화 적용 범위와 키·저장소 분리 설계에 대한 지적이 제기됐다. 한편 같은 날(11/13) 국내 다른 협업 플랫폼인 **NHN두레이(Dooray)**에서도 새벽 시간대 외부 비인가 계정 접근 시도와 API 키 비정상 호출이 포착돼 회사 측이 기존 서비스·관리자 API 키를 전량 폐기하고 API 서비스를 일시 차단하는 등 국내 업무용 협업툴 전반에 비상이 걸렸다.

**개요**: 미국 CISA는 2026-11-13(현지시간) **Check Point**의 다수 핵심 보안 제품(Quantum Security Gateway, Security Management Server, Multi-Domain Security Management Server, Scalable Platforms 등 R80.30~R82.20)에 영향을 미치는 로컬 권한 상승(LPE) 취약점 **CVE-2026-123039**(CVSS 7.8, CWE-732·CWE-862)를 실제 악용 확인 취약점 목록(KEV)에 긴급 등재하고, 미국 연방기관에 **포렌식 트리아지 수행 및 3일 이내(2026-11-16까지) 패치 완료**를 명령했다(Check Point 보안 권고 `sk1000362`, MITRE CVE 공식 레코드, Aviatrix·SecurityWeek·BleepingComputer 확인).

- **실제 공격 체인 및 와이퍼 파괴 [확인: Check Point, Aviatrix]**: 실제 관측된 공격 캠페인에서 위협 행위자들은 인터넷에 노출된 Check Point Security Gateway(특히 Mobile Access 포털)를 상대로 먼저 PHP 비인증 원격 코드 실행 취약점인 **PHP2Shell(`CVE-2026-109618`·`109619`, [D20261022-php2shell](2026-10-22.md))**을 악용해 침투하고 낮은 권한의 PHP 웹셸을 배포했다. 이어 본 제로데이(**CVE-2026-123039**)를 연쇄 실행해 `/tmp/dynamic_socket`을 통해 단숨에 `root` 권한을 획득했다. `root`를 장악한 공격자는 PhiliKit 악성코드 프레임워크 변종인 지속성 백도어 **`TSGA`**와 그 안에 내장된 네트워크 중계 도구 **`TSProxy`**를 설치해 은밀한 내부망 진입로를 확보했으며, 일부 파괴적 공격 물결에서는 침해된 Check Point 게이트웨이에서 SSH를 통해 내부 **VMware ESXi 하이퍼바이저**로 횡적 이동한 뒤 파괴형 와이퍼 악성코드 **`destroy_v6`**를 실행해 가상화 스토리지를 재귀적으로 삭제·초토화했다(앞서 10월 말 `[D20261029-php2shellroot]`에서는 PHP2Shell과 리눅스 커널 결함 Fragnesia `CVE-2026-46300`의 결합이 확인됐는데, 이번에는 Check Point 자체 데몬 결함 `CVE-2026-123039`와의 결합 및 ESXi 와이퍼 파괴 체인이 추가로 규명됐다).

### [D20261114-unrealircd-kev] UnrealIRCd `labeled-response` 모듈 서버 간 명령 주입 취약점(CVE-2026-114713) 실제 악용 및 CISA KEV 등재
> 날짜: 벤더 패치(`6.2.7.1`·핫패치) 및 CVE 공개 2026-11-07~08 · CISA KEV 등재 2026-11-13(연방기관 패치 기한 11-16) · 유형: IRC 서버 구분자 무력화 미흡을 통한 최고 서버 권한 명령 주입(실제 악용 확인) · 행위자: 미귀속 · 지역: 전 세계(해외) · 근거: 확인(UnrealIRCd 공식 보안 권고·CISA KEV·MITRE CVE 확인)

**쉽게 말하면**: 전 세계 오픈소스 커뮤니티와 기업·기관 내부 채팅망에서 널리 쓰이는 대표 IRC 채팅 서버 프로그램 '언리얼아이알씨디(UnrealIRCd)'에서, 아무 권한 없는 일반 접속자가 채팅 메시지 꼬리표(`label`)에 특수 문자를 섞어 보내는 것만으로 **서버 전체의 최고 권한 명령을 마음대로 내릴 수 있는 치명적 결함(CVE-2026-114713)**이 실제 해킹에 악용돼 미국 CISA가 긴급 패치 명령(KEV, 기한 11월 16일)을 내렸습니다. 서버가 2대 이상 연결된 채팅망에서 이 공격이 성공하면, 해커가 관리자나 전체 이용자를 네트워크에서 강제로 쫓아내거나(`KILL`·`GLINE`) 채팅망 전체의 제어권을 빼앗을 수 있습니다.
**먼저 할 일(초보용)**: UnrealIRCd(6.0.0~6.2.7 버전)를 운영하는 관리자는 서버를 재시작하지 않고도 즉시 고칠 수 있는 무중단 핫패치 명령(`./unrealircd hot-patch bundle-20261107`)을 실행하거나 **6.2.7.1 이상**(당시 기준)으로 즉시 업그레이드하세요(기한 11월 16일). 당장 패치가 어렵다면 설정 파일에 `blacklist-module "labeled-response";`를 추가하거나 스팸필터 차단 규칙을 적용하고, 이미 비정상 서버 명령이 실행된 흔적이 있다면 패치 후 운영자(IRCOp) 비밀번호와 서버 간 연동 비밀번호(Link block password)를 안전한 기기에서 교체하세요.

**개요**: 오픈소스 IRC 데몬 프로젝트인 **UnrealIRCd**는 지난 2026-11-07~08 보안 권고 및 버전 **6.2.7.1**을 공개해 **CVE-2026-114713**(CVSS 8.6, CWE-140 구분자 무력화 미흡)을 포함한 보안 취약점들을 수정했으며, 미국 CISA는 이 취약점이 실제 야생에서 악용(actively exploited)되고 있음을 확인해 2026-11-13 KEV 카탈로그에 등재했다(기한 2026-11-16, UnrealIRCd 공지·MITRE CVE·CISA KEV 확인). 결함은 UnrealIRCd 6.0.0부터 6.2.7까지의 IRCv3 `labeled-response` 모듈(`src/modules/labeled-response.c`의 `labeled_response_mtag_is_ok()` 함수)에 존재한다. 이 모듈은 클라이언트가 보낸 IRCv3 `label` 메시지 태그를 응답 메시지에 그대로 되돌려(echo) 주는데, 이때 줄바꿈·공백·세미콜론 같은 구분자(delimiter)를 제대로 검증·이스케이프하지 않았다. 그 결과 **2대 이상의 서버가 서로 연결(linked)된 IRC 네트워크**에서 권한이 전혀 없는 일반 사용자라도 조작된 `label` 태그를 보내 **서버 간(server-to-server) 프로토콜 명령을 몰래 주입**할 수 있으며, 상대 서버는 이를 일반 사용자의 채팅이 아니라 **연결된 신뢰 서버가 내린 최고 권한 명령(server authority)**으로 오인해 그대로 실행한다. 실제 악용 시 공격자는 전체 네트워크에서 정상 운영자와 사용자를 영구 추방(`GLINE`)하거나 연결을 강제 종료(`KILL`)하고 채널·권한 상태를 임의로 조작할 수 있다.

**왜 일어났나**
- 직접 원인 [확인: UnrealIRCd, MITRE CVE]: `labeled-response` 모듈의 `labeled_response_mtag_is_ok()`가 클라이언트가 입력한 `label` 태그의 구분자를 이스케이프하지 않은 채 서버 간 통신 스트림에 그대로 반영(echo)해 명령 주입(CWE-140)을 허용했다.
- 구조적 원인 [추정 — 분석]: 분산 IRC 네트워크는 연결된 서버끼리의 통신(Server-to-Server 프로토콜)을 전적으로 신뢰하는 구조여서, 클라이언트 입력 태그가 구분자 검증 없이 서버 간 프로토콜 줄(line)로 넘어가는 순간 일반 사용자 입력이 곧바로 최고 서버 권한 명령으로 둔갑한다(본 보고서의 분석).

- 구조적 원인 [추정 — 분석]: 오늘날 수많은 SaaS 서비스들이 자체 AI 기능을 구현할 때 하나의 모델이 아니라 여러 하위 AI 추론 공급사(Inference Provider)로 프롬프트를 중계(라우팅)하는 다단계 AI 공급망 구조를 쓴다. 이때 원청 SaaS와 하위 추론 공급사 사이에 '데이터 무보관(Zero-retention)' 계약이 맺어져 있더라도, 하위 공급사의 개발·디버깅 로깅 설정 실수 하나로 고객 프롬프트가 디스크에 고스란히 쌓여 해킹 표적이 될 수 있다(본 보고서의 분석).

**침투 경로 [확인 — Notion·Fireworks AI 발표 기준]**: 서드파티 AI 추론 공급사(Fireworks AI)의 클라우드 개발·R&D 환경을 침해해 클라우드 내에 보관돼 있던 데이터셋·모델 가중치 및 미삭제 Notion AI 채팅 기록에 접근(T1530, 확인). (Fireworks AI 개발 클라우드의 최초 침투 수단은 미공개여서 매핑하지 않는다.)

**어떻게 조치하나** (벤더 권고 및 본 보고서 권고)
- 즉시: Notion으로부터 개별 통지를 받은 워크스페이스 관리자는 통지 내역을 확인하고 관련 워크스페이스 감사 로그·AI 사용 기록을 신속히 보존하며, 해당 워크스페이스 구성원들에게 10월 말 이전 Notion AI 대화창에 입력한 민감 정보 유무를 즉시 파악하도록 공지한다. 침해가 의심되는 환경에서 새 비밀을 발급하지 않는다.
- 단기: 노출된 채팅 기록에 작성자·조직 이름표(메타데이터)가 없더라도, **프롬프트 텍스트 안에 적힌 AWS 키(`AKIA...`), GitHub 토큰(`ghp_...`), 사내 도메인 주소, API 엔드포인트와 비밀번호는 공격자가 정규식 검색만 돌리면 주인이 누구인지 몰라도 즉시 자동 악용할 수 있다.** 따라서 구성원이 코드 디버깅이나 문서 요약을 시키면서 Notion AI에 붙여 넣었을 가능성이 있는 모든 API 키·비밀번호·토큰을 안전한 기기에서 즉시 폐기·재발급한다.
- 장기: 사내 생성형 AI 및 협업툴 AI 활용 지침에 **"계약상 비학습·무보관(Zero-retention) 엔터프라이즈 요금제라도 AI 프롬프트 창에 실제 운영 환경의 비밀키·비밀번호·고객 개인정보 원문을 절대 입력하지 않는다"**는 원칙을 명시하고, DLP(데이터 유출 방지)나 브라우저 확장으로 AI 입력창 내 시크릿 패턴 전송을 사전 차단한다. 또한 SaaS 도입 시 하위 AI 추론 공급사(Sub-processor) 목록과 실제 로깅 비활성화 감사 결과를 확인한다.
- 탐지: 과거 문서·메모나 AI 채팅에 언급됐던 내부 API 키·서비스 계정의 비정상 외부 IP 호출 여부를 모니터링한다.

**교훈**: 이번 사고는 기업 보안 담당자들이 흔히 믿는 **"우리 SaaS는 Zero-Data-Retention(데이터 무보관) 계약을 맺었으니 AI에 기밀을 넣어도 서버에 안 남는다"**는 믿음이 왜 위험한지 증명한 대표 사례다. 계약서에는 '무보관'이라고 적혀 있어도 하위 AI 공급사의 개발 서버 설정 실수 하나로 대화록이 남아 털릴 수 있으며, 이름표가 없어도 대화 속에 적힌 API 키는 그 자체로 열쇠 구실을 한다.

### [D20261114-facestealer-fbi] 미 법무부·FBI, 북한 해커의 가짜 화상회의 사칭 캠페인 '페이스스틸러(FaceStealer)' 인프라 압수(4억 달러 탈취·웹캠 영상 900개 확보) 및 바이낸스 해킹 탈취 자산 27억 달러 동결
> 날짜: 미 법무부(DOJ)·FBI 발표 2026-11-12(현지시간) · 국내외 보도 2026-11-13 · 유형: 지인 계정 탈취 + 이전 피해자 웹캠 영상·딥페이크 가짜 화상회의 사회공학 캠페인 및 가상자산 탈취 · 행위자: 북한 연계 해커 조직(바이낸스 사건은 북한 'TraderTraitor' 공식 귀속) · 지역: 전 세계(해외) · 근거: 확인(미 법무부 DOJ·FBI 공식 발표, SecurityWeek·데일리시큐 확인)

**쉽게 말하면**: 미국 법무부와 연방수사국(FBI)이 최근 18개월 동안 가짜 화상회의로 가상자산 업계 종사자와 오픈소스 개발자들을 속여 **4억 달러(약 5,600억 원) 이상**을 훔친 북한 해커들의 '페이스스틸러(FaceStealer)' 서버를 압수했습니다. 해커들은 먼저 해킹한 지인의 텔레그램·링크드인 계정으로 연락해 줌(Zoom)·팀즈 같은 화상회의로 불러낸 뒤, **이전에 해킹당한 사람들의 실제 웹캠 녹화 영상(압수 서버에서 900개 이상 발견)이나 딥페이크 영상**을 화면에 틀어 안심시키고 "목소리가 안 들린다"며 악성 프로그램을 깔게 만들었습니다. 한편 미국 정부는 같은 날 지난 10월 말 북한이 바이낸스에서 훔쳐 간 60억 달러대 가상자산 중 **27억 달러 이상을 동결하고 12억 달러 이상에 대해 법원 압류 승인**을 받았다고 발표했습니다.
**먼저 할 일(초보용)**: 평소 알고 지내던 지인의 텔레그램·링크드인·슬랙·디스코드 계정에서 화상회의 초대가 오더라도, 회의 도중 **"오디오·마이크나 카메라가 안 되니 업데이트·오류 해결 프로그램을 설치하라"**는 안내가 뜨면 100% 해킹이므로 즉시 창을 닫고 절대 실행하지 마세요. 만약 이미 프로그램을 실행했다면 **즉시 그 컴퓨터의 인터넷(랜선·와이파이)을 끊고**, 그 컴퓨터가 아닌 **다른 안전한 기기**에서 가상자산 지갑 자산을 옮기고 메신저·GitHub·클라우드 계정의 비밀번호와 모든 로그인 세션·토큰을 폐기하세요.

**개요**: 미국 법무부(DOJ)와 연방수사국(FBI)은 2026-11-12(현지시간) 북한 해커들이 가상자산 탈취 및 소프트웨어 공급망 침투에 사용해 온 **'페이스스틸러(FaceStealer)'** 캠페인의 클라우드 인프라를 압수했다고 발표하고, 같은 날 별도 발표를 통해 지난 10월 말 발생한 역대 최대 바이낸스 해킹([D20261030-binance](2026-10-30.md), [D20261104-binance](2026-11-04.md)) 탈취 자금에 대한 대규모 동결·압류 조치를 공개했다(DOJ·FBI 발표, SecurityWeek·데일리시큐 11/13 보도).
1. **'페이스스틸러(FaceStealer)' 캠페인 수법과 피해 규모 [확인: DOJ, FBI]**: FBI에 따르면 북한 해커들은 최근 18개월 동안 이 수법으로 **4억 달러 이상의 가상자산**을 탈취했다(바이낸스 사건과는 별도 집계). 공격은 앞선 피해자에게서 탈취한 실제 지인의 텔레그램·링크드인·슬랙·디스코드 계정으로 접근해 협업이나 투자를 제안하면서 시작된다. 피해자가 수락하면 줌(Zoom), 마이크로소프트 팀즈(Teams), 구글 미트(Google Meet)로 위장한 가짜 화상회의 웹페이지로 초대한다. 회의 화면에는 **이전 피해자에게서 몰래 녹화한 실제 웹캠 영상(FBI가 압수 인프라에서 900개 이상 확보)**이나 가상자산 업계 유명 인사를 흉내 낸 **딥페이크 영상**이 재생된다. 화면에 아는 얼굴이 나타나 피해자가 경계를 풀면, 공격자는 "목소리가 들리지 않는다"는 식으로 오디오 오류를 꾸며 '해결 프로그램(패치·SDK·스크립트)' 실행을 유도한다. 피해자가 이를 실행하면 악성코드가 설치돼 가상자산 지갑·업무 시스템 접근권은 물론 **새 피해자의 웹캠 영상과 연락처까지 수집돼 다음 피해자를 속이는 미끼로 재사용**되는 연쇄 구조다. 특히 FBI는 일부 사례에서 **최초 감염 후 수개월~1년 이상 잠복**한 뒤에야 자산 탈취가 일어났으며, 최근에는 코드 저장소 장악(공급망 공격)을 노리고 **오픈소스 소프트웨어 개발자와 유지관리자(Maintainer)**로 표적을 확대했다고 경고했다.
2. **바이낸스 해킹 탈취 자산 27억 달러 동결 및 12억 달러 압류 승인 [확인: DOJ, FBI]**: 미 법무부는 같은 날(11/12), 지난 10월 29일경 북한 해킹 조직 **'트레이더트레이터(TraderTraitor)'**가 바이낸스에서 60억 달러 이상의 가상자산을 탈취한 사건(`D20261104-binance`)과 관련해, 미국 정부와 민간 가상자산 사업자들이 협력해 탈취 자산 중 **27억 달러(약 3조8,000억 원) 이상을 동결(freeze)**했으며 이 가운데 **12억 달러 이상을 압류하거나 처분을 제한(seize/restrain)할 수 있도록 법원 승인**을 받았다고 발표했다. 공격자들은 탈취 자산을 주로 이더(ETH)로 바꾼 뒤 브리지·믹서·거래소를 통해 세탁을 시도 중이다.

**왜 일어났나**
- 직접 원인 [확인: DOJ, FBI]: 실제 지인의 탈취된 메신저 계정과 실제 웹캠 녹화본·딥페이크 영상을 결합한 고도의 사회공학(스피어피싱)으로, 피해자가 가짜 화상회의 사이트에서 오류 해결 프로그램으로 위장한 악성코드를 직접 실행하도록 유도했다.
- 구조적 원인 [추정 — 분석]: (1) "화면으로 얼굴을 보고 통화하면 진짜 본인일 것"이라는 인간의 직관적 신뢰를 웹캠 녹화본(900개 이상 수집)과 딥페이크로 무너뜨렸다 (2) 감염 직후 바로 돈을 빼가지 않고 수개월~1년 이상 조용히 잠복하며 지갑 키나 오픈소스 저장소 권한이 열릴 때를 기다리기 때문에, 피해자가 "며칠 전에 눌렀던 회의 링크"와 "1년 뒤 발생한 해킹"을 연결해 알아차리기 어렵다(본 보고서의 분석).

**침투 경로 [확인 — 미 법무부·FBI 발표 기준]**: 탈취한 지인의 텔레그램·링크드인·슬랙·디스코드 계정으로 접근해 가짜 화상회의 링크로 유인하는 스피어피싱 수행(T1566.003, 확인) → 가짜 화상회의 화면에서 이전 피해자 웹캠 영상·딥페이크를 재생하며 오디오 오류 해결 프로그램으로 위장한 악성코드를 피해자가 직접 실행하도록 유도(T1204.002, 확인) → 감염된 단말에서 피해자의 웹캠 영상을 수집해 다음 사칭 공격용으로 확보(T1125, 확인) → 수개월~1년 잠복 후 가상자산 지갑 등에 접근해 총 4억 달러 이상의 가상자산 탈취(T1657, 확인).

**어떻게 조치하나** (FBI 권고 및 본 보고서 권고)
- 즉시: 화상회의 접속 중 외부 프로그램·스크립트·드라이버 설치나 터미널 명령 실행을 요구받아 이를 실행한 적이 있다면(비록 수개월 전이라도), 해당 PC를 즉시 네트워크에서 격리하고 메모리·디스크·시작프로그램(런치에이전트·예약작업 등) 포렌식 증거를 보존한다. 침해된 기기에서 새 지갑이나 비밀번호를 생성하지 않는다.
- 단기: **감염 후 1년 넘게 잠복하는 특성이 확인됐으므로, 과거 한 번이라도 '오디오 안 들림' 화상회의를 겪은 단말은 현재 증상이 없더라도 이미 침해된 것으로 간주해야 한다.** ① 감염 의심 단말이 아닌 **완전히 분리된 안전한 기기**에서 가상자산 지갑의 자산을 새 하드웨어 지갑(콜드월렛)으로 즉시 이전하고, 기존 지갑 시드 구문·개인키를 폐기한다. ② 안전한 기기에서 텔레그램·링크드인·슬랙·디스코드·GitHub·클라우드 계정의 비밀번호를 변경하고 **기존 발급된 모든 활성 세션·OAuth 토큰·SSH 키·PAT를 전량 회수(무효화)**하며, 피해 단말은 운영체제를 포맷 후 재설치(재구축)한다. ③ 내 웹캠 영상이 녹화돼 지인들을 속이는 데 악용될 수 있으므로 주요 거래처·동료들에게 사칭 주의 공지를 보낸다.
- 장기: 화상회의는 브라우저 웹 링크 대신 공식 설치된 정식 클라이언트 앱이나 사내 표준 테넌트에서만 접속하도록 통제하고, 오픈소스 유지관리자·가상자산 서명 담당자는 일반 메신저·웹서핑용 PC와 코드 서명·지갑 관리용 기기를 물리적으로 분리한다.

## 6. 검증 수준과 한계

- CISA KEV 카탈로그를 2026-11-14 직접 조회해 11-13 신규 등재된 2건(`CVE-2026-123039` Check Point, `CVE-2026-114713` UnrealIRCd)과 MITRE CVE 공식 레코드(`CVE-2026-123039`, `CVE-2026-114713`, `CVE-2026-120868`, `CVE-2026-107412`)를 1차 대조해 확인했다. 수정 버전 번호는 발표 당시 기준이므로 실제 조치 시 각 벤더의 최신 보안 권고를 재확인해야 한다.
- Qubole 공급망 침해 및 익스피디아 협박 사건(`D20261114-qubole-expedia`)에서 Qubole의 AWS 교차 계정 IAM 역할 악용 메커니즘과 익스피디아의 '서드파티 데이터 플랫폼 신뢰 접근 악용' 사실은 보안 연구기관(Sentra·Wiz·Mandiant) 및 익스피디아 입장문으로 확인됐으나, 갈취 그룹 `n0n`이 주장한 '익스피디아 레코드 약 10억 건(로열티 8.3억 건 등)' 수치는 공격자의 일방 주장(`[주장]`)이어서 확인된 사실과 엄격히 분리해 기술했다.
- 바라쿠다 내부 클라우드 침해(`D20261114-barracuda-cloud`)에서 외부 협력사 개발 환경 침해를 통한 키 유출 경위는 바라쿠다의 분석상 추정(`[추정]`)을 그대로 반영해 매핑(`T1199|추정`)했으며, AI 도구 'ARTEX' 사용 가능성 역시 동작 패턴 일치에 기반한 분석 단서임을 명시했다.
- 국내 사건 중 카카오워크(`D20261114-kakaowork`)는 비정상 접근 및 메일 본문·첨부파일 원본 유출 사실은 공식 확인됐으나 최초 침투 경로가 조사 중이어서 지침에 따라 ATT&CK 기법을 추측으로 매핑하지 않았다. 반면 '모두의 창업' 아미쿠스렉스(`D20261114-moduchangup`)는 KISA 신고 내역 보도에서 관리자 페이지 SQL 삽입 및 취약 API 악용이 구체적으로 확인돼 이를 반영했다.
- **ATT&CK 버전 확인 결과**: https://attack.mitre.org/tactics/enterprise/ 에서 현재 공식 버전이 **v20.1**임을 확인했다(작업 지침은 v19.2 기준, 본 저장소 카탈로그는 v20.0 기준). 전술 15개 체계는 동일하므로 임의 대규모 재매핑 없이 기존 카탈로그 범위에서 매핑했다.
- **독립 교차 검토**: 현재 실행 환경이 Gemini(Antigravity)여서 독립 교차 검토 기준에 따라 자체 교차 검토를 수행해 사실관계·근거 표기·ATT&CK 전술-기법 일치·초보용 문장 정확성을 점검했다.
