   - 그러자 `Cairn` 내부의 AI 에이전트들은 인간의 세부 지시 없이 스스로 표적 대학교 서버에서 돌아가던 오픈소스 의료 영상 AI 애플리케이션 **'MONAI Label'**의 API 엔드포인트들을 매핑·탐색했고, **단 11분 만에 이전에 알려지지 않았던 '경로 조작 및 임의 파일 업로드(Path-Traversal / File-Upload) 제로데이 취약점'을 독자적으로 찾아내 무기화**했다. 에이전트는 의도된 저장 디렉터리 바깥의 시스템 경로에 악성 파일을 써넣어 코드를 실행시켰고, 이어진 세션에서 **표적 대학교 서버의 최고관리자(`root`) 권한을 완전히 장악**했다.
   - **패치 미출시 주의**: 아마존 보고 시점 기준, 해당 취약점을 수정하는 코드는 MONAI Label의 소스코드 저장소(GitHub)에는 병합(merged)됐으나 **아직 공식 패치 릴리스 버전으로 패키징돼 배포되지 않은 상태**여서 운영자들의 즉각적인 접근 차단과 우회 조치가 요구된다.
2. **캐나다 최대 통신사 '벨 캐나다(Bell Canada)', '에이전틱(Agentic) 위협 행위자'에 의한 기업 회선 관리 테스트 시스템(`Maximo`) 침해 공식 확인 [확인: Bell Canada 공식 성명 및 고객 통지, BleepingComputer, CBC]**:
   - 벨 캐나다는 지난 **11월 17일** 자사가 **'에이전틱 위협 행위자(agentic threat actor — 인간 개입을 최소화한 채 다단계 탐색·침투 작업을 자율 수행하는 AI 기반 공격자)'**로 규정한 주체에 의해 시스템 침해가 발생했다고 11월 20~21일 공식 확인했다.
   - 침해당한 대상은 통신 네트워크 회선(circuit)을 주문·개통(provisioning)하는 데 쓰이는 **IBM Maximo 시스템의 사전 운영(pre-production / 테스트) 환경**이었다. 이로 인해 기업 고객(Enterprise customers)들의 **△업무용 연락처(이름·직함·회사 이메일·전화번호·사업장 주소) △티켓 제목 △특정 네트워크 요소(Network Element)의 IP 주소**가 외부로 유출됐다(비밀번호·자격 증명이나 첨부 PDF 파일은 포함되지 않았으며, 회사는 캐나다 사이버보안센터 CCCS 및 연방경찰 RCMP에 침해 지표 IOC를 공유했다).
3. **유럽연합 집행위원회(European Commission), 공개 AI 도구를 악용한 사이버 공격으로 인사·의료비 환급 등 내부 행정 앱 중단 사실 공식 확인 [확인: EU 집행위 대변인 발표 / 보도: 데일리시큐 209641 등]**:
   - 토마 레니에(Thomas Regnier) EU 집행위원회 대변인은 지난 10월 22일 이상 징후를 감지해 10월 26일 확인한 내부 사이버 공격이 **"공개적으로 이용 가능한 AI 도구(publicly available AI tools — 보도상 오픈소스 AI 침투 프레임워크 `ARTEX` 등 지목)"**를 악용해 감행됐다고 공식 확인했다. 이 공격으로 확산 방지를 위해 집행위의 인사 플랫폼(`Sysper`), 의료비 환급 포털(`MyPMO`), 내부 번역 서비스 등 주요 행정 앱들이 일시 중단(일부는 10일 이상 차질)됐으며, 현재 복구됐고 대규모 직원 데이터 유출이나 랜섬웨어 증거는 발견되지 않았다고 밝혔다.

**왜 일어났나**
- 직접 원인 [확인: Amazon Threat Intelligence, Bell Canada, EU 집행위]: (1) 동아시아 대학교 연구 서버에서 구동 중이던 의료 영상 AI 서버 `MONAI Label`에 파일 업로드 시 경로 조작을 허용하는 미발견 결함이 존재했고, 공격자의 `Cairn` AI 에이전트가 이를 11분 만에 자율 발굴·악용했다 (2) 벨 캐나다는 기업 회선 개통용 `Maximo`의 테스트(pre-production) 환경이 외부 공격에 노출돼 있었고 (3) EU 집행위 역시 외부 접점 시스템이 공개 AI 침투 도구의 자동화 공격을 받았다.
- 구조적 원인 [추정 — 분석]: (1) **'AI 연구용 서버(MONAI Label)가 AI 공격 도구(Cairn)의 가장 손쉬운 먹잇감이 되는 역설'**: 대학과 병원의 AI 연구자들은 고성능 GPU 서버에 `MONAI Label`, `Jupyter`, `Gradio` 같은 오픈소스 AI 도구를 빠르게 띄워 외부에서 접속해 쓰지만, 이러한 연구용 웹 도구들은 전통적인 엔터프라이즈 소프트웨어보다 입력값 검증(경로 조작 방지 등)이 허술해 자율형 AI 에이전트가 API 명세만 읽고도 10여 분 만에 제로데이를 뚫어낼 수 있다 (2) 벨 캐나다 사건은 어제 다룬 라쿠텐증권 테스트 환경(447만 계좌 노출 우려, `D20261118-fugaku-rakuten`)이나 코펜하겐대 테스트 환경(54.5만 명 노출, `D20261027-copenhagen`)과 똑같이, **'테스트(Pre-production) 환경에 실제 기업 고객 연락처와 핵심 통신망 장비 IP 주소를 넣어 두고 보안 통제는 운영망보다 느슨하게 한 관행'**이 자율형 AI 스캐너의 표적이 됐음을 보여준다(본 보고서의 분석).

**침투 경로 [확인 — Amazon Threat Intelligence·Bell Canada·EU 집행위원회 공식 발표 기준]**: 공격자가 오픈소스 자율형 AI 침투 프레임워크(`Cairn` 등)를 구동해 표적 대학교의 `MONAI Label` 의료 영상 서버 API를 자동 탐색하고 11분 만에 경로 조작·파일 업로드 제로데이 익스플로잇을 자율 개발(T1595, T1587.004, 확인) → 인터넷에 노출된 `MONAI Label` 서버의 제로데이 취약점, Bell Canada의 `Maximo` 사전 운영(테스트) 환경, EU 집행위 외부 접점 시스템을 공격해 초기 침투(T1190, 확인) → (`MONAI Label` 건) 저장 디렉터리 외부 시스템 경로에 파일을 써넣어 악성 코드를 실행하고 대학교 서버의 최고관리자(`root`) 권한 장악(T1059, 확인) → (`Bell Canada` 건) `Maximo` 테스트 환경에서 기업 고객 업무 연락처·티켓 제목 및 통신 네트워크 요소 IP 주소 수집·반출(T1213, 확인).

**어떻게 조치하나** (연구기관·벤더 권고 및 본 보고서 권고)
- 즉시: (1) **MONAI Label 운영 대학병원·의과대학·연구소**: `MONAI Label` 서버의 외부 인터넷 직접 노출을 즉시 차단(방화벽에서 격리 및 내부 VPN 전용 전환)하고, 웹·API 접근 로그와 시스템 파일 변경 기록을 보존한다. 아직 정식 패치 릴리스가 패키징되지 않았으므로 **MONAI Label 공식 GitHub 저장소의 경로 조작 수정 커밋(main 브랜치 픽스)을 즉시 수동 적용하거나 정식 패치 버전 출시 전까지 외부·비신뢰 네트워크 접근을 전면 중지**한다. (2) **Bell Canada 기업 고객 및 통신·인프라 기업**: 유출된 '네트워크 요소 IP 주소'와 '티켓 제목·담당자 실명/직함'을 악용한 통신사 엔지니어 사칭 표적 공격 및 해당 IP 대역에 대한 직접 스캔 공격에 대비해 경계 방화벽 ACL을 즉시 점검한다.
- 단기: **이미 AI 에이전트가 11분 만에 `root` 권한을 획득하는 공격이 지난 9월부터 동아시아 대학들을 덮쳤으므로, 패치나 격리만으로 끝나지 않는다.**
  1. **대학·병원 AI 연구 서버 포렌식 및 재구축**: `MONAI Label`이 설치된 GPU 서버에서 의도된 데이터 폴더 바깥(예: `/etc/`, `/root/.ssh/`, 웹 루트, cron 디렉터리, 파이썬 `site-packages` 등)에 생성·변조된 파일이 있는지 전수 조사하고, 침해 징후가 있으면 서버를 클린 이미지에서 재구축하며 서버에 저장돼 있던 **의료 영상 연구 데이터 접근 키, 대학 통합계정·SSH 개인키, 클라우드·HuggingFace 토큰을 안전한 환경에서 전면 교체**한다(그제 포항공대 GPU 서버 채굴기·포털 해킹 `D20261120-postech-paichai-univ`와 같은 맥락에서 국내 이공계·의대 GPU 서버 전수 점검이 시급하다).
  2. **사전 운영(Pre-production / 테스트) 환경 내 실데이터 전면 제거**: 기업들은 `Maximo`, ERP, CRM 등의 테스트·스테이징 환경에 실제 기업 고객 연락처나 실제 운영 네트워크 장비 IP 주소가 들어 있지 않은지 전수 감사해 가짜 데이터(마스킹·합성 데이터)로 교체하고, 테스트 환경을 외부 인터넷에서 완전히 분리해야 한다.
- 장기: (1) 대학·연구소의 오픈소스 AI 연구 도구(MONAI Label, Jupyter, MLflow, Ray 등)는 반드시 비특권 컨테이너(읽기 전용 루트 파일시스템)와 중앙 인증 프록시 뒤에서만 구동하도록 연구망 보안 표준을 강제한다 (2) 자율형 AI 에이전트(`Cairn`, `ARTEX`)의 초고속 API 매핑·퍼징을 차단하기 위해 모든 외부 웹·API 앞단에 행위 기반 속도 제한(Rate Limiting)과 비정상 경로 조작 패턴 차단을 기본 적용한다.
- 탐지: 웹·API 서버에서 짧은 시간(수 분) 내에 모든 API 엔드포인트를 순차 탐색한 직후 `../` 등 경로 조작 문자열이 포함된 파일 업로드 요청이 들어오는 에이전틱 스캔 패턴, 그리고 AI 애플리케이션 프로세스(`python`, `monailabel`)가 쉘을 실행하거나 시스템 디렉터리에 파일을 쓰는 행위를 WAF·EDR에서 즉시 차단·경보한다.

**교훈**: 이번 주 우리는 AI 보안의 역사적 분수령을 목격하고 있다. 그제(11/18) 구글이 `exploit_agent`를 경고했고, 어제(11/19~20) 티오리의 `Xint`(NGINX 90분 발굴)와 앤트로픽의 `OSS Scanner`(Drupal 발굴)가 방어자 측 AI의 위력을 보여줬다면, 오늘 아마존이 폭로한 **`Cairn`의 `MONAI Label` 공격은 실제 공격자가 무료 오픈소스 AI 에이전트에게 "셸을 따내라"고 시켜 단 11분 만에 동아시아 대학교 의료 AI 서버의 제로데이를 뚫고 루트 권한을 빼앗은 실전 기록**이다. 특히 표적이 **'동아시아의 대학교·연구기관'**이었고 국내 대학들도 최근 연쇄 해킹(`D20261118-univ-rerp`, `D20261120-postech-paichai-univ`)을 겪고 있는 만큼, 한국 대학병원과 의과대학·AI 연구실은 오늘 즉시 연구용 GPU 서버의 외부 노출 여부를 점검해야 한다.

**쉽게 말하면**: 기업들이 사내 윈도우 서버(Active Directory)와 마이크로소프트 클라우드(Microsoft 365·Entra ID)를 연결해 상태를 감시할 때 쓰는 공식 클라우드 서비스인 **'마이크로소프트 엔트라 커넥트 헬스(Microsoft Entra Connect Health)'**의 클라우드 API에서 보안 결함이 발견됐는데, 마이크로소프트가 조사해 보니 **실제 해커들이 이 결함을 악용해 여러 기업의 클라우드 설정 정보(테넌트 ID·도메인·라이선스 등급·동기화 상태)와 '최고관리자 및 기술 담당자의 이메일 주소'를 몰래 조회해 간 사실**이 확인됐습니다. 다행히 비밀번호나 인증 토큰은 털리지 않았고 마이크로소프트가 클라우드 서버 패치를 마쳤지만, **해커들이 이제 "어느 회사가 하이브리드 클라우드를 쓰고 있고, 그 회사의 클라우드 최고관리자 이메일이 무엇인지" 정확한 표적 명단을 손에 넣었다**는 점이 핵심 위험입니다.
**먼저 할 일(초보용)**: 마이크로소프트 클라우드(Entra ID / Azure / Microsoft 365)를 운영하는 기업의 보안 관리자는 지금 즉시 **Azure 포털의 'Service Health → Security Advisories(보안 권고)'** 메뉴에 들어가 자사 테넌트가 이번 `Entra Connect Health` API 조회 피해 대상이라는 통지를 받았는지 확인하세요. 마이크로소프트가 클라우드 쪽 패치를 이미 끝냈으므로 별도로 설치할 프로그램 업데이트는 없지만, **노출된 '관리자 및 기술 담당자 이메일 주소'와 '테넌트 동기화 정보'를 악용해 해커가 마이크로소프트 기술지원팀을 사칭하는 정교한 피싱 메일이나 전화(비싱), MFA 승인 폭탄 공격을 걸어올 위험이 매우 높으므로**, 모든 관리자 계정에 피싱 저항 MFA(**FIDO2 보안키·패스키**)가 빠짐없이 적용돼 있는지 오늘 즉시 점검하세요.

**개요**: 2026년 11월 20~21일(현지시간) BleepingComputer 등이 확인한 **마이크로소프트(Microsoft)**의 공식 고객 보안 통지(Azure Service Health 알림)에 따르면, 온프레미스(사내) Active Directory와 클라우드 Microsoft Entra ID 간의 신원 동기화 인프라를 모니터링하는 클라우드 서비스인 **Microsoft Entra Connect Health**의 API에 존재하던 취약점이 실제 공격자들에 의해 악용돼 일부 고객 테넌트의 메타데이터와 관리자 연락처가 무단 조회(read-only access)됐다.
- **사건 타임라인 및 취약점 성격 [확인: Microsoft 고객 통지, BleepingComputer]**:
  1. **약 4개월간 열려 있던 클라우드 API 결함**: 마이크로소프트 조사 결과 해당 취약점은 **2026년 7월 23일** `Entra Connect Health` 클라우드 API에 유입됐다. 마이크로소프트는 **11월 9일** 이 결함을 탐지해 **11월 19일** 서버 측 패치(server-side fix)를 배포했으며, **11월 20일** 조사를 마무리하면서 공격자들이 이 결함을 실제 악용해 서비스 모니터링 메타데이터에 비인가 읽기 전용 접근을 수행한 사실을 확인하고 영향받은 조직들에 통지했다(단, 공격자가 설정을 임의로 변경한 흔적은 발견되지 않았다).
  2. **노출된 정보(공격자의 '표적 정찰 지도' 역할)**:
     - **관리자 및 기술 담당자 이메일 주소(Administrator and technical contact email addresses)**
     - **테넌트 구성 메타데이터**: 테넌트 ID(Tenant IDs), 표시 이름(Display names), 초기 도메인 이름(Initial domain names), 국가 코드 및 리전 범위(Region scopes)
     - **라이선스 및 하이브리드 동기화 상태**: Microsoft Entra 라이선스 등급(License tiers), 디렉터리 동기화 활성화 여부 및 마지막 동기화 타임스탬프(Last sync timestamp), Connect Health 온보딩 상태
     - **만료된 레거시 인증서**: 2024년 말 폐기된 내부 서비스에 에이전트를 등록할 때 과거 사용됐던 만료 인증서(현재 보안 위험은 없다고 MS는 설명).
  3. **노출되지 않은 정보**: 마이크로소프트는 사용자 비밀번호, 비밀번호 해시, 인증 토큰, 유효한 암호화 키, 또는 온프레미스 Active Directory의 내부 상세 토폴로지는 노출되지 않았으며, 클라우드 서버 측 결함이므로 고객이 직접 설치해야 할 에이전트 패치는 없다고 밝혔다.

**왜 일어났나**
- 직접 원인 [확인: Microsoft]: 2026년 7월 23일 업데이트된 Microsoft Entra Connect Health의 클라우드 측 API에 인증·권한 검증 결함이 유입돼, 비인가 당사자가 타 테넌트의 모니터링 메타데이터와 관리자 연락처를 읽기 전용으로 조회할 수 있었다.
- 구조적 원인 [추정 — 분석]: (1) 비밀번호나 토큰이 직접 털리지 않았더라도, 클라우드 공격 조직(예: 그제 다룬 러시아 `COLD RELIC` `D20261119-cold-relic`이나 `ShinyHunters`/`Scattered Spider`)이 가장 먼저 찾고 싶어 하는 최고 가치의 정찰 정보가 바로 **"이 회사의 Entra ID 최고관리자 이메일 주소가 무엇이고, 사내 AD와 하이브리드 동기화를 쓰고 있는가, 보안 라이선스 등급(P1/P2 등)은 무엇인가"**이다 (2) 클라우드 공급사(Microsoft)의 멀티테넌트 API에서 권한 경계 결함이 한 번 발생하면, 개별 고객사가 아무리 사내 보안을 잘해도 클라우드 쪽에서 관리자 명단이 새어 나갈 수 있음을 보여준다(본 보고서의 분석).

**침투 경로 [확인 — Microsoft 공식 보안 통지 기준]**: Microsoft Entra Connect Health 클라우드 API의 취약점을 악용해 비인가 접근(T1190, 확인) → 대상 기업 테넌트의 관리자·기술 담당자 이메일 주소, 테넌트 ID·도메인·리전, Entra 라이선스 등급 및 하이브리드 디렉터리 동기화 상태 메타데이터를 읽기 전용으로 무단 조회·수집(T1087.004, T1526, T1213, 확인).

**어떻게 조치하나** (벤더 권고 및 본 보고서 권고)
- 즉시: (Microsoft Entra ID / 하이브리드 AD 운영 조직) (1) Azure 포털의 **Azure Service Health → Security Advisories**에서 자사 테넌트에 이번 `Entra Connect Health` 관련 통지가 도착했는지 확인하고, 통지 내용과 최근 Entra ID 로그인·감사 로그를 보존한다. (2) 테넌트에 등록된 **관리자(Global Admin, Hybrid Identity Admin 등) 및 기술 알림 수신 담당자(Technical Contacts) 이메일 목록**을 확인해 누가 표적에 노출됐는지 식별한다.
- 단기: **노출된 정보('관리자 이메일 + 테넌트 ID + 마지막 AD 동기화 시각 + 라이선스 등급')는 공격자가 맞춤형 사회공학 공격을 꾸미기에 완벽한 재료다.**
  1. **관리자 계정 FIDO2 강제 및 'MS 기술지원 사칭' 경보 발령**: 공격자가 노출된 테넌트 ID와 실제 마지막 동기화 시각을 들이대며 *"마이크로소프트 Entra 지원팀입니다. 귀사 테넌트(ID: xxx)의 하이브리드 AD 동기화에 오류가 감지돼 긴급 점검 링크로 로그인해 승인해 주셔야 합니다"*라고 접근하면 숙련된 관리자도 속기 쉽다. 노출된 모든 관리자·기술 담당자에게 즉시 이 시나리오를 경고하고, 모든 특권 계정의 인증 수단을 푸시 알림·SMS에서 **피싱 저항 MFA(FIDO2 하드웨어 보안키·패스키)**로 즉시 전환하며, 그제 `COLD RELIC` 사건(`D20261119-cold-relic`)처럼 비인가 MFA 기기나 패스키가 몰래 추가 등록되지 않았는지 감사한다.
  2. **온프레미스 Entra Connect(구 Azure AD Connect) 서버 보안 점검**: 공격자가 해당 테넌트의 하이브리드 디렉터리 동기화 사용 여부를 정확히 알게 됐으므로, 사내에 설치된 `Entra Connect` 동기화 서버(사실상 클라우드와 사내 AD를 잇는 Tier-0 핵심 서버)의 외부 원격 접속 차단 여부와 최신 버전 유지 상태를 함께 점검한다.
- 장기: 클라우드 테넌트의 기술 연락처(Technical Contact)에는 실제 최고관리자(Global Admin)의 로그인 계정(UPN) 이메일을 직접 적어 두지 말고, 로그인 권한이 없는 **전용 보안 메일링 리스트(Distribution List / 공용 알림 주소)**를 등록해 메타데이터가 노출되더라도 실제 관리자 로그인 ID가 드러나지 않도록 분리한다.
- 탐지: 테넌트 관리자 및 기술 담당자 계정으로 유입되는 외부 피싱 메일·팀즈(Teams) 외부 메시지, 관리자 계정에 대한 비정상 로그인 시도 및 MFA 피로(푸시 반복) 공격, 그리고 새로운 MFA 수단 등록이나 조건부 접근 정책 변경 시도를 SIEM·Entra ID 보호에서 최우선 경보한다.

**교훈**: 많은 기업이 마이크로소프트 클라우드 테넌트를 처음 만들 때 '기술 담당자 연락처(Technical Contact)' 칸에 아무 생각 없이 **최고관리자(Global Admin)가 실제로 로그인할 때 쓰는 이메일 주소**를 그대로 적어 넣는다. 이번 사건처럼 클라우드 모니터링 API에서 메타데이터가 새어 나가면, 그 연락처 하나가 해커에게는 **"이 계정을 집중 공격하면 회사 전체 클라우드가 열린다"**는 이정표가 된다. **알림을 받는 이메일 주소와 실제 관리자 권한으로 로그인하는 전용 계정(클라우드 전용 `admin-*` 계정)은 반드시 분리**해야 한다.

> 날짜: 미 FBI 국가범죄정보센터(`NCIC`) 외부 침입 탐지 및 조사 보도 2026-11-20~21 · 아일랜드·북아일랜드 금융 IT 공급사(`Wellington IT`) 침해 발생 2026-10-02~06(6주 뒤인 11-16~17 신용조합·당국 통지, 11-20~21 보도) · 유형: 미 연방수사국 전국 형사사법·수배·영장 핵심 데이터베이스(`NCIC`) 외부 해킹 침입 조사, 금융 코어뱅킹 IT 공급사(`Wellington IT`) 소프트웨어 인가 취약점 악용 자동화 스크립트 침해 및 40~43개 신용조합 송금 수취인 계좌(IBAN·BIC·계좌번호) 대량 노출 · 행위자: 미귀속 · 지역: 미국(FBI NCIC), 아일랜드·영국 북아일랜드(Wellington IT 및 40~43개 신용조합) · 근거: 보도(FBI NCIC 건 — CNN·The Guardian·Al Jazeera·BleepingComputer·보안뉴스 보도 및 미 대통령 언론 인터뷰 언급) / 확인(Wellington IT 건 — 아일랜드 재무부·중앙은행·데이터보호위원회 DPC 및 피해 신용조합 공식 통지, The Record·Irish Times·BleepingComputer 확인)

**쉽게 말하면**: 미국과 유럽에서 국가 핵심 사법망과 서민 금융망의 심장부가 뚫리는 충격적인 사건 두 건이 동시에 터졌습니다. 첫째, 미국에서는 전국의 모든 경찰관이 순찰차에서 용의자를 검문할 때 수배 여부, 체포 영장, 실종자, 도난 차량을 실시간으로 조회하는 **미 연방수사국(FBI)의 가장 핵심적인 전국 범죄 데이터베이스인 '국가범죄정보센터(NCIC)'에 외부 해커가 침입한 정황**이 포착돼 긴급 수사가 진행 중입니다(올해 4월 감시 시스템 침해와 9월 채용 포털 해킹에 이은 FBI의 또 다른 대형 사고로, 수배·영장 정보 열람이나 변조 우려까지 제기됐습니다). 둘째, 아일랜드에서는 전국 신용조합(우리나라의 신협·새마을금고 격)의 4분의 1에 달하는 **40~43개 신용조합에 온라인 뱅킹 시스템을 공급하는 IT 업체('웰링턴 IT Wellington IT')**가 해킹당해 고객들이 자주 돈을 보내려고 저장해 둔 **'송금 수취인 이름, 국제은행계좌번호(IBAN), 계좌번호, 송금 메모'**가 무더기로 털렸는데, 외주 IT 업체가 이 사실을 **무려 6주 동안이나 신용조합과 금융당국에 알리지 않고 숨겨 왔다**는 사실이 드러나 정부 각료들이 강력히 비판하고 나섰습니다.
**먼저 할 일(초보용)**: 아일랜드 및 북아일랜드 신용조합(Credit Unions)을 이용하는 교민·유학생·기업은 본인의 계좌 잔액이나 비밀번호는 털리지 않았더라도, **내가 평소 돈을 보내던 가족·집주인·거래처의 '실제 이름과 계좌번호(IBAN), 평소 송금 메모 내용'을 해커가 전부 알게 된 상태**이므로, 거래처나 집주인, 또는 신용조합을 사칭해 **"기존에 송금하시던 계좌(실제 IBAN 언급)가 변경되었으니 이번 달 월세·대금은 새 계좌로 보내 달라"**고 요구하는 이메일·문자를 받으면 100% 사기(인보이스·계좌 변경 사기)로 의심하고 반드시 기존에 알던 전화번호로 직접 통화해 확인하세요. 사법·공공·금융기관 보안 담당자는 핵심 조회망(NCIC 등)의 연동 단말 인증과 데이터 무결성 감사 로그를 점검하고, 외주 IT 공급사(`Wellington IT` 등)의 침해 통지 지연을 막기 위한 실시간 로그 연동 및 계약상 즉시 통지 의무를 재점검해야 합니다.

**개요**: 2026년 11월 20~21일(현지시간) 미국 CNN·더가디언·BleepingComputer·보안뉴스(idxno=147427)와 유럽 The Record·아이리시타임스(Irish Times) 등을 통해, 미국 연방수사국(FBI)의 핵심 형사사법 정보망 침입 사건과 아일랜드 금융권 공급망 대규모 유출·지연 통지 사태가 잇달아 공개됐다.
1. **미 연방수사국(FBI) '국가범죄정보센터(NCIC)' 데이터베이스 외부 침입 조사 [보도: CNN, The Guardian, Al Jazeera, BleepingComputer, 보안뉴스 147427]**:
   - **표적의 중요성(미국 사법 집행의 대동맥 `NCIC`)**: **NCIC(National Crime Information Center)**는 미국 전역의 연방·주·지방 법집행기관(경찰·보안관 등)이 24시간 내내 실시간으로 공유·조회하는 미국 형사사법 체계의 핵심 전산망이다. 이 안에는 **△미집행 체포 영장(outstanding arrest warrants) △수배자 및 실종자 명단 △신원 조회(background checks) △접근금지 명령(protection orders) △도난 차량 및 총기·재산 정보** 등 극도로 민감한 법집행 데이터가 들어 있으며, 일선 경찰관들이 도로 검문이나 체포 현장에서 가장 먼저 조회하는 시스템이다.
   - **침입 탐지 및 파장**: CNN 등이 수사 브리핑을 받은 관계자들을 인용해 보도한 바에 따르면, 11월 중하순경 NCIC 데이터베이스를 겨냥한 외부 사이버 침입(external intrusion)이 탐지돼 FBI가 긴급 조사에 착수했다(비슷한 시기 미 농무부 USDA의 농업인 보조금 지급 시스템도 사이버 공격으로 보이는 장애를 겪었다). FBI는 구체적인 침입 경로와 실제 데이터 유출·변조 여부에 대해 공식 논평을 자제하고 있으나, 도널드 트럼프 미국 대통령도 언론 인터뷰에서 해당 사건을 언급하며 "좋지 않은 일(not good)"이라고 인정하고 기관 시스템 전반의 재검토 계기가 될 수 있다고 발언했다.
   - **반복되는 FBI 표적화**: 이번 사건은 과거 본 저장소가 기록한 **2026년 4월 FBI 감시·도청 영장 관련 시스템 침해(`INC-2026-04-fbi`)** 및 올해 9월 `ShinyHunters`의 FBI 채용 포털(`FBIJobs.gov`) 침해 보도 이후 또다시 핵심 법집행 인프라가 뚫린 것이어서, 범죄 조직이나 외국 정보기관이 **자신들에 대한 수배·수사 여부를 사전 확인하거나 영장·수배 기록의 무결성을 훼손할 위험**에 대한 심각한 우려를 낳고 있다.
2. **아일랜드 신용조합 40~43곳(전체의 약 1/4)을 강타한 IT 공급사 '웰링턴 IT(Wellington IT)' 침해 및 '6주 늑장 통지' 파문 [확인: 아일랜드 정부·DPC·신용조합 통지, The Record, Irish Times, BleepingComputer]**:
   - **공격 방식(소프트웨어 인가 취약점 + 자동화 스크립트)**: 영국 북아일랜드 벨파스트에 본사를 두고 아일랜드·영국 신용조합들에 코어 뱅킹 및 온라인 뱅킹 소프트웨어를 공급하는 핵심 IT 벤더 **'Wellington IT'**에서, 지난 **2026년 10월 초(10월 2일~6일경)** 외부 공격자가 **소프트웨어 인가(authorization) 취약점을 악용하는 자동화 스크립트(automated script)**를 돌려 온라인 뱅킹 데이터를 무단 추출했다.
   - **6주간의 침묵(늑장 통지)**: 침해는 10월 초에 벌어졌으나, Wellington IT는 무려 **약 6주가 지난 11월 중순(11월 16~17일경)**에야 피해 신용조합들과 금융·개인정보 감독당국에 이 사실을 통보했다. 이로 인해 아일랜드 전체 신용조합의 약 4분의 1에 해당하는 **40~43개 신용조합**(및 북아일랜드 일부 조합, 잠재적 회원 수십만 명 규모)이 뒤늦게 비상 통지에 나섰으며, 사이먼 해리스(Simon Harris) 아일랜드 부총리 겸 재무장관과 로버트 트로이(Robert Troy) 국무장관은 공급사의 6주 지연 통지와 사후 대응을 "매우 우려스럽다(deeply concerning)"며 강도 높게 비판했다.
   - **유출 항목('저장된 송금 수취인 계좌 정보')**: 조합원들의 계좌 잔액, 로그인 비밀번호, 예금 자금 자체는 침해되지 않았다. 그러나 조합원들이 온라인 뱅킹에서 자주 송금하기 위해 등록·저장해 둔 **'수취인(Payee) 정보' — △수취인 이름(Payee names) △국제은행계좌번호(IBAN) △은행식별코드(BIC) △영국 은행 분류코드(Sort codes) △계좌번호 △송금 참조 메모(Payment reference information)**가 유출됐다. 아일랜드 데이터보호위원회(DPC), 영국 정보위원회(ICO), 아일랜드 중앙은행, 국가사이버범죄수사국(GNCCB)이 모두 조사에 착수했다.

**왜 일어났나**
- 직접 원인 [확인 / 보도]: (1) FBI NCIC 건은 전국 법집행기관이 연동되는 NCIC 시스템에 외부 비인가 침입이 발생했다(구체적 초기 침투 경로는 수사 중, 보도) (2) 아일랜드 신용조합 건은 공유 IT 공급사(Wellington IT)의 온라인 뱅킹 소프트웨어에 존재하던 인가(Authorization) 검증 취약점을 공격자가 자동화 스크립트로 공략해 저장된 수취인 테이블을 긁어갔다(확인).
- 구조적 원인 [추정 — 분석]: (1) **'외주 공급사(서드파티)가 사고를 6주 동안 뭉개면 고객 금융사는 속수무책이 되는 공급망 사각지대'**: 아일랜드 신용조합 40여 곳은 자체 보안팀 대신 공유 IT 벤더(Wellington IT) 하나에 온라인 뱅킹 인프라를 전적으로 위탁하고 있었는데, 정작 그 벤더가 10월 초 해킹을 당하고도 6주 동안 통보하지 않는 바람에 조합원들은 한 달 반 동안 아무런 경계 없이 송금 사기 위험에 노출됐다(한국의 더존비즈온·메타엠·KG에듀원 수탁사 연쇄 유출과 판박이다) (2) FBI NCIC처럼 전국 수만 개의 지방 경찰서·외부 기관 단말이 연결되는 거대 연방 데이터베이스는 단일 접점이나 위탁 네트워크 하나만 뚫려도 중앙 핵심 원장까지 위협받는 구조적 취약성을 안고 있다(본 보고서의 분석).

**침투 경로 [확인 / 보도 — 아일랜드 당국·Wellington IT 공식 통지 및 미 언론 보도 기준]**: (Wellington IT 건) 신용조합들의 온라인 뱅킹을 위탁 운영하는 IT 공급사(Wellington IT) 서버의 소프트웨어 인가(authorization) 취약점을 악용해 침투하고, 공급사 공유 인프라를 통해 연결된 40~43개 신용조합 환경에 우회 접근(T1190, T1199, 확인) → 자동화 스크립트를 실행해 온라인 뱅킹에 저장된 송금 수취인 데이터(수취인 실명, IBAN, BIC, Sort code, 계좌번호, 송금 참조 메모)를 대량 자동 수집·반출(T1119, T1213, 확인) / (FBI NCIC 건 — 보도 기준, 세부 기법은 미공개로 매핑 제외) 외부 공격자가 미 FBI 국가범죄정보센터(NCIC) 시스템에 비인가 침입(수사 진행 중).

**어떻게 조치하나** (당국 조치 및 본 보고서 권고)
- 즉시: (1) **Wellington IT 및 피해 신용조합**: 취약한 온라인 뱅킹 인가 API를 즉시 패치하고 자동화 스크립트 요청을 차단하며, 침해된 공유 서버의 웹·DB 쿼리 로그(10월 초 이후 전 기간)를 보존해 각 신용조합별로 실제 조회된 조합원 및 수취인 명단을 정확히 특정·통지한다. (2) **법집행·공공 핵심 조회망(NCIC 유사 시스템) 운영 기관**: 외부 지방 기관·순찰 단말에서 중앙 DB로 들어오는 모든 연동 세션의 비정상 대량 조회 여부와 **핵심 레코드(수배·영장·범죄경력 등)에 대한 비인가 수정·삭제(무결성 훼손) 로그**를 최우선 감사한다.
- 단기: **'수취인 이름 + IBAN 계좌번호 + 송금 참조 메모' 유출은 송금 가로채기(BEC·인보이스 사기)의 가장 치명적인 무기다.**
  1. **신용조합 고객 대상 '송금 계좌 변경 사기' 및 '수취인 실명 거론 보이스피싱' 방어**: 공격자는 조합원 A가 매달 수취인 B(예: 자녀, 임대인, 거래 업체)의 어느 IBAN 계좌로 어떤 메모(예: *"OO아파트 월세"*, *"송장 번호 1234"*)를 적어 돈을 보내는지 정확히 알고 있다. 따라서 수취인 B를 사칭해 *"기존 IBAN 계좌(실제 번호 제시)에 문제가 생겨 이번 달 월세는 새 계좌로 보내 달라"*고 하거나, 신용조합 보안팀을 사칭해 *"귀하가 최근 B님 계좌(IBAN 제시)로 송금하신 내역이 부정 거래로 감지됐다"*며 인증번호·원격제어 앱을 요구하는 사기가 기승을 부릴 수 있다. 피해 조합들은 모든 회원에게 **"저장된 수취인 이름과 IBAN을 정확히 알고 연락하더라도 전화·문자로 계좌 변경이나 보안 코드를 절대 믿지 말라"**고 긴급 공지하고, 신규 수취인 계좌 등록·변경 시 수취인 예금주 실명 대조(Verification of Payee) 및 추가 본인확인을 강화해야 한다.

- 탐지: 온라인 뱅킹 API에서 단일 세션이나 스크립트가 서로 다른 고객·신용조합의 수취인 목록(`beneficiaries/payees`) 엔드포인트를 연속 호출하는 인가 우회·스크래핑 트래픽을 API 게이트웨이에서 실시간 차단한다.
